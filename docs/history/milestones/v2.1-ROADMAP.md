# Milestone v2.1: Agents That Ship

**Status:** ✅ SHIPPED 2026-01-28
**Phases:** 23-27
**Total Plans:** 46

## Overview

v2.1 delivers end-to-end working agents where feature requests become shipped code. Product-agent receives Slack messages, asks clarifying questions, and creates well-structured Linear issues. Dev-agent receives Linear issues, works in dev containers, and produces mergeable PRs. Human-in-the-loop approvals keep humans in control.

## Milestone Summary

**Key Decisions:**
- Event type uses dotted notation (source.resource.action) for consistent parsing
- Integration-embedded dispatcher pattern: each integration dispatches its own events
- Dev container uses sleep infinity and Docker API exec for command execution
- Node factory pattern: createXNode(deps) returns async function for DI
- Dual-channel approval: full plan to Linear (permanent record), summary to Slack (real-time buttons)
- Temporal signals: planApproval, prFeedback for workflow continuation
- Cross-channel sync only when approval from Slack (Linear already knows if from Linear)

**Issues Resolved:**
- MCP body parsing fixed (JSON for MCP, raw for webhooks)
- API key vs OAuth token handling for Linear
- PR URL field mismatch (url vs html_url)
- Thread context standardization across Slack events

**Issues Deferred:**
- 11 tests skipped pending MCP mock and Temporal test framework
- GitHub webhook for PR completion requires user configuration
- Linear comment approval (HITL-03) infrastructure ready but not E2E tested

**Technical Debt Incurred:**
- REQUIREMENTS.md shows PROD-01 through PROD-11 as "Pending" but verified complete
- Pre-existing lint issues in legacy code (9 errors)
