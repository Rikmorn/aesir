# Milestone v2.4: Operations Dashboard

**Status:** SHIPPED 2026-02-05
**Phases:** 48-55
**Total Plans:** 22

## Overview

Real-time visibility into agent execution through a developer-focused web dashboard. The roadmap delivered agent-service API extensions first (runtime state that doesn't live in the database), then the Next.js dashboard infrastructure, followed by four independently verifiable view pages (conversations list, conversation detail, agents, tools), the system overview landing page, and finally real-time SSE wiring across all views. Each view phase produced a visually inspectable page.

## Phases

### Phase 48: Agent Service API Extensions

**Goal**: The agent service exposes runtime state (tool registry, agent definitions, worker status, live events) via read-only HTTP endpoints that the dashboard and future consumers can query
**Depends on**: Nothing (extends existing agent-service)
**Plans**: 2 plans

Plans:
- [x] 48-01-PLAN.md -- Shared API foundation, interface extensions, and four REST endpoints (tools/registry, tools/health, agents/registry, worker/status)
- [x] 48-02-PLAN.md -- SSE event stream endpoint with connection management, filtering, replay, and shutdown cleanup

**Details:**
- Created ToolContext.__inspection__ pattern for metadata extraction without executing tools
- Worker status via ConversationExecutor.getWorkerStatus() delegation
- Module-level cache for tool registry (immutable at runtime)
- SSE with global EventLog subscription for shared buffer, per-connection for filtered delivery
- Array-based buffer with shift() eviction (1000 items), 50 connection limit with 429 response

### Phase 49: Dashboard Infrastructure

**Goal**: A working Next.js 15 application exists in the monorepo, builds in Docker, serves on port 3005 via Compose, passes typecheck and lint, and has the service layer pattern established for all future views
**Depends on**: Nothing (parallel to Phase 48)
**Plans**: 3 plans

Plans:
- [x] 49-01-PLAN.md -- Next.js package scaffold with Tailwind, shadcn/ui, health endpoint, middleware, typecheck, lint
- [x] 49-02-PLAN.md -- Drizzle ORM database connectivity and service layer pattern
- [x] 49-03-PLAN.md -- Docker multi-stage build, Compose service, Nginx routing

**Details:**

- basePath=/dashboard for Nginx sub-path routing
- Local schema in lib/schema.ts mirrors agents schema (no @aesir/agents dependency)
- Service layer pattern: services/*.ts abstract all DB queries behind typed async functions

## Milestone Summary

**Key Decisions:**
- Separate Next.js dashboard service (different lifecycle from agent service)
- SSE over WebSockets (unidirectional monitoring data, proxy-friendly)
- Read-only Postgres access, no new tables (except agent_event_content for inline content)
- Service layer abstraction as future API boundary
- Agent service /api/ prefix for management endpoints
- shadcn/ui for components (owned code, not dependency)
- Local schema mirrors (no @aesir/agents import in dashboard)

**Issues Resolved:**
- Dashboard tsconfig incompatibility with monorepo base config
- Nginx routing with Next.js basePath
- RSC boundary Date serialization (ISO strings for client components)
- Monorepo env loading for seed/migrate scripts (loadEnvFromRoot utility)

**Issues Deferred:**
- Authentication enforcement (middleware is auth-ready, not enforced)
- Agent definition editing (YAML files sufficient for single-dev workflow)
- Conversation actions (cancel, retry) from dashboard UI
- Historical analytics and trend analysis
- Mobile responsiveness
- Automated E2E tests (Playwright)

**Technical Debt Incurred:**
None. All 8 phase verifications and 6 post-phase commits reviewed clean.
