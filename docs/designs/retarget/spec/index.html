The store is not the bottleneck; the evidence points at a shared pool; a team is a lead addressed directly and depth is one; connectors tier by who registers the app. One page, with what moved from first principles. What changed →

Where the platform ends

Three things are deliberately outside it. The human's chat surface is whatever harness they already run; aesir serves it an MCP server and builds no chat product. Tool execution runs in a sandbox pod the harness calls, never in the harness's own container. The model is an HTTPS endpoint reached through the gateway, in the cluster or on the internet; the harness holds no provider key.

Three rules that hold everywhere

  1. No model in any routing path. Events reach an agent by rule; agents reach each other by address; a model chooses only among a handful a search returned, and only when a human's sentence or an agent's brief has to be interpreted.
  2. The store is the only stateful thing, and it is not the bottleneck. Conversations, tasks, the inbox, the event log and the registry cards live in Postgres. Replicas are stateless and claim work; a paused conversation holds no process. A hundred agents are about two hundred statements a second; growth, connections and heartbeat churn are what to design for.
  3. Humans are reached through applications. An agent that needs a person ends its turn with a typed question into the tool thread the job came from. No human is ever an agent, an assignee or a directory entry.
