The three transports

The human's harness as a client

  1. The human, in Claude Code, asks for something. Their harness calls agents.search("release notes") on aesir's MCP server, authenticated with OAuth 2.1, and gets three cards.
  2. Their harness calls tasks.create("org/docs/release-writer", brief); the platform opens the task with the human as caller and the request as origin, and returns the task id. Claude Code moves the call to a background task if it runs past two minutes.
  3. The agent needs a decision on Tuesday. It ends its turn with INPUT_REQUIRED; the question lands in the tool thread the job belongs to (a Linear comment, a Slack thread), because the human's harness session is not durable and the current MCP revision has no server-initiated requests.
  4. The human answers in the tool on Thursday; the webhook resumes the task.
  5. Any later session of any MCP client calls tasks.get(id) and reads the completion record and artifacts. When clients support the MCP Tasks extension, the same job is exposed through it with no change to the record.

What the human's harness never does: choose over the full catalogue, hold the job's state, or be the only channel for a question. The platform holds the task; the tool thread is the durable channel; the harness is a convenient client.
