Positions taken, to be argued with

  1. The record shape: A2A's Task plus stopReason, caller, origin, completionRecord; no negotiation states, no group entity.
  2. The collaboration model: bounded orchestration at depth one (decided); in-platform delegation first; no choreography. For coding work the record, the work tool's issue tree, is the coordination medium and a lead is the gated exception for breadth-first work with a weak single-agent baseline; member questions land in the record under the member's task id; the human keeps a direct line to each member.
  3. Addressing: a registry derived from cluster objects and a policy gateway, no model in the route; events by rule, agents by address plus search over a handful, humans by tool and by their own harness over MCP; no front desk of aesir's own.
  4. The harness and container: the claimed loop kept as mechanism and rewritten as implementation; a shared harness pool per trust tier with a dedicated Deployment only for native dependencies (proposed; Roberto's decision); the manifest as three objects, Harness, AgentTemplate and Agent (candidate B, proposed); an own model port on the shared primitives with a capability declaration per adapter; tool exposure as a pinned core plus a searchable rest; sandbox separate; credentials injected at egress with a vending step for OAuth refresh and GitHub App tokens; the build as a ko-shaped CLI.
  5. The store: not the bottleneck at any modelled scale; partition the event log and inbox from day one, keep the lease in a narrow table, store one row per message, pool connections at organisation scale; the poll is the reconciliation and batched NOTIFY a hint.
  6. Connectors: three tiers by who registers the provider app and who wrote and reviewed the code (bring your own, reviewed, platform-native, the last being the reviewed tier authored by the platform); credential handling an orthogonal labelled axis; the operator registers each provider app once per installation; the container is never the MCP client.
  7. Inbound events: subscriptions with CEL predicates; the ingress verifies, persists and evaluates, with bundle transforms only as sandboxed pure functions; a copy per subscription; waits registered by paused sessions and evaluated per delivery; the outbox in the caller's transaction.
