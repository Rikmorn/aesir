    **conversation-executor.ts:**
    1. Import `CorrelationService` type.
    2. In `createConversationExecutor()`, destructure `correlationService` from options (optional).
    3. In the `start()` method, AFTER the successful INSERT (new conversation created), add auto-registration:
       ```typescript
       // Auto-register entity correlation (Phase 78)
       if (params.entityRef && correlationService) {
         try {
           await correlationService.register({
             entityType: params.entityRef.entityType,
             entityId: params.entityRef.entityId,
             conversationId: newId, // the ID just created
             agentId: params.agentDefinitionId,
           });
         } catch (err) {
           // Non-fatal: correlation is a secondary concern
           logger.warn({ err, conversationId: newId }, 'Failed to register entity correlation (non-fatal)');
         }
       }
       ```
    4. For the idempotent return path (conversation already exists), do NOT re-register. The correlation already exists from the original start().
    5. For the re-trigger path (terminal conversation, new -r{N} suffix), DO register the new conversation ID.

    Per CONTEXT.md locked decisions:
    - Dual-layer registration: auto at start() (this task), manual via work:register (Plan 03)
    - No auto-registration for sub-agents: entityRef is only set by the router, not by spawn_agent
    - Registration is best-effort (non-fatal on failure)
