<objective>
Replace the `fetch-retry-ts` library in the MCP client with a custom retry loop that classifies HTTP errors as permanent (4xx) vs transient (429, 5xx), returns structured error context to agents, and supports observability event emission via callback. Also lay the database foundation (new event types and `last_persisted_sequence` column) for subsequent plans.

Purpose: Agents currently receive opaque error messages from MCP failures. With classification, permanent errors (e.g., "issue not found") give the agent immediate, actionable context, while transient errors (e.g., rate limits, server errors) are retried transparently without wasting agent reasoning.

Output: Rewritten MCP client with error classification, extended McpError class, new event types in schema, migration for `last_persisted_sequence` column.
</objective>

  <action>
    Replace the `fetch-retry-ts` wrapped fetch with a custom retry loop inside `callMcpTool`. The library cannot distinguish permanent from transient errors or expose HTTP status codes for classification.

    **Remove:**
    - `import { fetchBuilder } from "fetch-retry-ts"` import
    - `const fetchWithRetry = fetchBuilder(fetch)` line
    - The `retries`, `retryDelay`, `retryOn` options from the fetch call

    **Add a `sleep` helper:**
    ```typescript
    function sleep(ms: number): Promise<void> {
      return new Promise((resolve) => setTimeout(resolve, ms));
    }
    ```

    **Add `calculateDelay` function** (per CONTEXT.md locked decision):
    - Exponential backoff: 1s, 2s, 4s (base = 1000 * 2^(attempt-1), attempt is 1-based)
    - Full jitter: `Math.floor(Math.random() * cappedDelay)` where cappedDelay = `Math.min(baseDelay, 10000)`
    - For 429 with Retry-After header: parse header, respect up to 10s cap. If server says >10s, return -1 (signal: don't retry, return error immediately per CONTEXT.md)
    - Max delay cap: 10s per attempt

    **Rewrite `callMcpTool`:**
    1. Extract `onMcpEvent` and `retryable` from options (default retryable=true)
    2. Constants: `MAX_ATTEMPTS = 3` (per CONTEXT.md: 3 total = initial + 2 retries)
    3. Loop `for (let attempt = 1; attempt <= maxAttempts; attempt++)`:

       a. **fetch call** -- plain `fetch(url, init)` with same headers/body as before. Wrap in try/catch for network errors.

       b. **Network error handling** (catch block): If `attempt < maxAttempts` AND `retryable !== false`, calculate delay, sleep, continue. If exhausted, emit `onMcpEvent?.({ type: "mcp.retries_exhausted", payload: { tool, integration, attempts: attempt, totalRetryMs, finalError: "Network error: " + err.message } })`, then throw `McpError` with classification `"network"`.

       c. **Permanent error (status >= 400 && status < 500 && status !== 429)**: Do NOT retry. Parse response body. Emit `onMcpEvent?.({ type: "mcp.error", payload: { tool, integration, status: response.status, message: errorText } })`. Return structured error as tool result (not throw) -- actually, per existing pattern this should throw `McpError` with httpStatus and classification "permanent". The caller (tool execution wrapper) converts to tool result.

       d. **Rate limit (status === 429)**: Emit `onMcpEvent?.({ type: "mcp.rate_limited", payload: { tool, integration, attempt, retryAfterMs } })`. If `retryable === false` or delay returns -1 (Retry-After > 10s) or last attempt, throw McpError. Otherwise sleep and continue.

       e. **Server error (status >= 500)**: If `attempt < maxAttempts` and `retryable !== false`, calculate delay, sleep, continue. If exhausted, emit `onMcpEvent?.({ type: "mcp.retries_exhausted", payload: { tool, integration, attempts: attempt, totalRetryMs, finalStatus: response.status } })`, throw McpError with classification "transient_exhausted".

       f. **Success (response.ok)**: Parse and return as before (existing logic for McpSuccessResponse/data/structuredContent).

       g. **Application-level error (200 + isError:true)**: Handle same as current code -- throw McpError. These are permanent (the integration processed the request but the tool failed).

    4. Track `totalRetryMs` across attempts.

    5. All thrown McpErrors include: `httpStatus`, `classification`, `retryAttempts: attempt`, `totalRetryMs`.

    **Do NOT change:**
    - `getMcpUrl()` function
    - The export signature of `callMcpTool` (still `<T>(options: McpCallOptions) => Promise<T>`)
    - How success responses are parsed (data/structuredContent/raw)
