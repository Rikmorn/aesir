### 1. Inline LLM Response Content (`f4057a1`)

**What:** Store LLM response content in a separate `agent_event_content` table and display inline in the event timeline, replacing the standalone Messages panel.

**Artifacts verified:**
- `packages/agents/src/framework/event-content.ts` (65 lines) -- fire-and-forget content storage
- `packages/agents/src/shared/db/migrations/0003_add_agent_event_content.sql` (15 lines) -- new table with FK cascade
- `packages/agents/src/shared/db/schema.ts` -- `agentEventContent` table definition
- `packages/dashboard/src/app/api/events/[id]/content/route.ts` (33 lines) -- API route for lazy loading
- `packages/dashboard/src/components/conversation-detail/event-content.tsx` (158 lines) -- lazy-loading display component
- `packages/dashboard/src/lib/schema.ts` -- local `agentEventContent` table mirror
- `packages/dashboard/src/services/conversations.ts` -- `getEventContent()` service function

**Wiring:** EventTimeline imports and renders EventContentDisplay for llm.response events. Old `message-panel.tsx` removed entirely.

**Impact:** Architectural change to how LLM responses are viewed. Content is now inline in the event timeline with expand-on-demand, rather than a separate panel. Better debugging UX.

## Known Limitations (by design)

These were explicitly scoped out of v2.4 per REQUIREMENTS.md:

| Limitation | Reason |
|------------|--------|
| Authentication not enforced | Auth-ready middleware exists; multi-user is future milestone |
| No agent definition editing | Write paths require API design; YAML files work for single-dev workflow |
| No conversation actions (cancel, retry) | Management endpoints exist but not exposed as UI actions |
| No historical analytics/trends | Raw data and recent aggregates sufficient for v2.4 |
| No alerting/notifications | Dashboard is pull-based; push is future |
| No mobile responsiveness | Desktop developer tool |
| MCP permission sync is manual | Operators must sync agent YAMLs with MCP seed scripts |
| No automated E2E tests | Flows verified via code inspection; Playwright tests are future |
