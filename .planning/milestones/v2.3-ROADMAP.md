# Milestone v2.3: Unified Agent Framework

**Status:** SHIPPED 2026-02-04
**Phases:** 37-47.1
**Total Plans:** 32

## Overview

v2.3 replaces Temporal workflow orchestration, per-agent services, and fragmented persistence with a Postgres-backed conversation executor, declarative agent definitions, and a unified event log. The milestone progresses from persistence foundations (schema, registries, history) through the critical-path executor, to signal routing, service consolidation, and finally Temporal migration and cleanup. Phases 37-47 continue from v2.2's Phase 36.

## Milestone Summary

**Key Decisions:**
- Custom SKIP LOCKED executor over generic job queue (conversation semantics don't map to generic job abstractions)
- pg-boss for timeout scheduling only (delayed signal delivery is a pure delayed-job problem)
- JSONB messages column with persist-at-boundaries strategy (avoids write amplification)
- Gapless sequences per conversation (one loop at a time per conversation makes this safe)
- Domain-language signal types (approval, pr_review, pr_merged, pr_closed) instead of Temporal signal names
- WaitForState uses mutable flag pattern (not exceptions) for executor interception
- Single-summary-block-with-merge strategy for history compaction (prevents summaries-of-summaries)
- SpawnAgentDeps travels inside ToolContext.spawnDeps (preserves ToolFactory type signature)
- Three-phase deletion order: refactor references -> delete files -> remove deps

**Issues Resolved:**
- Temporal workflow orchestration replaced with Postgres-backed ConversationExecutor
- Three disconnected persistence stores (execution_traces, tasks, context_snapshots) unified into single event log
- 12 Docker services reduced to 6 by consolidating into single agent service
- ~86 dead files and ~21,590 lines of legacy code removed
- 5 E2E bugs resolved (tool event recording, MCP isError propagation, workspace context, retry-after header, Slack context duplication)
- All lint errors and dead code cleaned up

**Issues Deferred:**
- Dispatcher route fallback defaults reference router:3006 instead of agent-service:3004 (22 occurrences; runtime correct via docker-compose env)
- Two signal types (user_reply, cancel) defined but no adapter produces them (reserved for future)
- schema.drizzle.ts retains legacy table definitions (intentional, prevents destructive migrations)

**Technical Debt Incurred:**
- schema.drizzle.ts legacy definitions are permanent (drizzle-kit migration safety)
- Dispatcher fallback defaults are cosmetic only (docker-compose overrides in production)
