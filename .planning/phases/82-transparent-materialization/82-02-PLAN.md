    Add a materialization guidance section to BOTH prompt files. Follow PROMPT_GUIDE.md principles: goal-oriented, judgment criteria, no state machines, minimal directive density.

    **Section to add (adapt wording to each agent's voice/role):**

    The section should cover:

    1. **What materialization is:** When delegating tasks, you can optionally create a corresponding Linear issue that gives human operators visibility. Use the `materialization` parameter on `delegate_task` or `delegate_group`.

    2. **The parameter shape:** `materialization: { type: "transparent", target: "linear", properties: { priority: "high" } }` -- priority is optional (urgent/high/medium/low/none), teamId is optional (defaults to parent issue's team or system default).

    3. **Decision heuristic (judgment-based, not prescriptive rules):**
       - Materialize when the work originated from a human request and they'd want to track progress in Linear
       - Keep internal for agent-internal decomposition: sub-tasks like code generation, research, or testing that are implementation details
       - Think: "Would a human PM create a separate ticket for this?" If yes, materialize.
       - When working on an existing Linear issue, materialized sub-delegations become sub-issues of that parent automatically

    4. **Nesting depth:** Default to materializing immediate decomposition of human-initiated work. Deeper delegation chains (sub-agent's sub-agent) should stay internal -- Linear gets unwieldy beyond 2-3 nesting levels, and humans care about outcomes not agent coordination details.

    5. **Completion summary:** When completing work on a materialized task, post a summary comment on the Linear issue before calling complete_task. Include: what was done, key artifacts (PR links), notable decisions. The issue then automatically moves to Done. If for some reason you can't post the comment, complete the task anyway -- the status sync handles the issue transition.

    **For product-agent specifically:** Product-agent primarily delegates to dev-agent and qa-agent. Guidance should emphasize materializing delegations to dev-agent for feature work and qa-agent for verification (human-initiated, wants visibility). Research or clarification sub-delegations stay internal.

    **For dev-agent specifically:** Dev-agent delegates to coder, researcher, and tester sub-agents. These are almost always internal (implementation details). Dev-agent should only materialize when it's re-delegating work that originated from a human and the human would benefit from seeing the decomposition.

    **Style requirements per PROMPT_GUIDE.md:**
    - Use "prefer" and "tend toward" instead of MUST/ALWAYS/NEVER
    - Describe judgment criteria, not branching rules
    - Keep it concise -- 15-25 lines max per agent
    - No if/then/else classification trees
