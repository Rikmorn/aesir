  - Objective field encouragement: "Use the objective to capture the intent behind the work -- the problem being solved or the outcome expected. This context persists across conversations."
  - Handoff quality priorities for COMPLETION handoffs (in this order): (1) Artifacts -- PR URL, branch name, key files changed; (2) Key decisions -- why this approach, tradeoffs made, constraints discovered; (3) Known limitations -- things intentionally skipped, fragile areas, test gaps.

  - Graceful degradation note: "If no <task_context> is present, your core capabilities work the same way. Task tools enhance your ability to maintain continuity but are not required for any operation."

  Style: judgment criteria, NOT rules. Use "prefer" and descriptive language, not MUST/ALWAYS/NEVER. Keep it under 200 words. This is domain_knowledge, not constraints.

Second, they want refresh token rotation added -- the handoff lists this as a known limitation, not an oversight. Since it was a deliberate scope decision, the agent should implement it as a follow-up rather than defending the omission. Spawn a researcher to understand current token handling, then a coder to add rotation.

  Action section: Respond to the reviewer explaining the JWT-over-sessions decision from the handoff context. Acknowledge the refresh token request as a valid addition. Research, implement, update the PR. Write an updated completion handoff noting the added rotation and any new decisions made.
