Extend `wait_for_task` so the delegator can explicitly reject a counter-proposal instead of relying on the 30-second timeout.

1. **Extend the input schema**: Add an optional `action` field to `WaitForTaskInputSchema`:
```typescript
action: z
  .enum(["accept", "reject"])
  .optional()
  .default("accept")
  .describe(
    "Action to take on a counter-proposed task. 'accept' (default) accepts the modified scope. " +
    "'reject' rejects the counter-proposal and cancels the task."
  ),
```

2. **Add reject branch**: After the existing auto-accept block (lines 76-100 which check `task?.status === "counter_proposed"`), add a reject path within the same `if (task?.status === "counter_proposed")` block. Structure:

```typescript
if (task?.status === "counter_proposed") {
  if (parsed.action === "reject") {
    // Send rejection signal to target
    const targetConv = await ctx.delegationDeps.executor.findActiveForTask(parsed.taskId);
    if (targetConv) {
      await ctx.delegationDeps.executor.signal(targetConv.id, {
        type: "task_handshake",
        data: {
          taskId: parsed.taskId,
          response: "rejected",
          rejectedBy: ctx.agentId,
        },
        message: `Counter-proposal rejected for task ${parsed.taskId}`,
        source: `agent:${ctx.agentId}`,
        deduplicationId: `handshake-reject-${parsed.taskId}`,
      });
    }
    // Transition task to cancelled
    await ctx.delegationDeps.taskService.update(parsed.taskId, {
      status: "cancelled",
    });
    // Do NOT set waitForState -- the delegator should NOT pause after rejecting
    return {
      content: `Counter-proposal for task ${parsed.taskId} rejected and task cancelled. You can re-delegate to a different agent or take a different approach.`,
    };
  }

  // Existing accept path (already present)...
}
```

Key design points:
- `action` defaults to `"accept"`, so existing callers (no action param) continue to auto-accept -- fully backward compatible.
- Reject does NOT set `waitForState.triggered` -- the delegator continues its conversation immediately after rejection instead of pausing.
- The `task_handshake` signal with `response: "rejected"` is already handled by `computeUpdatedDelegations` in worker-loop.ts (line 415) -- no changes needed there.
- The target agent's counter-propose wait is listening for `task_handshake` (respond-task.ts:184), so it will resume and see the rejection message.
- Task transitions from `counter_proposed` to `cancelled` which is valid per `VALID_TRANSITIONS` in types.ts.

```
"Use after calling delegate_task to wait for the delegated agent's result."
```
