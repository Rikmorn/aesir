<objective>
Create the `task:clarify` and `task:answer` tools that enable mid-task clarification between target and delegator agents. The target asks questions (auto-pausing), the delegator answers (auto-re-entering wait_for_task), and the target resumes with the answer.

Purpose: Enable agents to resolve ambiguity during execution rather than proceeding with wrong assumptions or rejecting outright.
Output: Two new tool factories (clarify-task.ts, answer-task.ts), barrel exports, registry registration, and worker-loop WaitForState wiring.
</objective>

    **1. Create `clarify-task.ts` -- the target agent's clarification tool:**

    Follow the pattern from `respond-task.ts` for tool factory structure.

    Input schema:
    ```typescript
    const ClarifyTaskInputSchema = z.object({
      taskId: z.string().min(1).describe("The delegated task ID to clarify"),
      question: z.string().min(1).describe("The clarification question for the delegator"),
      options: z.array(z.string()).optional().describe(
        "Optional structured choices when the question has discrete answers (e.g., ['OAuth', 'JWT', 'Session-based'])"
      ),
    });
    ```

    Factory signature:
    ```typescript
    export function createClarifyTaskTool(
      ctx: ToolContext,
      waitForState?: WaitForState,
    ): ToolDefinition
    ```

    Tool name: `"clarify_task"` (matches namespace:tool_name pattern as `task:clarify` in YAML).

    Tool description:
    ```
    "Send a clarification question back to the delegating agent. " +
    "Automatically pauses this conversation until the delegator answers. " +
    "Use when you need to understand the delegator's intent before proceeding -- " +
    "for example, when a requirement is ambiguous and the wrong assumption " +
    "would waste significant work. Provide structured options when the " +
    "question has discrete answers to help the delegator respond quickly."
    ```

    Execute function logic:
    a) Check `ctx.delegationDeps` exists (same guard as respond-task)
    b) Parse and validate input
    c) Get the task via `deps.taskService.get(taskId)` -- verify it exists and has a `parent_id`
    d) Find the delegator's active conversation: `deps.executor.findActiveForTask(task.parent_id)`
    e) If no delegator found, return error: "Delegator conversation not found. Cannot send clarification without an active delegator."
    f) Build the `task_clarification` signal:
       ```typescript
       const signal: Signal = {
         type: "task_clarification",
         data: {
           taskId: parsed.data.taskId,
           question: parsed.data.question,
           ...(parsed.data.options && { options: parsed.data.options }),
           respondedBy: ctx.agentId,
         },
         message: `Clarification needed for task ${parsed.data.taskId}: ${parsed.data.question}`,
         source: `agent:${ctx.agentId}`,
         deduplicationId: `clarify-${parsed.data.taskId}-${Date.now()}`,
       };
       ```
       NOTE: The deduplicationId includes a timestamp because the same task can have multiple clarification rounds. Each round is a distinct signal.
    g) Send signal: `await deps.executor.signal(parentConv.id, signal)`
    h) Auto-enter wait_for (asking and waiting is a single logical operation):
       ```typescript
       if (waitForState) {
         waitForState.triggered = true;
         waitForState.waitTypes = ["task_clarification_response"];
         waitForState.reason = `Waiting for clarification answer on task ${parsed.data.taskId}`;
         waitForState.timeout = null; // Task timeout is the universal bound
         waitForState.metadata = { taskId: parsed.data.taskId };
       }
       ```
    i) Return success message: "Clarification sent. Conversation paused until delegator responds."

    Imports: `z` from zod, `Signal` and `ToolContext` and `WaitForState` from framework/types.js, `ToolDefinition` and `ToolResult` from agent-loop/types.js.

    **2. Create `answer-task.ts` -- the delegator's clarification answer tool:**

    This is the delegator-side tool for answering clarification questions. Per the research, the delegator needs a mechanism to send `task_clarification_response` signals. This tool also auto-re-enters `wait_for_task` after answering, preventing CRITICAL-1 deadlock.

    Input schema:
    ```typescript
    const AnswerTaskInputSchema = z.object({
      taskId: z.string().min(1).describe("The task ID that sent the clarification question"),
      answer: z.string().min(1).describe("Your answer to the clarification question"),
    });
    ```

    Factory signature:
    ```typescript
    export function createAnswerTaskTool(
      ctx: ToolContext,
      waitForState?: WaitForState,
    ): ToolDefinition
    ```

    Tool name: `"answer_task"` (maps to `task:answer` in YAML).

    Tool description:
    ```
    "Answer a clarification question from a delegated agent. Sends your answer " +
    "and automatically re-enters wait_for_task to continue listening for the " +
    "task's completion, failure, or further clarifications. " +
    "Use when a delegated agent asks a clarification question during task execution."
    ```

    Execute function logic:
    a) Check `ctx.delegationDeps` exists
    b) Parse and validate input
    c) Find the target's conversation: `deps.executor.findActiveForTask(taskId)`
       (The target's conversation is waiting on this task, not the parent.)
    d) If no target found, return error: "Target agent conversation not found. The agent may have timed out."
    e) Build the `task_clarification_response` signal:
       ```typescript
       const signal: Signal = {
         type: "task_clarification_response",
         data: {
           taskId: parsed.data.taskId,
           answer: parsed.data.answer,
           answeredBy: ctx.agentId,
         },
         message: `Clarification answer for task ${parsed.data.taskId}: ${parsed.data.answer}`,
         source: `agent:${ctx.agentId}`,
         deduplicationId: `clarify-answer-${parsed.data.taskId}-${Date.now()}`,
       };
       ```
    f) Send signal: `await deps.executor.signal(targetConv.id, signal)`
    g) **Auto-re-enter wait_for_task** (CRITICAL for deadlock prevention):
       ```typescript
       if (waitForState) {
         waitForState.triggered = true;
         waitForState.waitTypes = [
           "task_completion",
           "task_failure",
           "task_timeout",
           "task_clarification",
           "task_counter_proposed",
         ];
         waitForState.reason = `Waiting for delegated task ${parsed.data.taskId} after answering clarification`;
         waitForState.timeout = null;
         waitForState.metadata = { taskId: parsed.data.taskId };
         waitForState.timeoutSignalType = "task_timeout";
       }
       ```
       This mirrors exactly what `wait_for_task` does. The delegator is paused listening for all delegation signals, preventing the CRITICAL-1 deadlock where a completion signal arrives but the delegator is waiting for the wrong type.
    h) Return success message: "Answer sent. Conversation paused -- waiting for task to complete or send further clarifications."

    **Important note on finding the target conversation:**
    The delegator calls `answer_task(taskId)`. The target is the agent WORKING on that task. Use `deps.executor.findActiveForTask(taskId)` (same taskId, not parent_id) to find the target's conversation. This is different from `clarify-task.ts` which uses `task.parent_id` because the target is looking up toward the delegator.
