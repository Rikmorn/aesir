<objective>
Add replyContext forwarding to the router's slow-path tool chain. Extends signal_conversation and start_conversation tool schemas with an optional replyContext field, implements auto-injection from the incoming event's replyContext via EventRouterDeps, and threads the eventReplyContext through the slow-path dispatch in router.ts.

Purpose: Enables the slow-path LLM router to propagate channel routing metadata (replyContext) through signal and start calls, so agents know where to reply. Auto-injection means the LLM doesn't need to construct replyContext -- it flows automatically from the incoming event.

Output: Four modified files -- types.ts, signal-conversation.ts, start-conversation.ts, router.ts.
</objective>

Change to thread eventReplyContext from the incoming event through to the deps:

```typescript
case "slow_path": {
  const slowPathDeps = {
    ...deps,
    ...(routeDecision.event.replyContext && {
      eventReplyContext: routeDecision.event.replyContext,
    }),
  };
  void routeViaAgentLoopV2(event, slowPathDeps).catch((error) => {
    eventLogger.error(
      { err: error },
      "Background slow-path routing failed",
    );
    void sendRoutingAlertV2(event, deps);
  });
  return { received: true, action: "classifying" };
}
```
