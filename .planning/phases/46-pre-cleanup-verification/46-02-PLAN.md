Create `scripts/validate-docker-compose.sh` -- a bash script that validates the full Docker Compose deployment works end-to-end.

**Script requirements:**
- `#!/usr/bin/env bash` with `set -euo pipefail`
- Accept optional `--keep` flag to skip teardown (useful for debugging)
- Accept optional `--timeout` flag to set max wait time (default 120s)
- Use colored output for [OK], [WAIT], [FAIL] markers
- Exit with code 0 on success, 1 on failure
- Always tear down (unless --keep) even on failure (trap handler)

**Script steps:**

1. **Pre-flight check:** Verify `docker compose` command exists, verify docker-compose.yml exists at project root
2. **Build and start:** `docker compose up -d --build` (build to ensure latest code)
3. **Wait for health endpoints** with polling loop:
   - Poll `http://localhost:3001/health` (linear-integration) -- expect `{"status":"ok"}`
   - Poll `http://localhost:3002/health` (github-integration) -- expect `{"status":"ok"}`
   - Poll `http://localhost:3003/health` (slack-integration) -- expect `{"status":"ok"}`
   - Poll `http://localhost:3004/health` (agent-service) -- expect `{"status":"ok"}`
   - Use exponential-ish backoff: poll every 5s, max 120s total
   - Print progress: `[WAIT] agent-service not ready (15/120s)...`
   - On timeout: print `[FAIL]`, dump `docker compose logs` for the failed service, and exit 1
4. **Send test event:** POST to `http://localhost:3004/events` with:
   ```json
   {
     "id": "validate-001",
     "type": "linear.issue.created",
     "source": "linear",
     "timestamp": "2026-02-03T00:00:00Z",
     "payload": {"issueId": "TEST-001"},
     "correlationId": "validation-run"
   }
   ```
   This event type maps to "ignore" action in the EventRouter (safe, requires no external state).
   - Assert HTTP 200 response
   - Assert response body contains `"action":"ignored"` (the EventRouter ignores linear.issue.created events)
5. **Verify agent-service worker is running:** Check logs for "Agent service listening" or "Starting worker loop" pattern: `docker compose logs agent-service 2>&1 | grep -q "listening"`
6. **Report results:** Print summary table of all checks
7. **Tear down:** `docker compose down` (skip if --keep flag)

**Error handling:**
- Trap EXIT to ensure teardown runs even on script errors
- If any health check fails, print the failing service's Docker logs before exiting
- Capture curl response codes and bodies for assertion failures

**Make the script executable:** `chmod +x scripts/validate-docker-compose.sh`

**Important implementation notes:**
- Do NOT use `-v` (remove volumes) on teardown -- this would destroy the database
- The script should work from the project root directory
- Use `docker compose` (v2 syntax), not `docker-compose` (v1)
- Health endpoint URLs use localhost (host-mapped ports), not Docker network names

**Step 1: Service Startup**
- [ ] `docker compose up -d` starts all 6 services (postgresql, nginx, linear, github, slack, agent-service)
- [ ] `docker compose ps` shows all services as "healthy"
- [ ] No error logs in startup: `docker compose logs --tail=20`

**Step 2: Health Endpoints**
- [ ] `curl http://localhost:3001/health` returns 200 with `{"status":"ok"}`
- [ ] `curl http://localhost:3002/health` returns 200 with `{"status":"ok"}`
- [ ] `curl http://localhost:3003/health` returns 200 with `{"status":"ok"}`
- [ ] `curl http://localhost:3004/health` returns 200 with `{"status":"ok","service":"agent-service"}`
- [ ] `curl http://localhost/health` returns 200 (nginx proxy)

**Step 3: Nginx Routing**
- [ ] `curl http://localhost/linear/health` proxies to linear-integration
- [ ] `curl http://localhost/github/health` proxies to github-integration
- [ ] `curl http://localhost/slack/health` proxies to slack-integration
- [ ] `curl http://localhost/agent/health` proxies to agent-service

**Step 4: Event Routing**
- [ ] POST test event to agent-service, verify "ignored" response (linear.issue.created)
- [ ] POST test event via nginx proxy, verify routing works through proxy
- Include exact curl commands for each

**Step 5: Management Endpoints**
- [ ] GET `/conversations/nonexistent` returns 404
- [ ] POST `/conversations/nonexistent/cancel` returns 409 or appropriate error

**Step 6: Worker Loop Verification**
- [ ] `docker compose logs agent-service` shows "Starting worker loop" or "Agent service listening"
- [ ] No recurring errors in agent-service logs after 30s of running

**Step 7: Graceful Shutdown**
- [ ] `docker compose stop agent-service` triggers graceful shutdown
- [ ] Logs show "Graceful shutdown initiated" and "Graceful shutdown complete"
- [ ] `docker compose up -d agent-service` restarts cleanly

**Step 8: Service Independence**
- [ ] Integration services start and remain healthy even if agent-service is stopped
- [ ] Agent-service starts and becomes healthy after integrations are running
