<task type="auto">
  <name>Task 1: Fix timeout signal type mismatch for wait_for_task</name>
  <files>
    packages/agents/src/framework/types.ts
    packages/agents/src/framework/wait-for-task-tool.ts
    packages/agents/src/framework/worker-loop.ts
  </files>
  <action>
  The bug: worker-loop.ts:1330 passes `waitForState.waitTypes?.join(",")` to the timeout scheduler. For wait_for_task, this produces `"task_completion,task_failure,task_timeout"` as a single string. The scheduler fires a signal with `type: "task_completion,task_failure,task_timeout"`. signalMatchesPendingWait rejects it because `types.includes("task_completion,task_failure,task_timeout")` is false. The agent hangs forever.

  Fix:

  1. **types.ts**: Add `timeoutSignalType` to the `WaitForState` interface:
     ```typescript
     /** Signal type to use for timeout delivery. Defaults to first waitType if not set. */
     timeoutSignalType: string | null;
     ```
     Also update the `createDefaultWaitForState()` factory (if it exists in this file) to initialize `timeoutSignalType: null`.

  2. **wait-for-task-tool.ts**: In the execute function, after setting the existing waitForState fields, add:
     ```typescript
     waitForState.timeoutSignalType = "task_timeout";
     ```
     This ensures wait_for_task timeouts fire with type `"task_timeout"` specifically, which is already in the waitTypes array and will pass signalMatchesPendingWait.

  3. **worker-loop.ts**: Change line 1330 from:
     ```typescript
     waitForState.waitTypes?.join(",") ?? "unknown",
     ```
     to:
     ```typescript
     waitForState.timeoutSignalType ?? waitForState.waitTypes?.[0] ?? "unknown",
     ```
     This uses the explicit timeoutSignalType when set (wait_for_task), falls back to the first waitType for single-type waits (regular wait_for), and defaults to "unknown" as last resort.

  4. If `createDefaultWaitForState` exists elsewhere (e.g., tool-factories.ts or wait-for-tool.ts), also initialize `timeoutSignalType: null` there.
  </action>
  <verify>
  - `pnpm run typecheck` passes
  - `grep "timeoutSignalType" packages/agents/src/framework/types.ts` returns a match
  - `grep "timeoutSignalType" packages/agents/src/framework/wait-for-task-tool.ts` returns `"task_timeout"`
  - `grep "timeoutSignalType" packages/agents/src/framework/worker-loop.ts` shows fallback chain
  </verify>
  <done>Timeout signals for wait_for_task use type "task_timeout" instead of comma-joined string. Regular wait_for falls back to first (and only) waitType. signalMatchesPendingWait now correctly matches timeout signals.</done>
</task>
