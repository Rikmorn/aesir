  <files>

  <action>
    Create `task-signal-dispatcher.ts` following the factory pattern (createService with options object, interface return type).

    **Interface:**
    ```typescript
    interface TaskSignalDispatcherOptions {
      executor: ConversationExecutor;
      taskService: TaskService;
      eventLog: EventLog;
      db: NodePgDatabase<typeof agentsSchemaModule>;
      logger: PinoLogger;
    }

    interface TaskSignalDispatcher {
      /** Called by TaskService after a task status change. Dispatches signal if terminal + delegated. */
      onTaskUpdate(taskId: string, oldStatus: string, newStatus: string, handoffContext?: Record<string, unknown>): Promise<void>;
    }
    ```

    **onTaskUpdate logic:**
    1. Return early if newStatus is not terminal (`completed`, `failed`, `cancelled`)
    2. Fetch the full task via taskService.get(taskId)
    3. Return early if task has no parent_id (root tasks don't signal anyone)
    4. Determine signal type: `completed` -> `task_completion`, `failed`/`cancelled` -> `task_failure`
    5. Build self-contained signal payload:
       - Common: `taskId`, `originalDescription` (from task.objective or task.title), `entityId` (task.assignee_id)
       - task_completion: `summary` and `artifacts` from handoffContext (if provided), otherwise generic "Task completed"
       - task_failure: `reason` from handoffContext?.summary or "Task failed", `partialResults` from handoffContext?.artifacts
    6. Build completion_result object: `{ signalType, payload, writtenAt: new Date().toISOString(), deliveryStatus: "pending", targetConversationId: null }`
    7. Resolve callback conversation: `executor.findActiveForTask(task.parent_id)` -- routes through parent task to find latest active conversation
    8. **If no active conversation (orphan path):**
       - Set `completionResult.deliveryStatus = "orphaned"`
       - Write completion_result to task row via raw SQL update (direct db.update on tasks table, setting completion_result column)
       - Log `signal.orphaned` event via eventLog.append() with payload `{ taskId, signalType, parentTaskId: task.parent_id }`
       - Call eventLog.flush()
       - Log warning and return
    9. **If active conversation found:**
       - Build Signal object: `{ type: signalType, data: { taskId, ...payload }, message: buildSignalMessage(...), source: "task:${taskId}", deduplicationId: "${signalType}-${taskId}" }`
       - Set `completionResult.targetConversationId = callbackConv.id`
       - Call `executor.signal(callbackConv.id, signal)`
       - Set deliveryStatus based on result: `result.action === "rejected" ? "failed" : "delivered"`
       - Write completion_result to task row
    10. Wrap entire flow in try/catch -- signal dispatch failures are logged but never thrown (at-most-once delivery, task row is the safety net)

    **buildSignalMessage helper (private function):**
    Format a human-readable message for the signal.message field that the agent sees when it resumes:
    - task_completion: `"Task ${taskId} completed. Summary: ${payload.summary}"`
    - task_failure: `"Task ${taskId} failed. Reason: ${payload.reason}"`
    Include key artifacts in the message for quick agent comprehension.

    **Writing completion_result to task row:**
    Use direct `db.update(tasks).set({ completion_result: completionResult }).where(eq(tasks.id, taskId))` -- do NOT go through taskService.update() to avoid infinite recursion (since taskService.update() calls onTaskUpdate).
  </action>

  </verify>
