## Decisions Made
- **SELF-REF-FK:** Used plain `text("parent_id")` in Drizzle schema for the self-referential FK instead of `.references(() => tasks.id)` because Drizzle's type inference creates a circular reference that fails TypeScript compilation. The FK constraint is enforced by the database via the SQL migration.
- **SERVICE-SHAPE-ONLY:** TaskService validates data shape only (Zod schemas enforce size limits, required fields, enum values). Business logic like status transition rules and circular delegation prevention will live in the tool layer (Phase 58.2) where workflow context is available.
- **INPUT-TYPES:** Exported param types use `z.input<>` rather than `z.infer<>` so callers can omit fields that have Zod defaults (status defaults to "active", metadata defaults to {}).
