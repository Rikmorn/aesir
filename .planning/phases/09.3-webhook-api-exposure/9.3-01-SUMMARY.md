## What Was Built

1. **cloudflared service** in Docker Compose
   - Image: `cloudflare/cloudflared:2025.2.0`
   - Uses `profiles: - tunnel` for optional activation
   - Token via `CLOUDFLARE_TUNNEL_TOKEN` environment variable
   - Metrics endpoint on port 2000 for health checks

2. **cloudflared-health sidecar** for tunnel readiness checks
   - curl-based health check against `/ready` endpoint

3. **Environment variable documentation** in .env.example

## Deviations

Infrastructure issues discovered during verification required additional fixes:

1. **cloudflared command flag order**: `--metrics` flag must come before `run` subcommand
2. **Temporal health check**: Changed from `localhost:7233` to `127.0.0.1:7233` (IPv6 resolution issue)
3. **dev-agent dependency**: Changed to `service_started` for Temporal (it binds to container IP, not localhost)
4. **Dockerfile base image**: Changed from `node:20-alpine` to `node:20-slim` (Temporal SDK requires glibc)

## User Setup Required

After code deployment, user must:
1. Create tunnel in Cloudflare Zero Trust dashboard
2. Copy tunnel token to `.env` as `CLOUDFLARE_TUNNEL_TOKEN`
3. Configure public hostname routing to `http://dev-agent:3001`
4. Update Linear/GitHub webhook URLs to use tunnel URL
