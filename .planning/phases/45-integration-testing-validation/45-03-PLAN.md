Create a `createTestApp()` function that builds an Express app with the same route handlers as `service/main.ts` but using test-injected dependencies. Do NOT import or require the production `service/main.ts` (it calls `process.exit` on env validation and starts listening).

```typescript
function createTestApp(deps: {
  executor: ConversationExecutor;
  eventRouter: EventRouter;
  logger: PinoLogger;
}): express.Express {
  const app = express();
  app.use(express.json({ limit: "1mb" }));

  const routeEventDeps: RouteEventDeps = {
    executor: deps.executor,
    eventRouter: deps.eventRouter,
    logger: deps.logger,
  };

  app.get("/health", (_req, res) => {
    res.json({ status: "ok", service: "agent-service" });
  });

  app.post("/events", async (req, res) => {
    try {
      const parsed = NormalizedEventSchema.safeParse(req.body);
      if (!parsed.success) {
        res.status(400).json({ error: "Validation failed", issues: parsed.error.issues });
        return;
      }
      const result = await routeEvent(parsed.data, routeEventDeps);
      res.json(result);
    } catch (error) {
      res.status(500).json({ error: "Internal server error" });
    }
  });

  app.get("/conversations/:id", async (req, res) => {
    try {
      const info = await deps.executor.get(req.params.id);
      if (!info) { res.status(404).json({ error: "Conversation not found" }); return; }
      res.json(info);
    } catch (error) {
      res.status(500).json({ error: "Internal server error" });
    }
  });

  app.post("/conversations/:id/cancel", async (req, res) => {
    try {
      const cancelled = await deps.executor.cancel(req.params.id);
      if (!cancelled) { res.status(409).json({ error: "Conversation already in terminal state" }); return; }
      res.json({ cancelled: true });
    } catch (error) {
      res.status(500).json({ error: "Internal server error" });
    }
  });

  return app;
}
```

# Phase 45: Manual E2E Validation Checklist

Manual end-to-end validation for the v2.3 unified agent framework.

Docker networking, and agent behavior with real LLM calls.

## Prerequisites

- [ ] Docker Compose running: `docker compose up -d`
- [ ] Migrations applied: `pnpm db:migrate`
- [ ] MCP permissions seeded for all integrations
- [ ] Cloudflare tunnel (or ngrok) exposing local ports for webhook delivery
- [ ] Valid API keys in .env (ANTHROPIC_API_KEY, integration tokens)

## Known Limitations (Phase 45)

- Temporal code is still on disk (Phase 47 cleanup)
- Legacy database tables (tasks, context_snapshots, execution_traces) still exist
- Feature flag (USE_V23_EXECUTOR) not implemented yet -- v2.3 is the only active path
- Old per-agent services (dev-agent:3004, product-agent:3005) are removed from Docker Compose

## What's Different in v2.3

| Before (v2.2) | Now (v2.3) |
|---------------|------------|
| 3 separate agent services + router | 1 unified agent-service on port 3004 |
| Temporal workflows orchestrate agents | ConversationExecutor with PostgreSQL |
| Per-agent main.ts entry points | Single service/main.ts |
| Temporal UI at :8080 | No Temporal UI (use GET /conversations/:id) |
| Signal via Temporal workflowClient | Signal via POST /events or executor.signal() |

## Flow 1: Dev Agent -- Linear Issue to PR

### Trigger
1. [ ] Create a Linear issue in the configured team
2. [ ] Assign the "agent-ready" label (or trigger agent_session.created event)

### Verify Start
3. [ ] Check agent-service logs: `docker compose logs -f agent-service`
   - Expected: "Routing event", "Started new conversation"
   - Look for conversation ID (e.g., "dev-agent-AES-42")
4. [ ] Verify conversation exists: `curl http://localhost:3004/conversations/dev-agent-<issue-id>`
   - Expected: JSON with status "queued" or "running"

5. [ ] Watch logs for agent loop execution
   - Expected: "Claimed conversation", tool calls (read_file, create_branch, etc.)
6. [ ] Agent should pause for approval (wait_for with type "approval")
   - Expected: status changes to "waiting" in GET /conversations/:id

### Verify Approval Signal
7. [ ] Approve via Slack button (or send manual signal)
   - If no Slack button: `curl -X POST http://localhost:3004/events -H 'Content-Type: application/json' -d '{"id":"manual-approve","type":"slack.block_actions.approve","source":"slack","timestamp":"...","correlationId":"dev-agent-<issue-id>","payload":{"taskId":"<issue-id>","approved":true}}'`
8. [ ] Verify conversation resumed: GET /conversations/:id shows "running" then "completed"

### Verify Artifacts
9. [ ] Check GitHub for created branch and PR
10. [ ] Check session projection: event log should contain tool.succeeded events for create_branch and create_pull_request

### Verify Start

### Verify Completion
5. [ ] GET /conversations/product-agent-<id> shows "completed"
6. [ ] Linear issue exists with gathered requirements

### Duplicate Event
