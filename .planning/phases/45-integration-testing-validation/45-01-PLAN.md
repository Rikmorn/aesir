   Shared testcontainer lifecycle for all integration tests in this directory.

   - Import `setupPostgresContainer`, `cleanupPostgresContainer` from `@aesir/test-utils`

   - Import `Pool` from `pg` and `drizzle` from `drizzle-orm/node-postgres`
   - Import `* as schema` from `../../shared/db/schema.js`

   Export `IntegrationTestContext` interface:
   ```
   { container: PostgresContainerContext, pool: Pool, db: NodePgDatabase<typeof schema>, connectionUri: string }
   ```

   Export `setupTestContext()`: creates testcontainer, runs agents migration SQL via `container.sql.unsafe()`, creates pg Pool from connectionUri, creates drizzle instance. Returns IntegrationTestContext.

   Export `teardownTestContext(ctx)`: ends pool, cleans up container.

   Export `cleanupTables(ctx)`: runs TRUNCATE on agents tables. Use this SQL:
   ```sql
   TRUNCATE agents.agent_events, agents.agent_sessions, agents.conversations CASCADE
   ```
   Do NOT truncate agents.tasks, agents.context_snapshots, agents.execution_traces (legacy tables that may have FK issues). Do NOT truncate any pgboss.* tables.

   IMPORTANT: Set required env vars BEFORE any framework module imports to prevent process.exit(1) from shared/env/config.ts. At the top of setup.ts (before any other imports), set:
   ```typescript
   process.env.ANTHROPIC_API_KEY = process.env.ANTHROPIC_API_KEY || "test-key-not-real";
   process.env.LINEAR_TEAM_ID = process.env.LINEAR_TEAM_ID || "test-team";
   process.env.GITHUB_REPO = process.env.GITHUB_REPO || "test-org/test-repo";
   process.env.SLACK_CHANNEL_ID = process.env.SLACK_CHANNEL_ID || "C000TEST";
   process.env.NODE_ENV = "test";
   ```
   These MUST be at the very top of the file, before all import statements.

2. Create `packages/agents/src/framework/__integration__/helpers.ts`:

   Test helper utilities for controlling agent behavior in integration tests.

   a) Mock agent loop factory functions. These create controlled `runAgentLoop` implementations.
      Do NOT use `vi.mock()` in helpers.ts -- that is done in the test files themselves.
      Instead, export helper functions that configure a mock function:

      - `mockAgentLoopCompletes(mockFn, output?)`: Configures the mock to return AgentLoopResult with status "completed"
      - `mockAgentLoopPauses(mockFn, waitType?, reason?, timeout?)`: Configures the mock to find the wait_for tool in the tools array and call it, triggering WaitForState mutation
      - `mockAgentLoopErrors(mockFn, errorMessage?)`: Configures the mock to return AgentLoopResult with status "error"
      - `mockAgentLoopSequence(mockFn, sequence)`: Configures the mock to return different results on successive calls (first call pauses, second call completes, etc.)

      Each function takes the mock function as first arg. The test file creates the mock via `vi.mock()` and passes it here.

      Type hint: The mock implementation receives the options object from `runAgentLoop`. For pause mocking, access `options.tools` to find and call the `wait_for` tool. Use type assertion since the mock doesn't know the exact type.

   b) `waitForStatus(executor, conversationId, expectedStatus, timeoutMs?, pollMs?)`:
      Polls `executor.get()` every pollMs (default 50ms) until status matches or timeoutMs (default 5000ms) expires. Throws descriptive error on timeout.

   c) `createTestAgentRegistry()`: Returns an in-memory AgentRegistry with two agent definitions:
      - "dev-agent": triggers on "linear.agent_session.created", tools: ["coordination:wait_for"], maxIterations: 10, tokenBudget: 50000, history pruneThreshold: 80000
      - "product-agent": triggers on "slack.app_mention.created", tools: ["coordination:wait_for"], maxIterations: 5, tokenBudget: 10000, history pruneThreshold: 30000
      Both should have systemPrompt set to "You are a test agent." and version "1".
      The registry implements the AgentRegistry interface: get(id) returns definition or null, list() returns all.

   d) `createTestToolRegistry(agentRegistry, logger)`: Creates a real ToolRegistry via `createToolRegistry()` and registers at minimum the `coordination:wait_for` tool factory via `registerAllTools()` or manual registration. The wait_for tool is the only tool needed for lifecycle flow tests.

      IMPORTANT: If `registerAllTools()` registers tools that depend on MCP or external services, those will fail at resolution time (not registration time). That's fine -- tests only resolve "coordination:wait_for". If registerAllTools throws at registration time due to missing deps, instead manually register only `coordination:wait_for` using `createWaitForTool` from `../../framework/wait-for-tool.js`.

   e) `createTestEventRouter(agentRegistry, logger)`: Creates a real EventRouter via `createEventRouter()` and calls `loadStartRules()`. Returns the initialized router.

   Import types from the framework: AgentDefinition, AgentRegistry, ToolRegistry, ConversationExecutor, etc.
