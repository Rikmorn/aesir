  <action>
Based on audit findings, restructure each index.ts with clear sections.

**Pattern for index.ts files:**
```typescript
// @aesir/{package} - {description}

// === Public Types ===
export type { TypeA, TypeB } from "./module-a/index.js";
export type { TypeC } from "./module-b/index.js";

// === Public Values (functions, classes, constants) ===
export { functionA, ClassB } from "./module-a/index.js";
export { constantC } from "./module-b/index.js";

// === Re-exports from Dependencies ===
// Only if explicitly needed by downstream packages
export { something } from "@aesir/lower-layer";
```

**Key principles:**
1. Separate `export type { }` from `export { }` for clarity
2. Group by category: Types, Values, Re-exports
3. Remove internal module exports (db utilities, internal helpers)
4. Add brief comment describing package purpose

**Specific changes:**

**@aesir/common** - Minimal changes, add errors export:
- Add errors module export
- Keep all existing exports (all are public)

**@aesir/platform** - Keep sandbox, temporal, services:
- Export errors (new)
- Keep sandbox, temporal, services
- testing stays (used by tests in other packages)

**@aesir/integrations** - Keep client APIs, services:
- Export errors (new)
- Keep Linear/GitHub/Slack client functions
- Keep credential store, services
- Remove db internals from re-export if not needed externally

**@aesir/observability** - Minimal public surface:
- Export services (ExecutionTracker factory)
- Export errors (new)
- Keep db exports minimal (only if used externally)

**@aesir/agents** - Webhook handlers for HTTP:
- Export webhook handlers (for HTTP server setup)
- Keep minimal - agents are entry points, not libraries

After changes, run build to ensure no broken imports.
