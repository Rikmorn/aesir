         - title: string

         - type: "status_update"

       - Define MessageResult interface:
         - ts: string (message timestamp for replies/updates)
         - channel: string (channel where message was posted)

       - Define SendMessageOptions interface:
         - client: WebClient
         - channel: string
         - text: string (fallback text)
         - blocks?: Block[] (optional Block Kit)
         - threadTs?: string (reply in thread if provided)
         - unfurlLinks?: boolean (default false for cleaner messages)

       - Define PostNotificationOptions interface:
         - client: WebClient
         - notification: Notification
         - channel: string
         - threadTs?: string

       - Import Block, KnownBlock from @slack/web-api
       - Move and enhance from packages/integrations/src/slack/notifications.ts

       - Create buildApprovalBlocks(options: ApprovalBlockOptions): (Block | KnownBlock)[]
         - Section: "*PR Ready for Review*\n{title}"
         - Section: {summary}
         - Section: "<{prUrl}|View Pull Request>"
         - Actions with approve/reject buttons:
           - Approve button: style="primary", action_id="approve_pr", value=taskId
           - Reject button: style="danger", action_id="reject_pr", value=taskId
         - Context: "Task: {taskId} | Requested by: dev-agent"

       - Create buildStatusBlocks(options: StatusBlockOptions): (Block | KnownBlock)[]
         - Move from formatStatusMessage in notifications.ts
         - Section with emoji and status text
         - Optional context with details

       - Create buildSimpleMessage(text: string): (Block | KnownBlock)[]
         - Single section with mrkdwn text
         - For simple conversational replies

       - Create buildProgressBlocks(options: ProgressBlockOptions): (Block | KnownBlock)[]
         - For showing work in progress
         - Header, description, optional bullet list of steps

       - Define ApprovalBlockOptions:
         - taskId: string
         - prUrl: string
         - title: string
         - summary: string
         - actionPrefix?: string (default "approve" for action_id prefix)

       - Define StatusBlockOptions:
         - taskId: string
         - status: "started" | "completed" | "failed"
         - details?: string

       - Define ProgressBlockOptions:
         - title: string

    1. Create packages/integrations/slack/src/messages/sender.ts:
       - Import WebClient, Block from @slack/web-api
       - Import createPinoLogger from @aesir/common
       - Import ResultAsync from neverthrow
       - Import SlackError from ../types/errors.js
       - Import types and blocks

       - Create sendMessage(options: SendMessageOptions): Promise<MessageResult>
         - Destructure client, channel, text, blocks, threadTs, unfurlLinks
         - Call client.chat.postMessage({
             channel,
             text,
             blocks,
             thread_ts: threadTs, // Reply in thread if provided
             unfurl_links: unfurlLinks ?? false,
           })
         - Return { ts: result.ts!, channel: result.channel! }
         - Log success at info level with channel, ts
         - On error, log at error level and re-throw

       - Create replyToEvent(options: ReplyToEventOptions): Promise<MessageResult>
         - For replying to an event while maintaining thread context
         - Extract threadTs from event (event.thread_ts || event.ts)
         - Call sendMessage with computed threadTs
         - Follows RESEARCH.md pattern for thread-aware replies

       - Create postNotification(options: PostNotificationOptions): Promise<MessageResult>
         - Determine notification type
         - Build appropriate blocks (approval or status)
         - Get fallback text
         - Call sendMessage
         - Return result
         - Match existing postNotification behavior from notifications.ts

       - Create sendApprovalRequest(client, notification, channel, threadTs?): Promise<MessageResult>
         - Semantic wrapper for approval notifications
         - Build approval blocks with action buttons
         - Call sendMessage

       - Create sendStatusUpdate(client, notification, channel, threadTs?): Promise<MessageResult>
         - Semantic wrapper for status notifications
         - Build status blocks
         - Call sendMessage

       - Create openDmChannel(client: WebClient, userId: string): Promise<string>
         - Move from notifications.ts
         - Call client.conversations.open({ users: userId })
         - Return channel.id
         - Throw if channel cannot be opened

       - Define ReplyToEventOptions:
         - client: WebClient
         - event: { channel: string; ts: string; thread_ts?: string }
         - text: string
         - blocks?: Block[]
