<objective>
Add echo loop prevention for Linear comment webhooks so that agent-authored comments (via communication:reply to Linear) are not re-dispatched to the agent service as new inbound events.

Purpose: When agents use communication:reply/ask/notify targeting Linear issues, the denormalizer calls linear:create_comment. Linear fires a webhook for that comment. Without echo filtering, the webhook re-enters the agent pipeline causing an infinite loop. This is a prerequisite for agents using communication tools on Linear channels.

Output: Modified Linear webhook handler that compares comment author userId against the stored OAuth user ID, dropping self-authored comments. Unit tests proving the filter works.
</objective>

   - Extract the Linear user ID associated with the OAuth token. The Linear SDK's `LinearClient.viewer` query returns the authenticated user. However, calling the API on every webhook is expensive. Instead, use a simpler approach:
     - Add a `LINEAR_BOT_USER_ID` env var to the Linear integration config (`linearEnvSchema` in `types/config.ts`). This is the Linear user ID of the OAuth bot account. Operators set it once during setup.
     - Compare `commentPayload.data.userId` against `config.linear.botUserId`
     - If they match, log at info level "Ignoring self-authored comment (echo filter)" and return 200
   - If `LINEAR_BOT_USER_ID` is not configured, log a warning once and skip filtering (graceful degradation)

   - Place under the `linear` config group
