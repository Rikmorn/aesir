**Schema extension (schema.ts):**
Add three table definitions to the dashboard's local schema, mirroring the canonical definitions in `packages/agents/src/shared/db/schema.ts`. The dashboard only reads, never writes. Add after the agentEventContent table:

1. `tasks` table -- mirror the canonical schema exactly: id, parent_id, creator_type, creator_id, assignee_type, assignee_id, status, title, objective, metadata (jsonb), depth (integer), completion_result (jsonb), created_at, updated_at, completed_at. Status enum: "created", "active", "paused", "completed", "cancelled". Add `signal.orphaned` to the agentEventTypeValues array (it was added in Phase 71 but the dashboard schema wasn't updated).

2. `taskHandoffs` table: id, task_id, conversation_id, handoff_type, context (jsonb), author_type, author_id, created_at. Handoff type enum: "completion", "pause", "delegation", "escalation".

3. `entityDirectory` table: id, type, name, description, capabilities (jsonb string[]), status, created_at, updated_at. Status enum: "active", "inactive". Type enum: "agent", "human".

Add type exports: `Task`, `TaskHandoff`, `EntityDirectoryEntry`.

**Task tree service (services/tasks.ts):**
Follow the exact pattern from `services/conversations.ts`: typed interfaces, Drizzle queries, camelCase mapping.

Create `getTaskTree(rootTaskId: string)` -- recursive CTE via `db.execute(sql\`...\`)`:
- WITH RECURSIVE task_tree: base case selects root task by ID, recursive case joins children with `WHERE tree_depth < 5` safety limit
- JOIN conversations ON c.task_id = tt.id (LEFT JOIN, some tasks may not have conversations)
- JOIN entity_directory ON ed.id = tt.assignee_id (LEFT JOIN for entity name)
- ORDER BY tree_depth, created_at
- Return typed `TaskTreeNode[]` (flat array, NOT nested tree -- the client builds the tree from parentId)

`TaskTreeNode` interface: id, parentId, creatorId, assigneeId, entityName, status, title, objective, depth, completionResult, metadata, conversationId, conversationStatus, createdAt (string ISO), updatedAt (string ISO), completedAt (string ISO | null).

Create `getTaskTimeline(taskIds: string[])` -- get delegation lifecycle events:
- Query agent_events for conversations whose task_id is in the provided taskIds array
- Filter event types: 'agent.started', 'agent.completed', 'agent.paused', 'agent.resumed', 'signal.received', 'signal.orphaned'
- Also get 'tool.called' and 'tool.succeeded' events but filter in application code: only keep those where payload.toolName matches 'task:delegate', 'task:respond', 'task:complete', 'wait_for_task'
- JOIN tasks via conversations.task_id to get assignee_id
- JOIN entity_directory for entity_name
- Return typed `TimelineEvent[]`: id, conversationId, taskId, entityName, type, payload, timestamp (ISO string)
- ORDER BY timestamp ASC

Create `listRootTasks(params)`:
- Query tasks WHERE parent_id IS NULL
- LEFT JOIN entity_directory for entity name (on tasks.creator_id = ed.id)
- Subquery for subtask count: `(SELECT count(*) FROM agents.tasks WHERE parent_id = t.id)`
- Accept optional status filter array and pagination (limit, offset)
- Return `{ items: RootTaskListItem[], total: number }` with id, title, status, creatorEntityName, subtaskCount, createdAt, updatedAt, completedAt

Create `computeTreeHealth(nodes, events)` -- pure function:
- orphanedCount: count events with type 'signal.orphaned'
- timeoutCount: count events with type 'signal.received' AND payload.signalType === 'timeout'
- rejectionChainCount: count nodes whose metadata has a `rejected` property set to true (or whose status is 'cancelled' with rejection-indicating metadata)
- depthLimitReached: any node with depth >= 3
- severity: 'failure' if any node failed OR orphanedCount > 0, 'warning' if timeoutCount > 0 or rejectionChainCount > 0 or depthLimitReached, 'clean' otherwise
- Return `TreeHealth` interface

Create `getRootTaskId(taskId: string)` -- walk parent_id up to root:
- Simple recursive CTE: start from taskId, follow parent_id until parent_id IS NULL
- Return the root task ID string

Create `getTreeHealthForRoots(rootTaskIds: string[])` -- batch health computation for the task list page:
- For each root ID, get tree nodes and events, compute health
- Return `Map<string, TreeHealth>` keyed by root task ID
- Used by the task list page to populate the health column

**API route (api/tasks/[taskId]/tree/route.ts):**
Follow the exact pattern from `api/events/[id]/content/route.ts`:
- GET handler, extract taskId from params
- Call getTaskTree(taskId) to get nodes
- Extract all taskIds from nodes
- Call getTaskTimeline(taskIds) to get events
- Call computeTreeHealth(nodes, events)
- Return JSON: { nodes, events, health }
- Handle missing task: return 404
