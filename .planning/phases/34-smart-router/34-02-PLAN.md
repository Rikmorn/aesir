Each tool is a factory function that takes `RouterDeps` (from types.ts) and returns a `ToolDefinition` object (from shared/agent-loop/types.ts). Tools use Zod schemas for input validation.

**query-workflows.ts** - `createQueryWorkflowsTool(deps: RouterDeps): ToolDefinition`

Input schema (Zod):
```
z.object({
  taskId: z.string().optional().describe("Filter by task ID to check if a specific workflow is running"),
  workflowType: z.string().optional().describe("Filter by workflow type (e.g., 'devAgentWorkflow', 'productAgentConversationWorkflow', 'orchestratorWorkflow')"),
})
```

Execute function:
- Use `deps.workflowClient.workflow.list()` with SQL-like query filter
- If taskId provided: filter by `WorkflowId = "dev-agent-{taskId}"` (check both dev-agent and product-agent patterns)
- If workflowType provided: filter by `WorkflowType = "{workflowType}"`
- Default: `ExecutionStatus = "Running"`
- Iterate async iterable, collect up to 20 results
- Return JSON stringified array of `{ workflowId, status, workflowType }` objects
- On error: return `{ content: error message, isError: true }`

Description: "List running Temporal workflows. Use to check if a workflow exists before signaling it. Returns workflow IDs, types, and statuses."

**start-workflow.ts** - `createStartWorkflowTool(deps: RouterDeps): ToolDefinition`

Input schema (Zod):
```
z.object({
  agentType: z.enum(["dev-agent", "product-agent"]).describe("Which agent to start"),
  workflowId: z.string().describe("Unique workflow ID (e.g., 'dev-agent-{issueId}' or 'product-agent-{threadTs}')"),
  input: z.record(z.unknown()).describe("Workflow input object matching the agent's expected input schema"),
})
```

Execute function:
- Map agentType to workflow name: "dev-agent" -> "devAgentWorkflow", "product-agent" -> "productAgentConversationWorkflow"
- Map agentType to task queue: "dev-agent" -> "dev-agent", "product-agent" -> "product-agent"
- Start workflow: `deps.workflowClient.workflow.start(workflowName, { taskQueue, workflowId, args: [input] })`
- Handle WorkflowExecutionAlreadyStartedError gracefully (return success with note)
- Return JSON: `{ started: true, workflowId }` or `{ started: false, reason: "already exists" }`
- On error: return `{ content: error message, isError: true }`

Description: "Start a new Temporal workflow for the specified agent. Use dev-agent for Linear issue work, product-agent for Slack conversations."

**signal-workflow.ts** - `createSignalWorkflowTool(deps: RouterDeps): ToolDefinition`

Import signal definitions from `../../shared/temporal/signals.js`: `planApprovalSignal`, `prFeedbackSignal`, `escalationResolvedSignal`, `prCompletionSignal`, `userReplySignal`, `cancelConversationSignal`.

Input schema (Zod):
```
z.object({
  workflowId: z.string().describe("Workflow ID to signal (e.g., 'dev-agent-{issueId}')"),
  signal: z.enum([
    "planApproval",
    "prFeedback",
    "escalationResolved",
    "prCompletion",
    "userReply",
    "cancelConversation",
  ]).describe("Signal name to send"),
  payload: z.unknown().optional().describe("Signal payload (varies by signal type)"),
})
```

Execute function:
- Get workflow handle: `deps.workflowClient.workflow.getHandle(workflowId)`
- Map signal name string to imported signal definition objects using a const map:
  ```typescript
  const SIGNAL_MAP = {
    planApproval: planApprovalSignal,
    prFeedback: prFeedbackSignal,
    escalationResolved: escalationResolvedSignal,
    prCompletion: prCompletionSignal,
    userReply: userReplySignal,
    cancelConversation: cancelConversationSignal,
  } as const;
  ```
- Look up signal definition: `const signalDef = SIGNAL_MAP[signal]`
- Send signal with payload: `handle.signal(signalDef, payload)` (for signals that take payload) or `handle.signal(signalDef)` (for cancelConversation which takes no args)
- Handle WorkflowNotFoundError gracefully (return isError with helpful message)
- Return JSON: `{ signaled: true, workflowId, signal }` or `{ content: "Workflow not found", isError: true }`

Description: "Send a signal to an existing Temporal workflow. Use planApproval for approvals/rejections, prFeedback for PR reviews, escalationResolved for stuck task guidance, prCompletion for PR merge/close, userReply for thread replies, cancelConversation for conversation cancellation."

Create `packages/agents/src/router/slow-path.ts`:

1. Import `runAgentLoop` from `../../shared/agent-loop/index.js`
2. Import `ROUTER_SYSTEM_PROMPT` from `./system-prompt.js`
3. Import all 4 tool factories from `./tools/*.js`
4. Import `RouteResult`, `RouterDeps` from `./types.js`
5. Import `NormalizedEvent` from `@aesir/types`

Export `routeViaAgentLoop(event: NormalizedEvent, deps: RouterDeps): Promise<RouteResult>`:

Implementation:
- Create router tools by calling all 4 factory functions with deps
- Format the event for the LLM as the initial message:
  ```
  Route this event:

  Event ID: {event.id}
  Type: {event.type}
  Source: {event.source}
  Timestamp: {event.timestamp}

  Payload:
  {JSON.stringify(event.payload, null, 2)}
  ```
- Call `runAgentLoop()` with:
  - `systemPrompt: ROUTER_SYSTEM_PROMPT`
  - `tools: routerTools`
  - `initialMessage: formattedEvent`
  - `model: "claude-haiku-4-5-20251016"` (fast, cheap model for routing -- per research recommendation)
  - `maxIterations: 10` (ROUT-07: router iteration limit)
  - `logger: deps.logger`
  - `onToolCall: (call) => deps.logger.info({ toolName: call.name, toolInput: call.input }, "Router tool call")`
- Parse result:
  - If `result.status === "completed"` and at least one tool call was made (result.toolCallCount > 0): return `{ status: "routed", action: result.output }`
  - If `result.status === "completed"` and NO tool calls: return `{ status: "ignored", action: "LLM decided no action needed" }`
  - If `result.status === "max_iterations"`: return `{ status: "failed", error: "Router hit iteration limit" }`
  - If `result.status === "error"` or `result.status === "aborted"`: return `{ status: "failed", error: result.output || "Router LLM error" }`

Also export `formatEventForLLM(event: NormalizedEvent): string` as a named export for testability.

IMPORTANT: The slow path is called AFTER the fast path returns null. The router.ts (Plan 03) handles the fast/slow dispatch. This file only handles the agentic loop.
