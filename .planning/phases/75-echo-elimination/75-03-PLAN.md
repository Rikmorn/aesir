    Import `config` from `../shared/env/config.js`.
    Extract sender from payload:
    ```typescript

    ```

    ```typescript
    const githubAppLogin = config.echo.githubAppLogin;
    ```

    **5. pg-boss dedup cleanup job (service/main.ts):**
    After `executor.startWorker()` (step 12, ~line 352), schedule the cleanup job.

    The TimeoutScheduler's pg-boss instance is available after `timeoutScheduler.start(executor)` which happens inside executor.startWorker(). So schedule the cleanup AFTER startWorker():

    ```typescript
    // 12b. Webhook dedup cleanup -- hourly, 24h TTL (Phase 75)
    const boss = timeoutScheduler.getBoss();
    if (boss) {
      const DEDUP_CLEANUP_QUEUE = 'webhook-dedup-cleanup';
      await boss.createQueue(DEDUP_CLEANUP_QUEUE);
      await boss.schedule(DEDUP_CLEANUP_QUEUE, '0 * * * *', {});
      await boss.work(DEDUP_CLEANUP_QUEUE, async () => {
        const result = await pool.query(
          "DELETE FROM agents.processed_webhook_events WHERE received_at < now() - interval '24 hours'"
        );
        if (result.rowCount && result.rowCount > 0) {
          logger.info({ deletedCount: result.rowCount }, 'Webhook dedup cleanup completed');
        }
      });
      logger.info('Webhook dedup cleanup scheduled (hourly, 24h TTL)');
    }
    ```

    **IMPORTANT:** The `schedule: false` option in TimeoutScheduler's pg-boss config disables cron monitoring. The cleanup job uses `boss.schedule()` which IS a cron feature. Update the TimeoutScheduler's pg-boss options to `schedule: true` (or remove the `schedule: false` line). This is needed for `boss.schedule()` to work with cron expressions.

    Alternatively, if changing the schedule flag has side effects, use a simpler approach: schedule a recurring job via `boss.send()` with `startAfter` and have the worker re-schedule itself after each run. But `schedule: true` with `boss.schedule()` is cleaner and standard.

    **Update:** Set `schedule: true` in the pg-boss constructor options in timeout-scheduler.ts.
