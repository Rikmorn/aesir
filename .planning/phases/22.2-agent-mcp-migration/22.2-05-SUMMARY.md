- Request body serialization (params as JSON)
- Response parsing (`data`, `structuredContent`, fallback)
- Error handling (`McpError` on non-ok responses)

**Mocking Pattern:**
```typescript
const { mockFetch } = vi.hoisted(() => {
  return { mockFetch: vi.fn() };
});

vi.mock("fetch-retry-ts", () => ({
  fetchBuilder: () => mockFetch,
}));
```

This pattern solves the module hoisting challenge where `vi.mock()` is hoisted to the top of the file before variable declarations. Using `vi.hoisted()` ensures the mock function is available when the module factory runs.

  fetchBuilder: () => mockFetch,

// Mock @aesir/common to prevent env validation

  const actual = await vi.importActual("@aesir/common");
  return {
    ...actual,
    generateCorrelationId: () => "test-corr-id",
  };

// Tests verify fetch calls

  mockFetch.mockResolvedValueOnce({
    ok: true,
    json: async () => ({ data: { ... } }),

        "X-Correlation-ID": "test-corr-id",
      }),
      body: JSON.stringify({ param: "value" }),
    }),
  );
});

## Lessons Learned

### vi.hoisted() is Essential for Fetch Mocking

**Problem:** `vi.mock()` is hoisted to the top of the file, causing "cannot access before initialization" errors when referencing variables declared before the mock.

**Solution:** Use `vi.hoisted(() => ({ mockFetch: vi.fn() }))` to create the mock in a way that's available during module factory execution.

**Pattern:**
```typescript
// WRONG - causes error
const mockFetch = vi.fn();
vi.mock("fetch-retry-ts", () => ({
  fetchBuilder: () => mockFetch, // Error: cannot access mockFetch
}));

// RIGHT - works correctly
const { mockFetch } = vi.hoisted(() => ({
  mockFetch: vi.fn(),
}));
vi.mock("fetch-retry-ts", () => ({
  fetchBuilder: () => mockFetch, // Works!
}));
```

### Test Verification Shifted from SDK to HTTP

**Before:** Tests verified SDK client methods were called correctly
```typescript
expect(mockReadIssue).toHaveBeenCalledWith(client, "ABC-123");
```

**After:** Tests verify HTTP requests are made correctly
```typescript
expect(mockFetch).toHaveBeenCalledWith(
  expect.stringContaining("/mcp/tools/get_issue"),
  expect.objectContaining({
    body: JSON.stringify({ issueId: "ABC-123" }),
  }),
);
```

**Impact:** Tests now verify the transport layer (HTTP) instead of the SDK layer. This is more accurate to how the code actually works post-migration.

### Sequential MCP Calls Require mockResolvedValueOnce

For nodes that make multiple MCP calls (like `commit-pr`), use `mockResolvedValueOnce` in sequence:

```typescript
mockFetch
  .mockResolvedValueOnce({ ok: true, json: async () => ({ data: {} }) }) // Call 1
  .mockResolvedValueOnce({ ok: true, json: async () => ({ data: {} }) }) // Call 2
  .mockResolvedValueOnce({ ok: true, json: async () => ({ data: {} }) }); // Call 3
```

Then verify with `toHaveBeenNthCalledWith(n, ...)` to check each call in order.
