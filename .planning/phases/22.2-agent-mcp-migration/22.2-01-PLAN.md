   - Define `McpError` class extending Error
   - Constructor takes `McpErrorResponse` data
   - Add `toToolResult()` method that returns structured error for LLM consumption
   - Add getters for `type`, `code`, `correlationId`, `retryAfter` (for rate limits)

2. Create `packages/agents/src/mcp/client.ts`:
   - Import fetchRetry from 'fetch-retry-ts'
   - Create wrapped fetch: `const fetchWithRetry = fetchRetry(fetch)`
   - Add MCP URL configuration type and defaults:
     ```typescript
     const MCP_URLS: Record<McpIntegration, string> = {
       linear: process.env.LINEAR_MCP_URL || 'http://linear-integration:3001',
       github: process.env.GITHUB_MCP_URL || 'http://github-integration:3002',
       slack: process.env.SLACK_MCP_URL || 'http://slack-integration:3003',
     };
     ```
   - Implement `callMcpTool<T>(options: McpCallOptions): Promise<T>`:
     - Build URL: `${MCP_URLS[options.integration]}/mcp/tools/${options.tool}`
     - Add headers: Content-Type, X-Agent-ID, X-Correlation-ID
     - Configure retry: retries=3, retryDelay with exponential backoff (1s, 2s, 4s), retryOn=[429, 500, 502, 503, 504]
     - On non-ok response: parse JSON, throw McpError
     - On success: return `result.data || result.structuredContent || result`

3. Create `packages/agents/src/mcp/index.ts`:
   - Export all from types.ts, errors.ts, client.ts
  </action>
