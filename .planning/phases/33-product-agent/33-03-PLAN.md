    Update the Temporal workflow, activities index, and worker for the new agentic loop architecture.

    1. **Update `product-agent-workflow.ts`:**

       The workflow structure stays mostly the same (signal handling, timeout logic, max iterations all remain). Key changes:

       a. Update the `ProductAgentActivities` interface:
          - `runProductAgentActivity` now takes: `{ threadTs, message, teamId, channelId, conversationHistory? }` and returns `{ response, phase, issueId?, issueIdentifier? }`
          - KEEP `sendSlackReplyActivity` -- still needed for timeout messages, reminders, and cancellation acknowledgments that happen OUTSIDE the agent turn (the workflow sends these directly)

       b. Add conversation history tracking to workflow state:
          - Initialize `conversationHistory: Array<{ role: "user" | "assistant"; content: string }>` as an empty array at the start of the workflow
          - Before calling `runProductAgentActivity`, append the current user message: `conversationHistory.push({ role: "user", content: currentMessage })`
          - After `runProductAgentActivity` returns with a non-empty response, append the agent response: `conversationHistory.push({ role: "assistant", content: agentResult.response })`
          - Pass the full `conversationHistory` array to `runProductAgentActivity` via the input object

       c. Update the activity call in the main loop:
          - Pass `channelId` to `runProductAgentActivity` (from workflow input -- `input.channelId`)
          - Pass `conversationHistory` from the workflow state tracking array

       d. REMOVE the `sendSlackReplyActivity` call AFTER `runProductAgentActivity`:
          - The agent now sends its own Slack messages via the `slack_send_message` tool during its agentic loop
          - The `response` field from the activity is internal reasoning + phase tag, NOT a user-facing message
          - DO NOT send `agentResult.response` to Slack -- it would expose internal reasoning

       e. KEEP all `sendSlackReplyActivity` calls for:
          - Cancellation acknowledgment: "Got it, I've cancelled this conversation..."
          - 24h reminder: "Hey! Just checking in..."
          - 72h timeout: "This conversation has timed out..."
          - Max iterations: "This conversation has reached its maximum length..."
          These are workflow-level messages, not agent turns.

       f. Update the comments/JSDoc:
          - Remove references to "LangGraph" -- replace with "agentic loop"
          - Update the flow description to reflect the new architecture

    2. **Update `activities/index.ts`:**

       a. Update product agent imports:
          - Import `initProductAgentActivities` from `./product-agent-activity.js`
          - Import updated types `RunProductAgentActivityInput`, `RunProductAgentActivityOutput`
          - Re-export `initProductAgentActivities` and `extractPhase`

       b. Update the `makeActivities` function:
          - Add `initProductAgentActivities` to the setup path if applicable, OR keep the existing pattern where activities are loaded separately
          - Since the product agent worker loads activities via dynamic import (see worker.ts), the index.ts just needs correct re-exports

    3. **Update `worker.ts`:**

       a. Remove the checkpointer initialization:
          - Remove `import { createProductAgentCheckpointer } from "./workflow/checkpointer.js"`
          - Remove the `await createProductAgentCheckpointer()` call

       b. Add activity initialization:
          - Import `initProductAgentActivities` from `../shared/temporal/activities/product-agent-activity.js`
          - Import `createPinoLogger` from `@aesir/platform`
          - Import drizzle and postgres for database connection
          - Before creating the worker, initialize database connection:
            ```
            const connectionString = process.env.DATABASE_URL || buildConnectionString()
            const client = postgres(connectionString)
            const db = drizzle(client)
            ```
          - Call `initProductAgentActivities({ db, logger })`

       c. Update `loadActivities()`:
          - The runProductAgentActivity import stays the same (it's still imported from the same file)
          - Remove any comments about "LangGraph"

       d. Update comments/JSDoc to reflect new architecture

    IMPORTANT: The workflow's core loop structure (while, signal waits, timeout cascade, cancellation) remains unchanged. The changes are:
    1. Activity input shape gains channelId and conversationHistory
    2. Workflow tracks conversation history for injection
    3. No more sendSlackReplyActivity after agent turns (agent handles its own messages)
