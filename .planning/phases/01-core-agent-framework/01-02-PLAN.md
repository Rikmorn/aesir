## Tasks

### Task 1: Agent State Schema

**What:** Define the agent state using LangGraph's Annotation API with Zod schemas for type safety.

**File to create:** `src/state/agent-state.ts`

**State fields:**
```typescript
const AgentState = Annotation.Root({
  // Message history
  messages: Annotation<BaseMessage[]>({
    reducer: (x, y) => x.concat(y),
    default: () => [],
  }),

  // Loop protection (defense-in-depth beyond recursionLimit)
  loopCount: Annotation<number>({
    reducer: (_, y) => y,
    default: () => 0,
  }),

  // Execution status
  status: Annotation<"running" | "completed" | "error" | "timeout">({
    reducer: (_, y) => y,
    default: () => "running",
  }),

  // Task context
  taskDescription: Annotation<string>({
    reducer: (_, y) => y,
    default: () => "",
  }),

  // Generated output
  generatedCode: Annotation<string | null>({
    reducer: (_, y) => y,
    default: () => null,
  }),
});
```

**Files to create:**
- `src/state/agent-state.ts` - State schema definition
- `src/state/index.ts` - Public exports
- `src/state/agent-state.test.ts` - Unit tests

**Verification:**
- State schema compiles without TypeScript errors
- Default values are correctly initialized
- Reducers work as expected (messages concat, others replace)

### Task 2: Code Generation Tool

**What:** Create the code generation tool that the agent will use to generate code from task descriptions.

**File to create:** `src/tools/code-gen.ts`

**Tool definition:**
```typescript
const codeGenTool = tool(
  async ({ taskDescription, language, context }) => {
    // Log the tool invocation
    logger.log({
      action: "tool_call",
      context: { tool: "generate_code", taskDescription, language },
      outcome: "pending",
    });

    // For now, return a placeholder - actual LLM call will be in agent
    // The tool structures the request, agent handles LLM interaction
    return {
      code: `// TODO: Implement ${taskDescription}`,
      language,
      explanation: "Generated code placeholder",
    };
  },
  {
    name: "generate_code",
    description: "Generate code based on a task description. Use this to create new code files or functions.",
    schema: z.object({
      taskDescription: z.string().describe("Detailed description of what the code should do"),
      language: z.enum(["typescript", "javascript", "python"]).describe("Programming language"),
      context: z.string().optional().describe("Additional context like existing code or constraints"),
    }),
  }
);
```

**Files to create:**
- `src/tools/code-gen.ts` - Code generation tool
- `src/tools/index.ts` - Tool exports
- `src/tools/code-gen.test.ts` - Unit tests

**Verification:**
- Tool has valid Zod schema
- Tool can be invoked with test parameters
- Tool logs activity using logger from Plan 01-01
- Tool returns structured response

## Context

**Research reference:** `.planning/phases/01-core-agent-framework/01-RESEARCH.md`

**Key patterns from research:**
- Use Annotation API for state (current LangGraph.js pattern)
- Pin Zod to 3.25.67 (compatibility issues documented)
- Loop counter in state provides defense-in-depth beyond recursionLimit
- Tools use `@langchain/core/tools` with Zod schemas

**Why loop counter in state:** Research shows recursionLimit can be ignored in certain configurations (withConfig bug). Having an explicit loop counter in state provides a second layer of protection that we fully control.
