    This file provides:

    1. **`McpToolDeps` interface:**

    2. **`createMcpToolWrapper()` generic helper:**
       ```typescript
       import { z } from "zod";
       import type { ToolDefinition, ToolResult } from "../../agent-loop/types.js";
       import { callMcpTool } from "../../mcp/client.js";
       import { McpError } from "../../mcp/errors.js";
       import type { McpIntegration } from "../../mcp/types.js";

       export interface McpToolConfig {
         integration: McpIntegration;
         toolName: string;        // MCP tool name (e.g., "get_issue")
         displayName: string;     // Name exposed to LLM (can differ from toolName)
         description: string;
         inputSchema: z.ZodType;
       }

       export function createMcpToolWrapper(
         config: McpToolConfig,
         deps: McpToolDeps,
       ): ToolDefinition {
         return {
           name: config.displayName,
           description: config.description,
           inputSchema: config.inputSchema,
           async execute(input: unknown): Promise<ToolResult> {
             const parsed = config.inputSchema.safeParse(input);
             if (!parsed.success) {
               return { content: `Invalid input: ${parsed.error.message}`, isError: true };
             }

             try {
               const result = await callMcpTool({
                 integration: config.integration,
                 tool: config.toolName,
                 params: parsed.data as Record<string, unknown>,
                 agentId: deps.agentId,
                 correlationId: deps.correlationId,
               });
               return { content: JSON.stringify(result, null, 2) };
             } catch (error) {
               if (error instanceof McpError) {
                 return { content: `${config.displayName} error: ${error.message}`, isError: true };
               }
               const msg = error instanceof Error ? error.message : String(error);
               return { content: `${config.displayName} error: ${msg}`, isError: true };
             }
           },
         };
       }
       ```

    **Step 2: Create `linear-tools.ts`**

    Export a single factory function `createLinearTools(deps: McpToolDeps): ToolDefinition[]` that returns an array of 5 tools.

    Use `createMcpToolWrapper` for each. Define Zod schemas LOCALLY (do NOT import from `@aesir/integration-linear`).

    **5 Linear tools:**

    | Name | Tool Name | Input Schema |
    |------|-----------|-------------|
    | `linear_get_issue` | `get_issue` | `{ issueId: z.string() }` |
    | `linear_create_issue` | `create_issue` | `{ teamId: z.string(), title: z.string(), description?: z.string(), priority?: z.number(), labelIds?: z.string()[] }` |
    | `linear_update_issue_status` | `update_issue_status` | `{ issueId: z.string(), statusName: z.string() }` |
    | `linear_list_teams` | `list_teams` | `{}` (empty object) |
    | `linear_list_labels` | `list_labels` | `{ teamId: z.string() }` |

    IMPORTANT naming convention: Prefix with `linear_` to avoid name collisions with GitHub tools (e.g., both have concepts of "issues"). The `displayName` (shown to LLM) uses the prefix, while `toolName` (sent to MCP) uses the original name.

    Each tool needs a 2-3 sentence description explaining what it does and when to use it.

    For optional fields in Zod schemas: use `z.string().optional()` -- this is fine because `exactOptionalPropertyTypes` applies to our interfaces, not to Zod schema outputs which are plain objects.
