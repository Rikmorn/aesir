    **Step 1: Create `packages/agents/src/shared/tools/types.ts`**

    Shared dependency interfaces for tool factories:

    ```typescript
    import type { PinoLogger } from "@aesir/platform";
    import type { DevContainerManager } from "@aesir/platform";

    /** Maximum output bytes before truncation */
    export const MAX_OUTPUT_BYTES = 100_000;

    /** Dependencies for codebase tools (closed over at toolkit construction) */
    export interface CodebaseToolDeps {
      containerManager: DevContainerManager;
      taskId: string;
      logger: PinoLogger;
    }
    ```

    Note: Import `DevContainerManager` type from `@aesir/platform` (check the barrel export -- it may be exported from the sandbox module). If not directly exported, use: `import type { DevContainerManager } from "@aesir/platform/sandbox/dev-container.js"` or wherever it's re-exported. Check `packages/platform/src/index.ts` for the export path.

    **Step 2: Create each codebase tool factory**

    Each factory follows this pattern:
    - Takes `CodebaseToolDeps` parameter (closed-over at toolkit construction)
    - Returns `ToolDefinition` (imported from `../agent-loop/types.js` -- note the relative path from tools/ to agent-loop/)
    - Uses `z.object().safeParse()` for input validation (NOT `.parse()`)
    - Returns `{ content: string, isError: true }` for all errors (validation, execution, container not found)
    - Catches all exceptions in try/catch
    - Truncates output exceeding MAX_OUTPUT_BYTES with "[output truncated...]" message

    **read-file.ts:**
    - Name: `read_file`
    - Input: `{ path: string }` (file path relative to repo root)
    - Implementation: `containerManager.execute(taskId, { command: ["cat", path], workdir: "/workspace/repo", timeoutMs: 30_000 })`
    - On exitCode !== 0: return isError with stderr or "File not found"
    - Truncate stdout if > MAX_OUTPUT_BYTES
    - Description: 2-3 sentences explaining what it does, when to use it (understand existing code before changes)

    **write-file.ts:**
    - Name: `write_file`
    - Input: `{ path: string, content: string }`
    - Implementation:
      1. Create parent directories: `["mkdir", "-p", dir]` (extract dir from path)
      2. Write via base64 transport: `["sh", "-c", \`printf '%s' '${b64}' | base64 -d > '${path}'\`]`
      3. Use `Buffer.from(content).toString("base64")` for encoding
    - 30s timeout for each command
    - On success: return "Successfully wrote {path}"
    - IMPORTANT: The base64 approach avoids shell escaping issues with arbitrary file content. Use `printf '%s'` instead of `echo` to avoid trailing newline issues with the base64 string itself.
    - Description: Explain it overwrites existing files, creates parent dirs

    **search-codebase.ts:**
    - Name: `search_codebase`
    - Input: `{ pattern: string, glob?: string, path?: string }`
    - Implementation: Build ripgrep command array: `["rg", "--line-number", "--max-count", "50", "--no-heading"]` with optional `--glob` and path args
    - Handle exit code 1 (no matches, not an error) vs other non-zero (actual error)
    - Truncate output if > MAX_OUTPUT_BYTES
    - Description: Mention regex support, glob filtering, 50 match limit

    **list-directory.ts:**
    - Name: `list_directory`
    - Input: `{ path?: string }` (defaults to repo root ".")
    - Implementation: `["ls", "-la", path ?? "."]` with workdir `/workspace/repo`, 10s timeout
    - Truncate output if > MAX_OUTPUT_BYTES
    - Description: Lists files with details, defaults to repo root

    **run-command.ts:**
    - Name: `run_command`
    - Input: `{ command: string, timeoutMs?: number }`
    - Implementation: `["sh", "-c", command]` with configurable timeout (default 180_000 for tests)
    - Format output with exit code, TIMED OUT indicator, labeled STDOUT/STDERR sections
    - Set `isError: true` when exitCode !== 0
    - Truncate stdout at MAX_OUTPUT_BYTES and stderr at 50_000 bytes separately
    - Description: Explain it runs shell commands for tests, builds, installs

    - Use `import type` for type-only imports
    - Use `.js` extension in relative import paths (ESM convention in this project)
    - Do NOT import from `@aesir/integration-*` packages (agents must not depend on integration packages)
