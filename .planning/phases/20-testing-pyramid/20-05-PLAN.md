<task type="auto">
  <name>Task 1: Update root package.json with test commands</name>
  <files>package.json</files>
  <action>
Update root package.json to add test:fast and test:integration commands:

```json
{
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest",
    "test:fast": "vitest run --exclude='**/*.integration.test.ts' --exclude='**/*.e2e.test.ts' --exclude='**/sandbox/**/*.test.ts'",
    "test:integration": "vitest run --include='**/*.integration.test.ts'",
    "test:coverage": "vitest run --coverage"
  }
}
```

Command breakdown:
- `test` - Run all tests (default)
- `test:watch` - Watch mode for development
- `test:fast` - Unit tests only, excludes:
  - *.integration.test.ts (database/container tests)
  - *.e2e.test.ts (end-to-end tests)
  - **/sandbox/**/*.test.ts (Docker sandbox tests - these are slow)
- `test:integration` - Integration tests only (requires Docker)
- `test:coverage` - All tests with coverage report

CONTEXT.md decision: Sandbox/Docker tests are the slowest, explicitly excluded from test:fast.
  </action>
  <verify>
Run `pnpm test:fast` and verify it completes quickly (should be under 10s).
Run `pnpm test` and verify it runs all tests.
  </verify>
  <done>Test commands configured in root package.json</done>
</task>

Update root vitest.config.ts to set sensible defaults and document the project structure:

```typescript
import { defineConfig } from "vitest/config";

export default defineConfig({
  test: {
    // Projects mode for monorepo - each package has its own vitest.config.ts
    // Note: packages/integrations/* is covered by packages/*
    projects: [
      "packages/*",
      "packages/integrations/*",
      "packages/test-utils",
    ],

    // Default test timeout (longer for integration tests)
    testTimeout: 10000,

    // Coverage configuration (must be at root level for monorepo)
    coverage: {
      provider: "v8",
      enabled: false, // Enable via --coverage flag
      reportsDirectory: "./coverage",
      reporter: ["text", "html", "lcov"],

      // Per-package thresholds
      thresholds: {
        // Core packages: 70% coverage target
        "packages/common/**": {
          lines: 70,
          functions: 70,
          branches: 70,
          statements: 70,
        },
        "packages/platform/**": {
          lines: 70,
          functions: 70,
          branches: 70,
          statements: 70,
        },
        "packages/observability/**": {
          lines: 70,
          functions: 70,
          branches: 70,
          statements: 70,
        },
        // Integration packages: 50% coverage target (API wrappers harder to test)
        "packages/integrations/**": {
          lines: 50,
          functions: 50,
          branches: 50,
          statements: 50,
        },
        "packages/agents/**": {
          lines: 50,
          functions: 50,
          branches: 50,
          statements: 50,
        },
      },

      // Exclusions from coverage
      exclude: [
        "**/node_modules/**",
        "**/dist/**",
        "**/*.test.ts",
        "**/*.integration.test.ts",
        "**/*.e2e.test.ts",
        "**/db/migrations/**",
        "**/db/scripts/**",
        "**/scripts/**",
        "**/main.ts",
        "**/types.ts",
        "**/schemas.ts",
        "**/_legacy/**",
        "**/test-utils/**", // Test utilities shouldn't count toward coverage
      ],
    },
  },
});
```

Key points:
- Projects array includes nested integration packages
- Coverage thresholds are per-package type (CONTEXT.md decision)
- Exclusions cover migrations, scripts, types, and legacy code
