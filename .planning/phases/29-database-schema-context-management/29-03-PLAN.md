<objective>
Create the context manager and task store services for persisting semantic context snapshots and structured task state to the agents PostgreSQL schema.

Purpose: These services enable agents to persist semantic context across Temporal activity boundaries (CTXM-01 through CTXM-04) and maintain structured task state throughout the workflow (CTXM-02). The context manager writes LLM-generated summaries + programmatic data at the end of each activity and reads them at the start of the next. The task store maintains critical structured data (status, branch, PR, approval) in typed columns.

Scope note on CTXM-05: Sub-agent context briefing is intentionally NOT in this plan's scope. Per 29-RESEARCH.md, sub-agent briefs are ephemeral and in-memory only -- the orchestrator constructs a brief string from its own context and passes it via runAgentLoop()'s context option. No database persistence is needed. Phase 30/31 will define the brief construction logic when building the orchestrator.

Output: createContextManager() and createTaskStore() factory functions with comprehensive tests.
</objective>

**Interfaces:**

```typescript
import type { PinoLogger } from "@aesir/platform";
import type { NodePgDatabase } from "drizzle-orm/node-postgres";

interface ContextManagerOptions {
  db: NodePgDatabase<typeof import("./schema.js")>;
  logger: PinoLogger;
}

interface WriteSnapshotParams {
  taskId: string;
  workflowId: string;
  agentType: string;
  stage: string;
  summary: string;
  completedActions?: string[];
  pendingIntent?: string;
  knownIssues?: string[];
  projectContext?: Record<string, unknown>;
  keyFiles?: string[];
  researchFindings?: unknown;
  plan?: unknown;
  toolCallCount: number;
  tokenCount: { input: number; output: number };
}

interface ContextManager {
  /** Write a context snapshot at end of activity */
  writeSnapshot(params: WriteSnapshotParams): Promise<string>;
  /** Read the latest snapshot for a task+workflow combination */
  readLatestSnapshot(taskId: string, workflowId: string): Promise<ContextSnapshot | null>;
  /** Read the latest snapshot for a specific stage */
  readLatestSnapshotForStage(taskId: string, stage: string): Promise<ContextSnapshot | null>;
  /** Health check */
  health(): Promise<{ healthy: boolean; latencyMs: number }>;
  /** Graceful shutdown */
  close(): Promise<void>;
}
```

Export all interfaces and the factory function.

**Factory implementation:**

`createContextManager(options: ContextManagerOptions): ContextManager`

1. Validate required options (db, logger). Throw if missing.
2. Create a child logger: `logger.child({ component: "context-manager" })`

3. **writeSnapshot(params)**:
   - Validate required fields: taskId, workflowId, agentType, stage, summary. Throw on missing.
   - Insert into `contextSnapshots` table using `db.insert(contextSnapshots).values({...}).returning({ id: contextSnapshots.id })`
   - Map params to column names (camelCase to snake_case via Drizzle column definitions)
   - Return the generated snapshot ID
   - Log success at info level: `{ snapshotId, taskId, stage }, "Context snapshot written"`

4. **readLatestSnapshot(taskId, workflowId)**:
   - Query `contextSnapshots` table with:
     ```typescript
     db.select().from(contextSnapshots)
       .where(and(
         eq(contextSnapshots.task_id, taskId),
         eq(contextSnapshots.workflow_id, workflowId),
       ))
       .orderBy(desc(contextSnapshots.created_at))
       .limit(1)
     ```
   - Return the first result or null
   - Import `and`, `eq`, `desc` from `drizzle-orm`

5. **readLatestSnapshotForStage(taskId, stage)**:
   - Same as readLatestSnapshot but filter on task_id + stage instead of task_id + workflow_id:
     ```typescript
     .where(and(
       eq(contextSnapshots.task_id, taskId),
       eq(contextSnapshots.stage, stage),
     ))
     ```

6. **health()**:
   - Execute `SELECT 1` via raw SQL or a simple count query
   - Time the round-trip
   - Return `{ healthy: true, latencyMs }` on success, `{ healthy: false, latencyMs: -1 }` on error

7. **close()**: No-op for now (pool is managed by client.ts). Log that close was called.

```typescript
interface TaskStoreOptions {
  db: NodePgDatabase<typeof import("./schema.js")>;
  logger: PinoLogger;
}

interface CreateTaskParams {
  taskId: string;
  agentType: string;
  issueId?: string;
  issueIdentifier?: string;
  workflowId?: string;
  slackChannel?: string;
  slackMessageTs?: string;
}

/** Fields that can be updated on an existing task */
interface TaskUpdate {
  status: "pending" | "researching" | "planning" | "approved" | "executing" | "complete" | "failed";
  workflowId: string;
  containerId: string;
  branchName: string;
  prNumber: number;
  prUrl: string;
  approvalStatus: "pending" | "approved" | "rejected";
  approvalFeedback: string;
  error: string;
  escalationReason: string;
  slackChannel: string;
  slackMessageTs: string;
}

interface TaskStore {
  /** Create a new task record */
  createTask(params: CreateTaskParams): Promise<string>;
  /** Update specific fields of an existing task */
  updateTask(taskId: string, updates: Partial<TaskUpdate>): Promise<void>;
  /** Get a task by its external task_id */
  getTask(taskId: string): Promise<AgentTask | null>;
  /** Get a task by workflow_id */
  getTaskByWorkflowId(workflowId: string): Promise<AgentTask | null>;
  /** Health check */
  health(): Promise<{ healthy: boolean; latencyMs: number }>;
  /** Graceful shutdown */
  close(): Promise<void>;
}
```

Export all interfaces and the factory function.

**Factory implementation:**

`createTaskStore(options: TaskStoreOptions): TaskStore`

1. Validate required options (db, logger). Throw if missing.
2. Create child logger: `logger.child({ component: "task-store" })`

3. **createTask(params)**:
   - Validate required: taskId, agentType. Throw on missing.
   - Insert into `tasks` table, mapping camelCase params to snake_case columns:
     - task_id: params.taskId
     - agent_type: params.agentType
     - issue_id: params.issueId
     - issue_identifier: params.issueIdentifier
     - workflow_id: params.workflowId
     - slack_channel: params.slackChannel
     - slack_message_ts: params.slackMessageTs
   - Use `.returning({ id: tasks.id })` to get the generated ID
   - Return the generated task ID
   - Log at info level: `{ id, taskId }, "Task created"`

4. **updateTask(taskId, updates)**:
   - Map camelCase update keys to snake_case columns:
     - status -> status
     - workflowId -> workflow_id
     - containerId -> container_id
     - branchName -> branch_name
     - prNumber -> pr_number
     - prUrl -> pr_url
     - approvalStatus -> approval_status
     - approvalFeedback -> approval_feedback
     - error -> error
     - escalationReason -> escalation_reason
     - slackChannel -> slack_channel
     - slackMessageTs -> slack_message_ts
   - Build update object only with provided fields (skip undefined values)
   - `db.update(tasks).set(mappedUpdates).where(eq(tasks.task_id, taskId))`
   - Log at info level: `{ taskId, fields: Object.keys(updates) }, "Task updated"`

5. **getTask(taskId)**:
   - `db.select().from(tasks).where(eq(tasks.task_id, taskId)).limit(1)`
   - Return first result or null

6. **getTaskByWorkflowId(workflowId)**:
   - `db.select().from(tasks).where(eq(tasks.workflow_id, workflowId)).limit(1)`
   - Return first result or null

7. **health()**: Same pattern as context manager.

8. **close()**: No-op, log close called.
