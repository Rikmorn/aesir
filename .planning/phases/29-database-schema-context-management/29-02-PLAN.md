Create `packages/agents/src/shared/db/trace-recorder.ts` following the dependency injection factory pattern from `packages/observability/src/services/execution-tracker.ts`.

**Interface definitions:**

```typescript
import type { PinoLogger } from "@aesir/platform";
import type { NodePgDatabase } from "drizzle-orm/node-postgres";
import type { ToolCallInfo, LLMResponse } from "../agent-loop/types.js";
import type * as agentsSchemaModule from "./schema.js";

interface TraceRecorderOptions {
  db: NodePgDatabase<typeof agentsSchemaModule>;
  logger: PinoLogger;
  taskId: string;
  workflowId: string;
  agentType: string;
  agentInstanceId: string;
  parentAgentInstanceId?: string;
}

interface TraceRecorderCallbacks {
  /** Pass to runAgentLoop() options.onToolCall */
  onToolCall: (call: ToolCallInfo) => void;
  /** Pass to runAgentLoop() options.onResponse */
  onResponse: (response: LLMResponse) => void;
  /** Record a sub-agent spawn event */
  onAgentSpawn: (childInstanceId: string, childType: string, brief: unknown) => void;
  /** Record agent completion */
  onAgentComplete: (result: unknown) => void;
  /** Flush all buffered trace steps to the database. Call at end of activity. */
  flush: () => Promise<void>;
  /** Get the current step count (for testing/debugging) */
  stepCount: () => number;
}
```

Export both interfaces and the factory function.

**Factory implementation:**

`createTraceRecorder(options: TraceRecorderOptions): TraceRecorderCallbacks`

1. Validate required options (db, logger, taskId, workflowId, agentType, agentInstanceId). Throw if missing.

2. Maintain internal state:
   - `buffer: NewExecutionTrace[]` -- in-memory buffer of trace steps not yet written to DB
   - `stepCounter: number` -- auto-incrementing step number per agent instance, starts at 0

3. **onToolCall callback** (synchronous, does NOT await):
   - Increment stepCounter
   - Create a `NewExecutionTrace` record:
     - id: use `createId.executionTrace()`
     - task_id: from options
     - workflow_id: from options
     - agent_type: from options
     - agent_instance_id: from options
     - parent_agent_instance_id: from options (may be undefined)
     - step_number: stepCounter
     - type: `"tool_call"`
     - tool_name: `call.name`
     - input: truncate `call.input` to 10KB JSON string length (see truncation below)
     - output: null (tool result comes later via a separate callback or we skip it -- see note)
     - token_count_input: null (tools don't have token counts)
     - token_count_output: null
     - duration_ms: null (we don't time individual tool calls in this version)
   - Push to buffer

   **Note on tool_result:** The Phase 28 callbacks (`onToolCall`, `onResponse`) do not include a tool_result callback. The tool result is part of the conversation history but not surfaced via a callback. For v2.2, record tool_call and llm_response steps only. Tool results can be added later if needed by extending `runAgentLoop()` with an `onToolResult` callback. This is sufficient for TRAC-02 because the LLM response contains all the information about what the tool produced (the LLM sees the result and reasons about it).

4. **onResponse callback** (synchronous, does NOT await):
   - Increment stepCounter
   - Extract from `response` (Anthropic.Message):
     - `token_count_input`: `response.usage.input_tokens`
     - `token_count_output`: `response.usage.output_tokens`
     - `stop_reason`: `response.stop_reason`
   - Extract text output: find content blocks with `type === "text"` and join their text
   - Create a `NewExecutionTrace` record:
     - type: `"llm_response"`
     - tool_name: null
     - input: null
     - output: truncate text output to 10KB
     - token_count_input: from usage
     - token_count_output: from usage
     - duration_ms: null (we don't time individual LLM calls in this callback -- timing is recorded in TraceStep by the loop itself)
   - Push to buffer

5. **onAgentSpawn** (synchronous):
   - Increment stepCounter
   - Create record with type `"agent_spawn"`, tool_name: childType, input: truncated brief, output: null
   - Push to buffer

6. **onAgentComplete** (synchronous):
   - Increment stepCounter
   - Create record with type `"agent_complete"`, tool_name: null, input: null, output: truncated result
   - Push to buffer

7. **flush** (async):
   - If buffer is empty, return immediately
   - Batch insert all buffered records into `executionTraces` table
   - Use `db.insert(executionTraces).values(buffer)` for a single batch insert
   - Wrap in try/catch: on error, log the error but do NOT re-throw (best-effort persistence -- the agent loop should not fail because of trace recording issues)
   - Clear the buffer after attempt (whether success or failure)
   - Log the number of steps flushed on success

8. **stepCount**: Return current stepCounter value.

**Truncation helper:**

Create an internal `truncateJsonPayload(value: unknown, maxBytes: number = 10240): unknown` function:
- If value is a string and length > maxBytes: return `value.slice(0, maxBytes) + " [truncated]"`
- If value is an object: `JSON.stringify(value)`, check length. If > maxBytes, return `{ _truncated: true, preview: JSON.stringify(value).slice(0, maxBytes) }`
- If value is null/undefined: return value as-is
- For primitives (number, boolean): return as-is

**IMPORTANT:** The `onToolCall` and `onResponse` callbacks MUST be synchronous (void return). They MUST NOT await database writes. All writes are buffered in memory and flushed via the explicit `flush()` call. This prevents trace recording from blocking the agent loop (Pitfall 2 from research).

**IMPORTANT:** For the `db` type parameter, use `NodePgDatabase<typeof import("./schema.js")>` or equivalent. Check how the existing codebase types the Drizzle database instance and follow the same pattern. The key is that schema-aware queries like `db.insert(executionTraces)` work with type safety.
