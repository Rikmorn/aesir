    **1. Create `packages/agents/src/service/api/event-buffer.ts`:**

    A bounded circular buffer for SSE Last-Event-ID replay support.

    ```
    interface BufferedEvent {
      id: string;        // String sequence ID used as SSE event id
      sequence: number;  // Numeric sequence for ordering
      type: string;      // Event type (e.g., "tool.called")
      conversationId: string;
      data: unknown;     // Full event payload
    }

    interface EventBuffer {
      push(event: BufferedEvent): void;
      getAfter(sequence: number): BufferedEvent[];
      getOldestSequence(): number | null;
      size(): number;
    }

    function createEventBuffer(maxSize: number = 1000): EventBuffer
    ```

    Implementation:
    - Use an array as a circular buffer with a head pointer (or simpler: use an array and `shift()` when exceeding maxSize -- at 1000 items this is efficient enough).
    - `push()`: Append event. If buffer exceeds maxSize, remove oldest (shift).
    - `getAfter(sequence)`: Return all events with `sequence > afterSequence`, in order.
    - `getOldestSequence()`: Return the sequence of the oldest buffered event, or null if empty.
    - `size()`: Return current buffer length.

    Keep it simple. No need for fancy ring buffer -- array operations on 1000 items are sub-millisecond.

    **2. Create `packages/agents/src/service/api/sse-events.ts`:**

    This is the most complex handler. It manages SSE connections, bridges EventLog.subscribe(), and handles all the SSE protocol concerns.

    **Connection Manager (exported for shutdown access):**

    ```
    interface SseConnectionManager {
      getConnectionCount(): number;
      closeAll(): void;
    }
    ```

    The connection manager tracks all active SSE Response objects in a Set and provides `closeAll()` for graceful shutdown.

    **Factory function:**

    ```
    interface SseEventsRouterOptions {
      eventLog: EventLog;
      logger: PinoLogger;
      maxConnections?: number;      // default 50
      keepaliveIntervalMs?: number; // default 20_000
      bufferSize?: number;          // default 1000
    }

    function createSseEventsRouter(options: SseEventsRouterOptions): {
      router: Router;
      manager: SseConnectionManager;
    }
    ```

    Returns both the Express Router and the connection manager (main.ts needs the manager for shutdown).

    **GET / handler implementation:**

    1. **Connection limit check:**
       - If `connections.size >= maxConnections`, return 429 with `sendApiError(res, 429, "TOO_MANY_CONNECTIONS", "Maximum SSE connections reached")`.

    2. **Parse query params:**
       - `conversationId` (optional string): filter events to this conversation
       - `types` (optional comma-separated string): filter events to these types. Validate each type against the known 9 agent event types using Zod enum. If invalid, return 400 VALIDATION_ERROR.
       - Use Zod for validation:
         ```
         const querySchema = z.object({
           conversationId: z.string().optional(),
           types: z.string().optional(),
         });
         ```
       - Parse types string: `types ? types.split(",").map(t => t.trim()) : undefined`
       - Validate each type is a valid AgentEventType (import `agentEventTypeValues` from framework types).

    3. **Set SSE headers:**
       ```
       res.writeHead(200, {
         "Content-Type": "text/event-stream",
         "Cache-Control": "no-cache",
         "Connection": "keep-alive",
         "X-Accel-Buffering": "no",
       });
       res.flushHeaders();
       ```

    4. **Send retry interval:**
       - `res.write("retry: 3000\n\n");`

    5. **Handle Last-Event-ID replay:**
       - Read `req.headers["last-event-id"]`
       - If present, parse as integer
       - Call `eventBuffer.getAfter(lastSeq)` to get missed events
       - If `lastSeq` is older than `eventBuffer.getOldestSequence()`, send a gap event first:
         `res.write('event: gap\ndata: {"reason":"Events expired from buffer, consider full refresh"}\n\n');`
       - Replay all buffered events matching the client's filters (conversationId, types)

    6. **Subscribe to EventLog:**
       - Call `eventLog.subscribe(subscriptionFilter, handler)` where:
         - `subscriptionFilter.types` = the parsed types array (or undefined for all)
         - `handler` = async function that:
           a. Checks conversationId filter (EventLog subscribe only filters by type, not conversation). If `conversationId` is set and `event.conversation_id !== conversationId`, skip.
           b. Pushes the event to the shared EventBuffer (for future reconnections)
           c. Writes the SSE event to this client's response:
              ```
              res.write(`id: ${event.sequence}\n`);
              res.write(`event: ${event.type}\n`);
              res.write(`data: ${JSON.stringify(eventPayload)}\n\n`);
              ```
           d. The `eventPayload` should include: `{ id: event.id, conversationId: event.conversation_id, agentDefinitionId: event.agent_definition_id, type: event.type, payload: event.payload, sequence: event.sequence, timestamp: event.timestamp, tokenCountInput: event.token_count_input, tokenCountOutput: event.token_count_output, durationMs: event.duration_ms }`
       - Store the returned `unsubscribe` function.

    IMPORTANT: The EventLog subscriber receives ALL events (or type-filtered events). The conversationId filter must be applied in the handler, not in the EventLog subscribe call. The EventBuffer is shared across all connections -- push events to it from a single global subscriber, not per-connection. Use a pattern like:
    - Create ONE global EventLog subscription that pushes all events to the EventBuffer
    - Per-connection handlers read from their own EventLog subscription (with type filter) and apply conversationId filter in the handler

    Actually, simpler approach: each SSE connection creates its own EventLog subscription. The EventBuffer is populated by a separate global subscription created once when the first SSE connection is established (or at router creation time). This way:
    - Global subscription -> pushes to EventBuffer (for replay)
    - Per-connection subscription -> writes SSE events (with conversationId filter in handler)

    7. **Keepalive ping:**
       - Start `setInterval(() => res.write(": ping\n\n"), keepaliveIntervalMs)`
       - Store the interval ID for cleanup.

    8. **Track connection:**
       - Add `res` to the connections Set.

    9. **Cleanup on disconnect:**
       - `req.on("close", () => { ... })`:
         a. Call `unsubscribe()` (the per-connection EventLog unsubscribe)
         b. Clear the keepalive interval
         c. Remove `res` from the connections Set
         d. Log at debug level

    10. **Connection manager:**
        - `getConnectionCount()`: return `connections.size`
        - `closeAll()`: iterate connections Set, call `res.end()` on each, clear the Set. Also unsubscribe the global EventBuffer subscription and clear the keepalive intervals.

    IMPORTANT anti-patterns to avoid:
    - Do NOT call `res.write()` after `req.on("close")` has fired -- check a `closed` flag
    - Do NOT forget to call the EventLog unsubscribe function -- this causes memory leaks
    - Do NOT use `res.json()` or `res.send()` -- SSE uses raw `res.write()`
    - Do NOT forget `res.flushHeaders()` -- without it Express buffers the response
    - Do NOT forget `X-Accel-Buffering: no` header -- without it nginx buffers SSE
