    **1. Create `packages/agents/src/service/api/types.ts`:**

    Define all API response types used across the six endpoints:

    - `ApiError` -- `{ error: { code: string; message: string; details?: unknown[] } }`
    - Error code constants: `NOT_FOUND`, `VALIDATION_ERROR`, `TOO_MANY_CONNECTIONS`, `INTERNAL_ERROR`
    - `ToolRegistryEntry` -- `{ name: string; namespace: string; description: string; inputSchema: Record<string, unknown> }`
    - `AgentRegistrySummary` -- AgentDefinition fields WITHOUT `systemPrompt` (id, name, description, version, model, temperature, tools, subAgents, maxIterations, tokenBudget, history, triggers)
    - `AgentRegistryDetail` -- extends AgentRegistrySummary with `systemPrompt: string`
    - `WorkerStatusResponse` -- `{ activeClaims: number; maxConcurrent: number; pollIntervalMs: number; lastPollAt: string | null; uptimeMs: number }`
    - `IntegrationHealth` -- `{ name: string; status: "healthy" | "unhealthy"; latencyMs: number | null; lastChecked: string }`
    - `ToolsHealthResponse` -- `{ integrations: IntegrationHealth[] }`

    **2. Create `packages/agents/src/service/api/middleware.ts`:**

    - `sendApiError(res, status, code, message, details?)` -- sends the standard error envelope as JSON
    - `validateParams(schema: ZodType, params: unknown)` -- parses params with Zod, returns `{ success: true, data } | { success: false, error: ZodError }`. Do NOT use Express middleware pattern (no req, res, next) -- keep it as a pure function that callers use in their handlers.
    - `asyncHandler(fn)` -- wraps async Express route handlers to catch errors and send INTERNAL_ERROR envelope. Pattern: `(req, res, next) => fn(req, res, next).catch(err => { logger.error(...); sendApiError(res, 500, 'INTERNAL_ERROR', 'Internal server error') })`. Takes a logger parameter.

    - In the `createWorkerLoop()` closure, track `startedAt: Date | null` (set when `start()` is called) and `lastPollAt: Date | null` (set at the beginning of each `poll()` call)
    - Implement `getStatus()` returning: `{ activeClaims: running.size, maxConcurrent: concurrencyLimit, pollIntervalMs, lastPollAt, uptimeMs: startedAt ? Date.now() - startedAt.getTime() : 0, isRunning: started && !draining }`
    - Export `WorkerLoopStatus` type from the module

  <action>
    Each endpoint follows the factory pattern: export a function that takes dependencies and returns an Express Router.

    **1. `tools-registry.ts` -- `createToolsRegistryRouter({ toolRegistry, logger })`:**

    `GET /` handler:
    - Get all registered tool refs via `toolRegistry.listRegistered()`
    - For each ref, resolve with an inspection context to get the ToolDefinition. The inspection context is a minimal ToolContext: `{ agentId: "__inspection__", correlationId: "__inspection__", logger: logger.child({ component: "api-tools-registry" }) }`. This is safe because we only read metadata (name, description, inputSchema) and never call `execute()`.
    - Use `zodToJsonSchema()` from the `zod-to-json-schema` package (already in the project) to convert each tool's `inputSchema` (Zod type) to JSON Schema.
    - Parse the ref string to extract namespace (part before colon) and name (part after colon).
    - Return JSON array of `ToolRegistryEntry[]` sorted by namespace then name.
    - Cache the result on first call (tool registrations don't change at runtime). Use a module-level `let cache: ToolRegistryEntry[] | null = null`.
    - Wrap in asyncHandler for error handling.

    IMPORTANT: The tool factories for codebase tools expect `containerManager` and `taskId` in context. When those are undefined, the factory still returns a ToolDefinition object (it just fails on `execute()`). Since we only read metadata, this is fine. However, if a factory throws, catch the error and fall back to just `{ name, namespace, description: "Unable to load", inputSchema: {} }`.

    **2. `tools-health.ts` -- `createToolsHealthRouter({ config, logger })`:**

    The `config` parameter should be the relevant MCP URLs. Define an options interface:
    ```
    interface ToolsHealthRouterOptions {
      integrations: Array<{ name: string; healthUrl: string }>;
      logger: PinoLogger;
      cacheTtlMs?: number; // default 30_000
      timeoutMs?: number;  // default 3000
    }
    ```

    `GET /` handler:
    - Check cache: if `cache` exists and `Date.now() - cache.fetchedAt < cacheTtlMs`, return cached data.
    - Otherwise, fetch all integration health endpoints in parallel using `Promise.allSettled()` (not `Promise.all()` -- one failure must not block others).
    - Each fetch uses `AbortSignal.timeout(timeoutMs)` for the 3-second timeout.
    - For each integration: if fetch succeeds and `response.ok`, return `{ name, status: "healthy", latencyMs, lastChecked }`. Otherwise return `{ name, status: "unhealthy", latencyMs: null, lastChecked }`. Log errors at warn level (details stay in logs per CONTEXT.md decision).
    - Cache the result.
    - Return `{ integrations: IntegrationHealth[] }`.

    **3. `agents-registry.ts` -- `createAgentsRegistryRouter({ agentRegistry, logger })`:**

    Two routes on the same Router:

    `GET /` (list):
    - Call `agentRegistry.list()` to get all `AgentDefinition[]`.
    - Map each to `AgentRegistrySummary` by destructuring and omitting `systemPrompt`. Use `const { systemPrompt, ...summary } = definition;` pattern.
    - Return JSON array sorted by `id`.

    `GET /:id` (detail):
    - Validate `:id` param with Zod: `z.string().min(1).regex(/^[a-z0-9-]+$/)`. If invalid, return 400 VALIDATION_ERROR via `sendApiError`.
    - Call `agentRegistry.get(id)`.
    - If null, return 404 NOT_FOUND via `sendApiError`.
    - Return the full `AgentRegistryDetail` (including systemPrompt).

    **4. `worker-status.ts` -- `createWorkerStatusRouter({ getWorkerStatus, logger })`:**

    Options interface:
    ```
    interface WorkerStatusRouterOptions {
      getWorkerStatus: () => WorkerLoopStatus | null;
      logger: PinoLogger;
    }
    ```

    `GET /` handler:
    - Call `getWorkerStatus()`.
    - If null (worker not started), return `{ activeClaims: 0, maxConcurrent: 0, pollIntervalMs: 0, lastPollAt: null, uptimeMs: 0 }`.
    - Otherwise map to `WorkerStatusResponse`: convert `lastPollAt` Date to ISO string (or null), pass through numeric fields.
    - Return JSON object.
  </action>
