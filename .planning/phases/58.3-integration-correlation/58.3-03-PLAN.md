  <action>
    **MCP handler (mcp.ts) -- outgoing recording:**

    1. Extract `X-Task-ID` header:
       ```typescript
       const taskId = req.headers["x-task-id"] as string | undefined;
       ```
       Add to requestLogger child bindings.

    2. Pass taskId into MCPToolContext:
       ```typescript
       const context: MCPToolContext = {
         logger: requestLogger,
         correlationId,
         agentId,
         startTime,
         taskId,
       };
       ```

    3. After each correlatable tool handler returns successfully, record correlation. The correlatable tools are:

       - `create_branch`: Record as `("branch", "{owner}/{repo}:{branchName}")`. Extract owner/repo/branchName from `req.body` (the input args). The branch name is in `args.branchName`, owner in `args.owner`, repo in `args.repo`.
       - `create_commit`: Record as `("commit", commitSha)`. Extract SHA from `result.structuredContent.sha` (the CreateCommitOutput has a sha field from the GitHub API). If structuredContent not available, check result.data.
       - `create_pull_request`: Record as `("pull_request", "{owner}/{repo}#{prNumber}")`. Extract from result structuredContent: owner/repo from args, prNumber from result.

       Pattern:
       ```typescript
       case "create_pull_request":
         result = await handleCreatePR(context, args, prDeps);
         if (!result.isError) {
           const data = result.structuredContent as { number?: number } | undefined;
           if (data?.number) {
             const ref = `${args.owner}/${args.repo}#${data.number}`;
             recordTaskCorrelation(db, taskId, "pull_request", ref, requestLogger)
               .catch(() => {});
           }
         }
         break;
       ```

    4. Do NOT record correlations for read-only operations (get_repository, get_pull_request, list_pull_requests, get_file_contents, list_files) or merge_pull_request (the PR was already correlated at creation time).

    5. Import `recordTaskCorrelation` from `../db/task-correlations.js`.

    **Webhook handler (webhooks.ts) -- incoming lookup:**

    1. Import `lookupTaskCorrelation` from `../db/task-correlations.js`.

    2. The webhook router needs a `db` dependency. Add `db: NodePgDatabase` to the `WebhookRouterDeps` interface.

    3. For **pull_request_review** events:
       - After parsing the payload, before normalizing:
       - Construct the PR ref: `${payload.repository.owner.login}/${payload.repository.name}#${payload.pull_request.number}`
       - Look up: `lookupTaskCorrelation(db, "pull_request", ref, childLogger)`
       - If taskId found, inject into normalizedEvent payload as `taskId` field

    4. For **pull_request** events (action === "closed"):
       - After parsing prPayload, before normalizing:
       - Construct PR ref: `${prPayload.repository.owner.login}/${prPayload.repository.name}#${prPayload.pull_request.number}`
       - Look up: `lookupTaskCorrelation(db, "pull_request", ref, childLogger)`
       - If taskId found, inject into normalizedEvent payload

    5. The lookups use the **anchor entity** (pull_request) only, per user decision. Branch and commit correlations are write-only for observability.

    **Adapter (packages/agents/src/adapters/github.ts):**

    6. In each case that produces an IncomingEvent, extract `taskId` from the NormalizedEvent payload if present and include it:
       ```typescript
       const taskId = payload.taskId as string | undefined;
       return {
         type: "...",
         ...(taskId && { taskId }),
         // ... other fields
       };
       ```
       Apply to: `github.pull_request.merged`, `github.pull_request.closed`, and all `github.pull_request.review_*` cases.
  </action>
