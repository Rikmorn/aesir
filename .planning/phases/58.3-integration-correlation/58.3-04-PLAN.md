  <action>
    **MCP handler (mcp.ts) -- outgoing recording:**

    1. Extract `X-Task-ID` header:
       ```typescript
       const taskId = req.headers["x-task-id"] as string | undefined;
       ```
       Add to requestLogger child bindings.

    2. The Slack MCP handler currently uses `_db` (unused db parameter). Rename it to `db` since we now need it for correlation recording.

    3. After each correlatable tool returns successfully, record correlation. The Slack reference format uses `channelId:ts` per CONTEXT.md.

       **send_message** (both new thread and thread reply):
       - After `sendMessage` returns `sendResult`, record:
         - If `input.threadTs` is defined (thread reply): `("thread", "${input.channel}:${input.threadTs}")`
         - If `input.threadTs` is undefined (new message): `("thread", "${sendResult.channel}:${sendResult.ts}")`
       - The external_ref for threads is always `channelId:threadTs`. For new messages, the message ts IS the thread ts.

       **reply_to_thread**:
       - After `sendMessage` returns `replyResult`: `("thread", "${input.channel}:${input.threadTs}")`
       - Uses the parent thread ts, not the reply ts.

       **send_approval_request**:
       - After `sendApprovalRequest` returns `approvalResult`: `("approval", "${approvalResult.channel}:${approvalResult.ts}")`
       - The approval message ts is the identifier for button click lookups.

       **send_escalation_request**:
       - After `sendEscalationRequest` returns: `("approval", "${escalationResult.channel}:${escalationResult.ts}")`
       - Escalation buttons use the same lookup pattern as approvals.

       Pattern:
       ```typescript
       case "send_message": {
         // ... existing validation and sendMessage call ...
         recordTaskCorrelation(
           db, taskId, "thread",
           input.threadTs
             ? `${input.channel}:${input.threadTs}`
             : `${sendResult.channel}:${sendResult.ts}`,
           requestLogger,
         ).catch(() => {});
         // ... rest of case ...
       }
       ```

    4. Do NOT record correlations for read-only operations (get_message, list_channels, update_message).

    5. Import `recordTaskCorrelation` from `../db/task-correlations.js`.

    **Events handler (events.ts) -- incoming lookup for thread replies:**

    1. Import `lookupTaskCorrelation` from `../db/task-correlations.js`.

    2. Add `db: NodePgDatabase` to the `EventsRouterDeps` interface.

    3. After the eventHandler processes a non-null, non-error event (at the `normalizeSlackEvent` call), if the event is a thread reply (has `threadTs` in the result):
       - Look up: `lookupTaskCorrelation(db, "thread", "${result.value.channel}:${result.value.threadTs}", childLogger)`
       - If the result.value has a `threadTs` field (indicating it's a thread reply), do the lookup
       - If taskId found, inject into the normalizedEvent payload as `taskId`

       Place this between `normalizeSlackEvent(result.value)` and `dispatcher.dispatch(normalizedEvent)`:
       ```typescript
       if (normalizedEvent && result.value.threadTs) {
         const taskId = await lookupTaskCorrelation(
           db, "thread",
           `${result.value.channel}:${result.value.threadTs}`,
           childLogger,
         );
         if (taskId) {
           (normalizedEvent.payload as Record<string, unknown>).taskId = taskId;
         }
       }
       ```

    **Interactions handler (interactions.ts) -- incoming lookup for approval clicks:**

    1. Import `lookupTaskCorrelation` from `../db/task-correlations.js`.

    2. Add `db: NodePgDatabase` to the `InteractionsRouterDeps` interface.

    3. After parsing the action (Step 4, after parseActionId succeeds), before constructing normalizedEvent:
       - Look up: `lookupTaskCorrelation(db, "approval", "${channelId}:${messageTs}", childLogger)`
       - If taskId found, inject into the normalizedEvent payload:
         ```typescript
         const lookupTaskId = await lookupTaskCorrelation(
           db, "approval", `${channelId}:${messageTs}`, childLogger,
         );
         ```
       - Add to normalizedEvent.payload: `...(lookupTaskId && { taskId: lookupTaskId })`

    **Adapter (packages/agents/src/adapters/slack.ts):**

    4. In each case that produces an IncomingEvent, extract `taskId` from the NormalizedEvent payload if present:
       ```typescript
       const taskId = payload.taskId as string | undefined;
       return {
         type: "...",
         ...(taskId && { taskId }),
         // ... other fields
       };
       ```
       Apply to: `slack.block_actions.approved`, `slack.block_actions.rejected`, `slack.block_actions.escalation_retry`, `slack.block_actions.escalation_abort`, `slack.message.created` (thread reply case), and `slack.app_mention.created`.
