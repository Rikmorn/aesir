**types.ts** -- Add two new types after the existing EventRouterDeps interface (keep ALL existing types, do not remove anything):

```typescript
/**
 * Dependencies for the v2.3 adapted routeEvent() function.
 * RouteEventDeps is a superset of EventRouterDeps: includes the
 * EventRouter itself (pre-initialized with loadStartRules() called).
 *
 * TypeScript structural typing means RouteEventDeps satisfies
 * EventRouterDeps -- can pass directly to routeViaAgentLoopV2().
 */
export interface RouteEventDeps {
  /** ConversationExecutor for start/signal operations */
  executor: ConversationExecutor;
  /** EventRouter for routing decisions (must have loadStartRules() called) */
  eventRouter: EventRouter;
  /** Pino logger instance */
  logger: PinoLogger;
  /** Slack channel ID for routing failure alerts (optional) */
  alertsChannel?: string | undefined;
  /** Linear team ID for product-agent starts (optional) */
  linearTeamId?: string | undefined;
}

/**
 * Result returned by routeEvent(). Used as HTTP response body.
 * Unified 200 for all paths -- webhook callers just need ack.
 */
export interface RouteEventResult {
  /** Always true -- event was received */
  received: true;
  /** What happened */
  action: "started" | "signaled" | "classifying" | "ignored" | "error";
  /** Conversation ID when a conversation was started or signaled */
  conversationId?: string;
}
```

Import `EventRouter` from `../framework/types.js` (add to existing import that already has ConversationExecutor).

**router.ts** -- Major rewrite. Rename the existing `routeEvent` to `routeEventLegacy` with a `@deprecated` JSDoc tag. Add a NEW `routeEvent` function with the adapter -> EventRouter -> executor pipeline.

The new routeEvent() signature:
```typescript
export async function routeEvent(
  event: NormalizedEvent,
  deps: RouteEventDeps,
): Promise<RouteEventResult>
```

Implementation (follow RESEARCH.md patterns closely):

1. Create child logger with eventId, eventType, source
2. Log `"Routing event"` at info level
3. **Adapter pipeline**: Iterate `ALL_ADAPTERS`, take first non-null result. If all return null, call `adaptPassThrough(event)` as fallback.
4. **EventRouter**: Call `deps.eventRouter.handle(incomingEvent)` to get routing decision
5. **Dispatch based on result.action**:

   - `"start"`: Call `deps.executor.start({ agentDefinitionId: result.agentDefinitionId, correlationKey: result.correlationKey, initialMessage: result.message })`. Log success at info level. Return `{ received: true, action: "started", conversationId }`.

   - `"signal"`: Call `deps.executor.signal(result.conversationId, result.signal)`. Log the signal action result (resumed/queued/rejected/deduplicated) at info level. For "rejected" or error, log at warn level but do NOT alert (idempotent). Return `{ received: true, action: "signaled", conversationId: result.conversationId }`.

   - `"slow_path"`: Fire and forget. `void routeViaAgentLoopV2(event, deps).catch(...)`. In the catch, log at error level and call `void sendRoutingAlert(event, deps, error)`. Return `{ received: true, action: "classifying" }` immediately.

   - `"ignore"`: Log at debug level with reason. Return `{ received: true, action: "ignored" }`.

6. **Wrap the dispatch section in try/catch**. On catch, call `handleRoutingError(event, error, deps, eventLogger)` which logs at error level and calls `sendRoutingAlert`.

7. **sendRoutingAlert** -- New function replacing the old one. Takes `(event, deps, error)`. If no `deps.alertsChannel`, log warning and return. Use `callMcpTool` to send a GENERIC message to Slack: `"Something went wrong processing event ${event.type} (${event.id}). Check logs."` -- NO stack traces, NO detailed error messages per CONTEXT.md. Wrap in try/catch, swallow alert send failures (best-effort, log at warn level).

8. **handleRoutingError** returns `{ received: true, action: "error" }`.

Import `ALL_ADAPTERS` from `../adapters/index.js` and `adaptPassThrough` from `../adapters/pass-through.js`. Import `routeViaAgentLoopV2` from `./slow-path.js`. Import `callMcpTool` (already imported). Import `RouteEventDeps`, `RouteEventResult` from `./types.js`.

Keep the old `routeEventLegacy` and its helper functions (`handleRoutingFailure`, `sendRoutingAlert` as the old one) in the same file but renamed. The old `sendRoutingAlert` should become `sendRoutingAlertLegacy` (or keep as-is since it's only called from routeEventLegacy). Mark both with `@deprecated`.

**IMPORTANT**: Do NOT await slow-path. Use `void routeViaAgentLoopV2(...).catch(...)`. This is critical -- see CONTEXT.md and RESEARCH.md pitfall 2.

**IMPORTANT**: Do NOT call any MCP enrichment (callMcpTool for Linear get_issue, etc.) in the start path. Agents fetch their own context. The only callMcpTool usage is for Slack alerts on errors.
