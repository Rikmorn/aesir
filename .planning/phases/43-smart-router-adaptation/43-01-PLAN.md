**slack.ts** -- Add a case for `slack.message.created` BEFORE the default null return:
- If `payload.threadTs` exists, produce `{ type: "thread_reply", ... }` with correlationKey set to `payload.threadTs`
- If no `payload.threadTs`, produce `{ type: "channel_message", ... }` with correlationKey set to undefined (goes to slow-path)
- data: `{ text: payload.text, userId: payload.user, channelId: payload.channel, threadTs: payload.threadTs ?? payload.ts }`
- source: `"slack:webhook"`
- message: `payload.text as string`
- deduplicationId: `event.correlationId`

**github.ts** -- Add cases for ALL 5 PR review event type variants BEFORE the default null return. Use a switch fallthrough for:
- `github.pull_request.review_submitted`
- `github.pull_request.review_approved`
- `github.pull_request.review_changes_requested`
- `github.pull_request.review_commented`
- `github.pull_request.review_dismissed`

All map to domain type `"pr_review"`. Extract `prNumber` from payload. PR review payloads do NOT include branchName (confirmed in RESEARCH.md), so correlationKey is always undefined -- these events always go to slow_path. Include data: `{ reviewState: payload.reviewState, reviewBody: payload.reviewBody, reviewerLogin: payload.reviewerLogin, prNumber }`. message: `PR #${prNumber} review (${payload.reviewState}): ${(payload.reviewBody as string) || "(no comment)"}`.

**linear.ts** -- Add two cases BEFORE the default null return:
1. `linear.comment.created` -> type: `"issue_comment"`, correlationKey: `payload.issueId as string`, data: `{ body: payload.body, userId: payload.userId, issueId }`, message: `payload.body as string`
2. `linear.agent_session.prompted` -> type: `"agent_prompt"`, correlationKey: `payload.issueId as string`, data: `{ issueId, prompt: payload.prompt ?? payload.body }`, message: `(payload.prompt ?? payload.body) as string`

**pass-through.ts** -- Create NEW file. A single exported function `adaptPassThrough(event: NormalizedEvent): IncomingEvent` that:
- Returns `{ type: event.type, data: (event.payload as Record<string, unknown>) ?? {}, source: "${event.source}:webhook", deduplicationId: event.correlationId }` -- NO correlationKey (goes to slow_path)
- Import IncomingEvent from `./types.js` and NormalizedEvent from `@aesir/types`
- Add JSDoc explaining this is the fallback for unmatched events

**index.ts** -- Add export for `adaptPassThrough` from `./pass-through.js`. The `ALL_ADAPTERS` array stays as-is (pass-through is used AFTER the pipeline, not inside it -- Plan 02 handles the pipeline logic).
