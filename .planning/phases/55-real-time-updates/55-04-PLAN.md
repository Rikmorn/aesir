  <name>Task 1: Create LiveOverview client wrapper with SSE stat and active conversation updates</name>

  <action>
    Create a "use client" component that wraps the overview's stat cards and active conversations with SSE real-time updates. Worker status, recent errors, and token usage remain server-rendered (non-live).

    **Props (initial server-rendered data):**
    ```typescript
    interface LiveOverviewProps {
      initialStatusCounts: StatusCounts;
      initialActiveConversations: SerializedActiveConversation[];
      workerStatus: WorkerStatus | null;
      recentErrors: SerializedRecentError[];
      tokenUsage: TokenUsageByAgent[];
    }
    ```

    Note: ActiveConversation has a `createdAt: Date` field. Since this crosses the server/client boundary, define `SerializedActiveConversation` with `createdAt: string` and convert back to Date when passing to the presentational component. Same for RecentError's `timestamp`.

    **SSE connection:**
    Use `useEventStream` with:
    - `url: "/dashboard/api/sse/events"`
    - `types: LIFECYCLE_EVENT_TYPES` (agent.started, agent.completed, agent.paused, agent.resumed)
    - No conversationId filter (want events for all conversations)

    **State management:**

    1. **Status counts state**: `useState<StatusCounts>(initialStatusCounts)`
       When SSE events arrive, adjust counts:
       - `agent.started`: running += 1
       - `agent.completed`: Check if conversationId was in running -> running -= 1. completedLast24h += 1
       - `agent.paused`: running -= 1, waiting += 1
       - `agent.resumed`: waiting -= 1, running += 1

       Edge cases: counts should never go below 0. Use `Math.max(0, count - 1)` for decrements.

       To track which conversations are in which status (for correct decrement), maintain a `useRef<Map<string, string>>` mapping conversationId to last-known status. Initialize from the initial active conversations list. Update on each SSE event.

    2. **Active conversations state**: `useState<SerializedActiveConversation[]>(initialActiveConversations)`
       - `agent.started`: Prepend new conversation with `{ id: event.conversationId, agentDefinitionId: event.agentDefinitionId, status: "running", createdAt: event.timestamp, lastEventType: event.type }`
       - `agent.completed`: Remove from the list (filter out by conversationId)
       - `agent.paused`: Update status to "waiting" and lastEventType
       - `agent.resumed`: Update status to "running" and lastEventType

    **Stat card highlight:**
    When a stat count changes, apply a brief highlight to the changed card. The simplest approach: track which stat keys changed in the current batch (e.g., `changedStats: Set<keyof StatusCounts>`), pass to StatCards as an optional prop, and add a highlight class that fades out. Since StatCards is a server component currently, you have two choices:
    - Option A: Make StatCards accept an optional `highlightedFields` prop and add conditional classes (it doesn't use hooks so it can remain non-"use client")
    - Option B: Render stat cards inline in LiveOverview (duplicate the card layout from StatCards)

    **Choose Option A** -- it's minimal and StatCards can accept the prop without needing "use client" (it has no hooks or state). Add `highlightedFields?: Set<string>` to StatCardsProps. In the card rendering, add `ring-2 ring-accent/50 transition-all duration-[1500ms]` when the card's key is in highlightedFields, and `transition-all duration-[1500ms]` otherwise.

    Clear the highlighted set after 1.5 seconds via setTimeout in the LiveOverview effect.

    **Connection status display:**
    Render `ConnectionStatusIndicator` in the header area next to "System Overview" title.

    **Render structure:**
    ```tsx
    <>
      {/* Header with connection status */}
      <div className="mb-6 flex items-center justify-between">
        <div>
          <h1>System Overview</h1>
          <p>Real-time pulse check...</p>
        </div>
        <ConnectionStatusIndicator status={status} />
      </div>

      <div className="space-y-6">
        <StatCards counts={liveCounts} highlightedFields={highlightedStats} />

        <div className="grid gap-4 lg:grid-cols-2">
          <ActiveConversations conversations={liveActiveConversations} />
          <WorkerStatus status={workerStatus} />
        </div>

        <div className="grid gap-4 lg:grid-cols-2">
          <RecentErrors errors={recentErrors} />
          <TokenUsage data={tokenUsage} />
        </div>
      </div>
    </>
    ```

    **Date handling for ActiveConversations:**
    The `ActiveConversations` presentational component expects `createdAt: Date`. Convert serialized string dates back to Date objects before passing to it:
    ```typescript
    const liveActiveConversationsWithDates = liveActive.map(c => ({
      ...c,
      createdAt: new Date(c.createdAt),
    }));
    ```

    Same for RecentErrors -- convert `timestamp` strings back to Dates.

    **Gap handling:**
    When `state.hasGap` is true, call `router.refresh()` to re-sync all data from the server.
