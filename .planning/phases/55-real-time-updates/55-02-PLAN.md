  <files>
    packages/dashboard/src/components/conversations/live-conversations-table.tsx
  </files>
  <action>
    Create a "use client" component that wraps the existing ConversationsTable with SSE real-time updates.

    **Props:**
    Accept all the same props that the existing ConversationsTable receives from the page, plus mark them as initial data:
    - `initialData: ConversationListItem[]`
    - `total: number`
    - `page: number`
    - `pageSize: number`
    - `agentDefinitions: string[]`

    **SSE connection:**
    Use `useEventStream` with:
    - `url: "/dashboard/api/sse/events"`
    - `types: LIFECYCLE_EVENT_TYPES` (agent.started, agent.completed, agent.paused, agent.resumed)
    - No conversationId filter (we want events for all conversations)

    **State management:**
    - `useState` for `data` initialized from `initialData`
    - `useState` for `liveTotal` initialized from `total`
    - When `initialData` or `total` changes (due to server re-render from filter/page changes), reset state to new values using `useEffect` keyed on `initialData` and `total`

    **Applying SSE events:**
    Use `useEffect` watching `events` from the hook. When events array changes and has items:

    1. Build an update map from the batch of events:
       - `agent.started` with a conversationId NOT in current data: Create a new ConversationListItem with the fields available from the SSE payload (id=conversationId, agentDefinitionId, status="running", createdAt/updatedAt from timestamp, tokenInput=0, tokenOutput=0, triggerEventType=type, lastActivity from timestamp, errorMessage=null)
       - `agent.completed`: Update status to "completed", update updatedAt and lastActivity
       - `agent.paused`: Update status to "waiting", update updatedAt and lastActivity
       - `agent.resumed`: Update status to "running", update updatedAt and lastActivity

    2. Apply updates: Map over current data, merge updates for matching IDs. For new conversations, prepend to array. Increment `liveTotal` for each new conversation added.

    **Row highlight animation:**
    Track recently-updated conversation IDs in a `useRef<Set<string>>`. After applying updates, add updated IDs to the Set. Clear them after 1.5 seconds via setTimeout.

    Pass a `highlightedIds` prop (or use CSS class matching) to ConversationsTable. For the highlight effect, since ConversationsTable renders rows using TanStack Table, the simplest approach is:
    - Add an optional `highlightedIds?: Set<string>` prop to ConversationsTable
    - In the TableRow rendering, add `className` conditionally: if the row's conversation ID is in highlightedIds, add `bg-accent/30 transition-colors duration-[1500ms]`; otherwise no extra class. This creates a fade-out effect because when the ID is removed from the set, the transition smoothly returns to transparent.

    **Connection status display:**
    Import `ConnectionStatusIndicator` from `@/components/ui/connection-status`.
    Render it above the table, aligned right (or left, next to a "Conversations" sub-heading if desired), showing the current SSE connection status.

    **Render:**
    Render `ConnectionStatusIndicator` and the existing `ConversationsTable` with the live `data` (not `initialData`), `liveTotal`, and the `highlightedIds` set.
  </action>
