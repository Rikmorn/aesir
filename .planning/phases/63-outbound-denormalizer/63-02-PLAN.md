Define a `MessageOptionSchema` for ask input (separate from the one in communication/types.ts -- this is the tool's input, not the denormalizer's):

```typescript
const AskOptionSchema = z.object({
  label: z.string().describe("Display label for this option"),
  value: z.string().describe("Value sent back when this option is selected"),
});

const AskInputSchema = z.object({
  replyContext: ReplyContextSchema.describe("Channel address to send the question to"),
  question: z.string().describe("Question text to ask"),
  options: z.array(AskOptionSchema).optional().describe("Structured options for the recipient to choose from"),
});
```

- `replyContext` is REQUIRED (locked decision)
- Factory signature: `createAskTool(deps: CommunicationToolDeps): ToolDefinition`
- Tool name: `"communication_ask"`
- Description: "Ask a question on the originating channel, optionally with structured options. Options are rendered as text instructions. Requires replyContext."
- Execute: safeParse, then render options into text:

```typescript
function renderOptions(options: Array<{ label: string; value: string }>): string {
  return options.map((opt) => `- **${opt.label}**: reply "${opt.value}"`).join("\n");
}
```

If options are present and non-empty, compose text as:
```
${parsed.data.question}\n\n${renderOptions(parsed.data.options)}
```
Otherwise use `parsed.data.question` as-is.

- Call `denormalize({ replyContext: parsed.data.replyContext, text }, deps)` and return result.
- Same McpError/Error catch pattern as reply.ts.

Define communicationAdapter inline (follows mcpAdapter/codebaseAdapter pattern):
```typescript
function communicationAdapter(
  createFn: (deps: CommunicationToolDeps) => ToolDefinition,
): (ctx: ToolContext) => ToolDefinition {
  return (ctx: ToolContext) =>
    createFn({
      agentId: ctx.agentId,
      correlationId: ctx.correlationId,
      ...(ctx.taskId && { taskId: ctx.taskId }),
      logger: ctx.logger,
    });
}
```
