**2. Update conversation-executor.ts -- Four integration points:**

a. **Refactor factory to use named executor variable (CRITICAL):**

The current factory returns an object literal directly: `return { async start(...) { ... }, ... }`. The `startWorker()` method inside that literal has no way to reference the executor object itself, which is needed for `timeoutScheduler.start(executor)`.

Fix: Change the return pattern from `return { ... }` to a named variable:

```typescript
// BEFORE (current code ~line 181):
return {
  async start(params) { ... },
  async signal(conversationId, signal) { ... },
  // ...
  startWorker() { ... },
  async stopWorker() { ... },
};

// AFTER:
const executor: ConversationExecutor = {
  async start(params) { ... },
  async signal(conversationId, signal) { ... },
  // ...
  startWorker() { ... },
  async stopWorker() { ... },
};
return executor;
```

This is a pure structural refactor -- the object literal contents remain IDENTICAL. The only change is assigning to `const executor` before returning. This gives `startWorker()` closure access to the `executor` variable.

IMPORTANT: Do NOT change the contents of ANY method in the object literal for this refactor step. Just wrap the existing `return { ... }` into `const executor: ConversationExecutor = { ... }; return executor;`.

b. **Pass timeoutScheduler to worker loop:**
In `getOrCreateWorkerLoop()`, add after the existing option forwarding lines:
```typescript
if (options.timeoutScheduler !== undefined)
  loopOpts.timeoutScheduler = options.timeoutScheduler;
```

c. **Start TimeoutScheduler in startWorker():**

Add a `let schedulerStarted = false;` flag near the top of the factory (next to `let workerLoop: WorkerLoop | null = null;`).

In `startWorker()`, after `loop.start()`:
```typescript
startWorker(): void {
  const loop = getOrCreateWorkerLoop();
  loop.start();
  if (options.timeoutScheduler && !schedulerStarted) {
    schedulerStarted = true;
    void options.timeoutScheduler.start(executor).catch((err: unknown) => {
      logger.error({ err }, "Failed to start timeout scheduler");
    });
  }
},
```

This works because `executor` is now a named `const` in the enclosing scope. When `startWorker()` runs, `executor` is already fully constructed (it was assigned before `return executor`). The `void` fire-and-forget pattern with `.catch()` is intentional -- scheduler start is async but we don't want to change `startWorker()` to async since the existing interface is synchronous.

if (waitForState.triggered) {

  if (timeoutScheduler && waitForState.timeout) {

        waitForState.timeout,
        waitForState.waitType ?? "unknown",
        waitForState.reason ?? "Agent paused",

      childLogger.error({ err: scheduleError }, "Failed to schedule timeout (non-fatal)");
    }

    reason: waitForState.reason,

      messages: finalMessages as unknown[],
      pending_wait: pendingWaitValue,
      claimed_by: null,
      claimed_at: null,
      last_heartbeat_at: null,
      updated_at: new Date(),
    })
    .where(eq(conversations.id, conv.id));
