<objective>
Create the TimeoutScheduler service that wraps pg-boss for delayed signal delivery to paused conversations.

Purpose: When an agent calls wait_for with a timeout (e.g., "72h"), the system needs a durable mechanism to fire a wake-up signal after the specified duration. pg-boss provides PostgreSQL-backed delayed job scheduling that survives process restarts. This plan creates the scheduler; Plan 02 wires it into the executor and worker loop.

Output: TimeoutScheduler factory function, IDatabase adapter for pg Pool sharing, timeout duration parser, and comprehensive unit tests.
</objective>

2. Create `packages/agents/src/framework/timeout-scheduler.ts` with:

   a. **IDatabase adapter** (`createPgBossAdapter`): Wraps existing `pg.Pool` to satisfy pg-boss's `IDatabase` interface. Single method: `executeSql(text, values) => { rows, rowCount }`. Export this function for testing.

   b. **Duration parser** (`parseTimeoutDuration`): Parses timeout strings into milliseconds. Supported formats: `<number>h` (hours), `<number>d` (days), `<number>m` (minutes -- useful for testing). Throws on invalid format. Export for testing.

   c. **`computeStartAfter`**: Converts duration string to a future Date via `new Date(Date.now() + parseTimeoutDuration(duration))`. Keep as internal helper.

   d. **TimeoutScheduler interface** with 4 methods:
      - `start(executor: ConversationExecutor): Promise<void>` -- calls `boss.start()`, registers pg-boss worker on queue `conversation-timeout` that delivers `wait_timeout` signal via `executor.signal()`. The worker handler:
        - Extracts `{ conversationId, waitType, reason }` from `job.data`
        - Builds a Signal with `type: "wait_timeout"`, `source: "internal:scheduler"`, `deduplicationId: "timeout-<conversationId>-<jobId>"`
        - Calls `executor.signal(conversationId, signal)`
        - Logs result (info for success, info with warning tone for rejected -- NOT an error since rejection is expected when conversation already resumed)
      - `schedule(conversationId, timeoutDuration, waitType, reason): Promise<string>` -- calls `boss.send(TIMEOUT_QUEUE, data, { startAfter, singletonKey: conversationId })`, returns job ID
      - `cancel(jobId): Promise<void>` -- calls `boss.cancel(jobId)`. Wraps in try/catch; log debug on failure (job may have already fired)
      - `close(): Promise<void>` -- calls `boss.stop()`

   e. **`createTimeoutScheduler` factory** accepting `TimeoutSchedulerOptions`:
      - `pool: Pool` (from `pg` package)
      - `logger: PinoLogger`
      - `schema?: string` (default: `"pgboss"`)
      Creates PgBoss with `{ db: adapter, schema, schedule: false, migrate: true }`. Returns TimeoutScheduler interface.

   f. **Constant**: `TIMEOUT_QUEUE = "conversation-timeout"`

   g. **TimeoutJobData interface**: `{ conversationId: string; waitType: string; reason: string }`

   Type imports: use `import type { ConversationExecutor, Signal } from "./types.js"` and `import type { Pool } from "pg"` and `import type { PinoLogger } from "@aesir/platform"`.

   IMPORTANT: Import PgBoss as `import PgBoss from "pg-boss"`. pg-boss exports a default class.

   IMPORTANT: pg-boss's `cancel` method signature is `cancel(id: string)` NOT `cancel(queue, id)`. Check the pg-boss types before calling.

   IMPORTANT: `boss.work()` second argument should be `{ batchSize: 1 }` as options and the handler as third argument, OR use the two-argument form `boss.work(queue, handler)`. Check pg-boss v12 types to determine correct call signature.
