Update all three integration Dockerfiles to use tini as init process:

1. In runtime stage, install tini via apt-get (node:22-slim is Debian-based):
   ```dockerfile
   RUN apt-get update && apt-get install -y --no-install-recommends tini && rm -rf /var/lib/apt/lists/*
   ```

2. Add ENTRYPOINT with tini before CMD:
   ```dockerfile
   ENTRYPOINT ["/usr/bin/tini", "--"]
   CMD ["node", "dist/main.js"]
   ```

3. For Linear Dockerfile, update from node:20-slim to node:22-slim for consistency with GitHub/Slack.

Why tini: Node.js as PID 1 ignores signals (SIGTERM) unless explicitly handled. tini receives signals and forwards them to Node.js, enabling graceful shutdown. Docker's --init flag does this but requires flag at runtime; baking tini into image ensures consistent behavior.

Do NOT use Alpine apk commands - these images use Debian (apt-get).

2. Replace simple health endpoint with async handler that checks database:
   ```typescript
   interface HealthResponse {
     status: "ok" | "degraded";
     service: string;
     timestamp: number;
     uptime: number;
     database?: "healthy" | "unhealthy";
     error?: string;
   }

   app.get("/health", async (_req, res) => {
     const health: HealthResponse = {
       status: "ok",
       service: "{service-name}",
       timestamp: Date.now(),
       uptime: process.uptime(),
     };

     try {
       await db.execute(sql`SELECT 1`);
       health.database = "healthy";
     } catch (err) {
       health.status = "degraded";
       health.database = "unhealthy";
       health.error = err instanceof Error ? err.message : "Database connection failed";
       logger.error({ err }, "Health check: database unhealthy");
       return res.status(503).json(health);
     }

     res.status(200).json(health);
   });
   ```

3. Use appropriate service names:
   - Linear: "linear-integration"
   - GitHub: "github-integration"
   - Slack: "slack-integration"

4. For Slack HTTP mode, ensure health endpoint exists (currently only in socket mode). Add health check to Express app in HTTP mode branch.

5. Import `db` from ./db/client.js if not already imported.

Why database validation: A health endpoint that just returns "ok" doesn't verify the service can actually serve requests. Docker Compose depends_on uses health checks to determine readiness - services should only report healthy when they can process requests (which requires database access).
