<task type="auto">
  <name>Task 1: Add Docker Compose watch configuration</name>
  <files>docker-compose.yml</files>
  <action>
Add `develop.watch` configuration to each application service (NOT to postgresql, temporal, temporal-ui, cloudflared).

Add watch config to these services:
1. linear-integration
2. github-integration
3. slack-integration
4. dev-agent
5. product-agent

For each integration service (linear, github, slack), add:
```yaml
    develop:
      watch:
        # Sync TypeScript source files for hot reload
        - action: sync
          path: ./packages/integrations/{integration}/src
          target: /app/src
          ignore:
            - node_modules/
            - "**/*.test.ts"
        # Rebuild on dependency changes
        - action: rebuild
          path: ./packages/integrations/{integration}/package.json
        # Rebuild on common package changes (dependency)
        - action: rebuild
          path: ./packages/common/src
```

For dev-agent and product-agent services, add:
```yaml
    develop:
      watch:
        # Sync agent source files
        - action: sync
          path: ./packages/agents/src
          target: /app/packages/agents/src
          ignore:
            - node_modules/
            - "**/*.test.ts"
        # Rebuild on dependency changes
        - action: rebuild
          path: ./packages/agents/package.json
        # Rebuild on shared package changes
        - action: rebuild
          path: ./packages/common/src
        - action: rebuild
          path: ./packages/platform/src
        - action: rebuild
          path: ./packages/integrations/src
```

Note: The path for integrations targets /app/src because integration Dockerfiles COPY dist to /app/dist (relative paths). However, watch mode syncs source files, so the build step inside container needs to handle this. Given integration Dockerfiles copy pre-built dist, watch with sync will NOT work directly - syncing TS files won't help since the image runs from dist/.

CORRECTION: Integration images run from pre-built dist/, so watch mode should use `sync+restart` or `rebuild` for changes. Let's use a practical approach:

For integration services, use rebuild on source changes (since they need compilation):
```yaml
    develop:
      watch:
        - action: rebuild
          path: ./packages/integrations/{integration}/src
        - action: rebuild
          path: ./packages/integrations/{integration}/package.json
        - action: rebuild
          path: ./packages/common/src
```

For agents (which also run from pre-built dist/):
```yaml
    develop:
      watch:
        - action: rebuild
          path: ./packages/agents/src
        - action: rebuild
          path: ./packages/agents/package.json
        - action: rebuild
          path: ./packages/common/src
        - action: rebuild
          path: ./packages/platform/src
```

This means all source changes trigger rebuild. For faster iteration, developers can run services locally with tsx watch instead of Docker.

Update the header comment to document watch mode usage:
```yaml
# Watch mode (opt-in hot reload):
#   docker compose watch                   # Watch all services
#   docker compose watch --no-up           # Watch without starting services
#   docker compose up && docker compose watch  # Start then watch
```
