# Phase 9.1: Infrastructure & Local Dev - Context

**Gathered:** 2026-01-18
**Status:** Ready for planning

<vision>
## How This Should Work

Fully containerized local development where `docker-compose up` starts everything — Temporal, Product Agent, Dev Agent, webhook receivers, all services. No "run this on host, that in Docker" split.

The README serves dual purpose: onboarding human developers AND providing context for LLMs reading the project. Someone (or something) clones the repo and has everything running with minimal friction.

Containerizing now also sets up for production deployment later — the same containers that run locally will run on remote services.

</vision>

<essential>
## What Must Be Nailed

All three are non-negotiable for v1.0:

- **Clone-to-running experience** — Minimal friction from git clone to everything running
- **Linear OAuth working E2E** — Authorize, token exchange, automatic refresh, agent acts as app identity (not personal user)
- **Dev Agent parity with Product Agent** — Same polish with entry point script, clear invocation

</essential>

<specifics>
## Specific Ideas

- OAuth tokens need persistence — SQLite already in project for checkpointing, can use that. Or simple JSON file for MVP.
- Follow standard docker-compose patterns for multi-service local dev
- No specific reference project to emulate — general best practices

</specifics>

</notes>
