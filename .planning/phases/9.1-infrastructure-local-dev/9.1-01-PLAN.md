## Must-Haves

### Truths (invariants)
- `actor=app` in authorization URL ensures actions appear as app identity, not user
- OAuth tokens expire after 24 hours; refresh tokens are long-lived
- State parameter must be verified on callback to prevent CSRF attacks
- Token refresh is already implemented in `client.ts`; only authorization flow is missing

### Artifacts
- `src/scripts/linear-oauth.ts` — standalone authorization script
- `.linear-tokens.json` — persisted tokens (gitignored)

### Key Links
- Research: `9.1-RESEARCH.md` → OAuth flow diagram, code examples
- Existing: `src/integrations/linear/client.ts` → `createLinearClient`, `refreshOAuthToken`
- Pattern: `src/scripts/start-product-agent.ts` → entry point script pattern

<objective>
Create a standalone OAuth authorization script that exchanges authorization codes for tokens and persists them to a JSON file, enabling the existing Linear client to use OAuth tokens with automatic refresh.
</objective>

<execution_context>
@9.1-RESEARCH.md
@src/integrations/linear/client.ts
@src/integrations/linear/types.ts
</execution_context>

<context>
The Linear client already implements token refresh (`refreshOAuthToken`). What's missing:
1. Initial authorization flow (user consent → code → token exchange)
2. Token persistence (save tokens to file for reuse across runs)

The `createLinearClient(config, onTokenRefresh)` function accepts a callback to persist refreshed tokens.

Required env vars: LINEAR_CLIENT_ID, LINEAR_CLIENT_SECRET (already documented)
</context>

## Tasks

<task id="1" name="Create OAuth authorization script">
<description>
Create `src/scripts/linear-oauth.ts` that:
1. Builds authorization URL with `actor=app` parameter
2. Starts a local HTTP server on port 3000 to receive callback
3. Exchanges authorization code for tokens
4. Persists tokens to `.linear-tokens.json`
</description>

<files>
- CREATE: src/scripts/linear-oauth.ts
</files>

<acceptance_criteria>
- Script builds authorization URL with correct scopes: `read,write,issues:create,comments:create`
- Authorization URL includes `actor=app` parameter (critical for app identity)
- State parameter generated and verified on callback
- Token exchange uses existing pattern from research
- Tokens saved to `.linear-tokens.json` in project root
- Script exits cleanly after successful authorization
</acceptance_criteria>

<implementation_hints>
Use Node.js `http` module for callback server (no Express needed).
Use `crypto.randomUUID()` for state parameter.
Follow the code example structure from 9.1-RESEARCH.md.

Token file format:
```json
{
  "accessToken": "...",
  "refreshToken": "...",
  "expiresAt": 1705612800000
}
```
</implementation_hints>
</task>

```bash

import { loadLinearTokens } from './src/integrations/linear/token-store.js';
const tokens = await loadLinearTokens();
```
