<objective>
Build the dual-layer token refresh middleware for Linear OAuth tokens.

Purpose: actor=app tokens are short-lived (~24h). Without proactive refresh, every MCP tool call risks hitting an expired token. The proactive timer prevents most expirations; the reactive 401 retry catches edge cases (downtime, clock skew). This is the prerequisite for the actor=app migration in Plan 67-02.

Output: `refresh-middleware.ts` with proactive timer and 401 retry, updated `flow.ts` to use it, proactive timer lifecycle in `main.ts`.
</objective>

  <action>
Create `refresh-middleware.ts` in the Linear client directory with two exports:

**1. `withTokenRefresh<T>(operation, options)` -- reactive 401 retry wrapper:**
- Takes an async operation `(client: LinearClient) => Promise<T>` and `RefreshMiddlewareOptions` (credentialStore, workspaceId, logger).
- Creates a LinearClient from the credential store's current token.
- Executes the operation. On success, returns result.
- On 401/auth error (`isAuthError` check -- look for status 401 or "Unauthorized" or "Authentication" in error message), calls `refreshWithMutex()` then retries the operation once with a fresh client.
- On non-auth errors, re-throws.

**2. `startProactiveRefresh(options)` -- proactive timer:**
- Takes `ProactiveRefreshOptions` (credentialStore, workspaceId, logger, checkIntervalMs = 60_000).
- Returns `{ stop: () => void }` for cleanup on shutdown.
- Every `checkIntervalMs`, reads the credential from DB via `credentialStore.getByWorkspace()`.
- If no credential or no `expiresAt` or no `refreshToken`, skip silently.
- Calculate 80% lifetime threshold: `createdAt + (expiresAt - createdAt) * 0.8`. If `Date.now() >= threshold`, call `refreshWithMutex()`.
- On first call, also check immediately (don't wait for first interval tick).

**3. Internal `refreshWithMutex(options)` -- shared refresh coalescing:**
- Module-level `let refreshPromise: Promise<void> | null = null`.
- If `refreshPromise` is active, return it (concurrent callers wait on same promise).
- Otherwise, create new promise: call `refreshOAuthToken()` from factory.ts with the current refresh token, persist new tokens via `credentialStore.updateTokens()`, then clear `refreshPromise` in `.finally()`.
- **Retry logic:** 3 attempts with exponential backoff (1s, 2s, 4s delays). Use a simple loop.
- **Non-transient failure detection:** If the refresh response indicates revoked token (`invalid_grant` or HTTP 400/401 from the token endpoint), log at ERROR: "Linear refresh token revoked -- manual re-authorization required". Then attempt Slack notification by calling `fetch` to the Slack integration's MCP endpoint (`http://slack-integration:3003/mcp/tools/send_message` or use env `SLACK_MCP_URL`). Use `SLACK_OPS_CHANNEL` env var for target channel. If Slack call fails, log but don't throw -- alerting is best-effort.
- After all retries exhausted for transient errors, throw the last error (caller handles -- MCP tool returns error to agent).

**Helper `isAuthError(error: unknown): boolean`:**
- Check for Linear GraphQL auth errors: look for status code 401, or error messages containing "Unauthorized", "Authentication required", "UNAUTHENTICATED".
- Linear SDK wraps GraphQL errors in a specific way -- check `error.extensions?.code === "UNAUTHENTICATED"` and `error.response?.status === 401`.
