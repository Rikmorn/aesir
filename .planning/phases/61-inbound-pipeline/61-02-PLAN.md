  <action>
    **Slack adapter** (`packages/agents/src/adapters/slack.ts`):

    For `slack.app_mention.created`:
    - Extract `teamId` from `payload.teamId as string | undefined`
    - Extract `channelId` from `payload.channel as string | undefined`
    - `threadTs` is already extracted: `(payload.threadTs as string) || (payload.ts as string)`
    - Only include replyContext if `teamId` AND `channelId` are truthy
    - Spread into the return object: `...(teamId && channelId && { replyContext: { channel: "slack" as const, teamId, channelId, threadTs } })`

    For `slack.message.created` (thread reply case, after the !threadTs guard):
    - Extract `teamId` from `payload.teamId as string | undefined`
    - Extract `channelId` from `payload.channel as string | undefined`
    - Only include replyContext if `teamId` AND `channelId` are truthy
    - Spread: `...(teamId && channelId && { replyContext: { channel: "slack" as const, teamId, channelId, threadTs } })`

    For `block_actions.approved`, `block_actions.rejected`, `block_actions.escalation_retry`, `block_actions.escalation_abort`:
    - Do NOT add replyContext. Per research and locked decisions: the Slack interactions handler does not include teamId in NormalizedEvent for block_actions events. Omit replyContext entirely for these events.

    **Linear adapter** (`packages/agents/src/adapters/linear.ts`):

    For `linear.agent_session.created`:
    - `issueId` is already extracted from `payload.issueId`
    - Add replyContext: `replyContext: { channel: "linear" as const, issueId }`

    For `linear.comment.created`:
    - `issueId` is already extracted from `payload.issueId`
    - Add replyContext: `replyContext: { channel: "linear" as const, issueId }`

    For `linear.agent_session.prompted`:
    - `issueId` is already extracted from `payload.issueId`
    - Add replyContext: `replyContext: { channel: "linear" as const, issueId }`

    For `linear.issue.created` and `linear.issue.updated`:
    - Do NOT add replyContext. These are ignore events with no actionable reply address.

    **Tests:**

    In `slack.test.ts`, add tests in existing describe blocks:
    - `app_mention.created`: verify replyContext has `{ channel: "slack", teamId, channelId, threadTs }` when all fields present
    - `app_mention.created`: verify replyContext is undefined when `teamId` is missing from payload
    - `message.created` (thread reply): verify replyContext has correct fields
    - `block_actions.approved`: verify replyContext is NOT present

    In `linear.test.ts`, add tests:
    - `agent_session.created`: verify replyContext has `{ channel: "linear", issueId }`
    - `comment.created`: verify replyContext has `{ channel: "linear", issueId }`
    - `issue.created`/`issue.updated`: verify NO replyContext
  </action>
  <verify>
    Run `pnpm test:fast -- packages/agents/src/adapters/slack.test.ts` -- all pass.
    Run `pnpm test:fast -- packages/agents/src/adapters/linear.test.ts` -- all pass.

    - Extract repository same way: `const repository = payload.repository as { owner: string; name: string } | undefined;`
