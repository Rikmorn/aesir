<task type="auto">
  <name>Task 1: Install Octokit and create type definitions</name>
  <files>package.json, src/integrations/github/types.ts</files>
  <action>
    1. Install @octokit/rest (the official GitHub REST API client):
       `npm install @octokit/rest`

    2. Create src/integrations/github/types.ts following the Linear pattern:
       - GitHubConfig interface: token (string)
       - BranchInfo interface: name, sha, protected (boolean)
       - CreateBranchOptions interface: owner, repo, branchName, baseBranch (default: 'main')
       - CommitInfo interface: sha, message, author (name, email, date)
       - FileChange interface: path, content, mode (default: '100644')
       - CreateCommitOptions interface: owner, repo, branch, message, files (FileChange[])
       - PullRequestInfo interface: number, title, body, state, headBranch, baseBranch, url
       - CreatePROptions interface: owner, repo, title, body, head, base

    Use consistent JSDoc comments like the Linear types.
    Do NOT create interfaces that duplicate Octokit's own types - only create what we need for our API surface.
  </action>
  <verify>npm run lint passes, types.ts has proper exports</verify>
  <done>@octokit/rest installed, type definitions exported from types.ts</done>
</task>

<task type="auto">
  <name>Task 3: Create branch operations</name>
  <files>src/integrations/github/branches.ts, src/integrations/github/branches.test.ts, src/integrations/github/index.ts</files>
  <action>
    1. Create src/integrations/github/branches.ts:
       - Import Octokit from @octokit/rest
       - Import createLogger
       - Import types (CreateBranchOptions, BranchInfo)

       - getBranch(octokit: Octokit, owner: string, repo: string, branch: string): Promise<BranchInfo>
         - Uses octokit.rest.git.getRef({ owner, repo, ref: `heads/${branch}` })
         - Returns { name: branch, sha: ref.object.sha, protected: false }
         - Log operation at debug level

       - listBranches(octokit: Octokit, owner: string, repo: string): Promise<BranchInfo[]>
         - Uses octokit.rest.repos.listBranches({ owner, repo })
         - Maps response to BranchInfo array
         - Log operation at debug level

       - createBranch(octokit: Octokit, options: CreateBranchOptions): Promise<BranchInfo>
         - First get base branch SHA: getBranch(octokit, owner, repo, baseBranch)
         - Then create ref: octokit.rest.git.createRef({ owner, repo, ref: `refs/heads/${branchName}`, sha: baseSha })
         - Return new branch info
         - Log operation at info level with outcome

    2. Create src/integrations/github/branches.test.ts:
       - Mock Octokit methods (rest.git.getRef, rest.git.createRef, rest.repos.listBranches)
       - Test getBranch returns correct BranchInfo
       - Test listBranches maps response correctly
       - Test createBranch calls getRef then createRef with correct params
       - Test createBranch returns new branch info

    3. Create src/integrations/github/index.ts:
       - Export all from ./types.js
       - Export createGitHubClient, getOctokit from ./client.js
       - Export getBranch, listBranches, createBranch from ./branches.js
  </action>
  <verify>npm test -- src/integrations/github/branches.test.ts passes, npm run build succeeds</verify>
