3. Define `HumanInputRequest` interface: `{ channel: string; message: string; requestType: "approval" | "clarification" | "escalation" }`.

4. Define `parseHumanInputMarker(result: AgentLoopResult): HumanInputRequest | null` function:
   - Scan `result.trace` for steps where `step.type === "tool_result"` and `step.toolName === "request_human_input"`
   - For each matching step, try `JSON.parse(step.output as string)`, check for `parsed.type === HUMAN_INPUT_MARKER`
   - Return `{ channel: parsed.channel, message: parsed.message, requestType: parsed.requestType }` on match
   - Return null if no sentinel found (or parsing fails)
   - IMPORTANT: Parse the ENTIRE trace, not just the last step (Pitfall 1 from research -- LLM may continue after sentinel)

Rejection feedback: ${input.rejectionFeedback}"`
   - Call `runDevAgentOrchestrator({ issueId: input.issue.identifier, issueTitle: input.issue.title, containerManager: deps.containerManager, taskId: input.taskId, agentId: "dev-agent", correlationId: input.taskId, workflowId: input.workflowId, db: deps.db, logger: deps.logger, maxIterations: 100 })`
   - NOTE: `runDevAgentOrchestrator` builds its own initialMessage internally. We need to check if it accepts a custom initialMessage. Looking at orchestrator.ts: it builds `initialMessage` from `issueId` and `issueTitle` internally. For rejection feedback, we should NOT duplicate the initial message -- instead, we need to handle this differently.
   - REVISED APPROACH: Store rejection feedback in the task store before calling the orchestrator: `deps.taskStore.updateTask(input.taskId, { approvalFeedback: input.rejectionFeedback, approvalStatus: "rejected" })`. The orchestrator's system prompt tells it to read task state, and it has tools to do so. This aligns with the "self-sufficient agents" principle from Phase 31.
   - Parse sentinel: `const humanInputRequest = parseHumanInputMarker(result)`
   - Write context snapshot: `deps.contextManager.writeSnapshot({ taskId: input.taskId, workflowId: input.workflowId, agentType: "dev-orchestrator", stage: "post-research-plan", summary: result.output, toolCallCount: result.toolCallCount, tokenCount: result.tokenCount })`
   - Return slim result: `{ status: result.status, plan: result.output, humanInputRequest, toolCallCount: result.toolCallCount, tokenCount: result.tokenCount }`
   - Wrap in try/catch: if `runDevAgentOrchestrator` throws an infrastructure error (e.g., Anthropic API 500), re-throw for Temporal retry. If it returns a result with `status === "error"`, return it (don't throw -- let the workflow handle it).

   - Get deps, update task status to "executing"

   - Extract PR info from the task store after the orchestrator completes (the orchestrator writes PR info via tools). Read task: `const task = await deps.taskStore.getTask(input.taskId)`.
   - Build output using conditional property assignment for exactOptionalPropertyTypes:
