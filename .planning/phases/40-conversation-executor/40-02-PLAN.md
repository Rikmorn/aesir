  <action>
Create `packages/agents/src/framework/conversation-executor.ts` implementing `createConversationExecutor(options: ConversationExecutorOptions): ConversationExecutor`.

The factory returns an object implementing the ConversationExecutor interface. Internally it holds references to db, eventLog, sessionProjection, agentRegistry, toolRegistry, logger from options. The worker loop is NOT in this plan -- this plan focuses on the API surface (data operations).

**start(params: StartConversationParams): Promise&lt;string&gt;**

1. Compute deterministic conversation ID: `${params.agentDefinitionId}-${params.correlationKey}`
2. Inside a transaction (`db.transaction()`):
   a. Check for existing conversation with this ID using `SELECT ... FOR UPDATE`
   b. If existing:
      - Status is 'running', 'queued', or 'waiting': return existing ID (idempotent no-op, log info)
      - Status is 'completed', 'failed', or 'cancelled': find next suffix by querying `WHERE id LIKE baseId-r%` ORDER BY id DESC LIMIT 1, parse suffix number, increment. Create new conversation with suffixed ID.
   c. If not existing: INSERT new conversation
3. For new conversations (both fresh and re-trigger):
   - Resolve agent definition via `agentRegistry.get(params.agentDefinitionId)`
   - Throw if agent definition not found
   - Set fields: id, agent_definition_id, agent_definition_version, status='queued', messages=[initial user message], parent_conversation_id (from params)
   - For re-triggers: inject one-line previous attempt context into initial message. Query the session projection for the previous conversation to get status, failure reason, and known artifacts. Prepend: `"[Previous attempt ${prevId}: ${status}. ${failureReason || ''}. Known artifacts: ${artifacts}.]"`
4. Return the conversation ID (either existing or newly created)

**signal(conversationId: string, signal: Signal): Promise&lt;{ action: ... }&gt;**

1. Validate signal against SignalSchema (from types.ts). If invalid, return `{ action: "rejected" }`.
2. Inside a transaction:
   a. Lock conversation row: `SELECT ... FOR UPDATE` by ID
   b. If not found: return `{ action: "rejected" }`
   c. Check signal deduplication: build dedup key as `${signal.source}:${signal.deduplicationId}`. If present in `delivered_signal_ids` JSONB array, return `{ action: "deduplicated" }`
   d. Track delivered signal: append dedup key to delivered_signal_ids (only if deduplicationId is present)
   e. If status is 'waiting':
      - Check type match against `pending_wait.type`. If mismatch, log warning, return `{ action: "rejected" }`
      - Build signal message: `{ role: "user", content: signal.message ?? "Signal received: ${signal.type}. Data: ${JSON.stringify(signal.data)}" }`
      - Append signal message to messages array
      - Update: status='queued', messages=updated, pending_wait=null, delivered_signal_ids=updated
      - Append `signal.received` event to eventLog
      - Return `{ action: "resumed" }`
   f. If status is 'running' or 'queued':
      - Append signal to queued_signals JSONB array
      - Update: queued_signals=updated, delivered_signal_ids=updated
      - Return `{ action: "queued" }`
   g. Otherwise (terminal status): return `{ action: "rejected" }`

**get(conversationId: string): Promise&lt;ConversationInfo | null&gt;**

1. Query conversations table by ID
2. If not found, return null
3. Map row to ConversationInfo: { id, agentDefinitionId, agentDefinitionVersion, status, createdAt, updatedAt }

**cancel(conversationId: string): Promise&lt;boolean&gt;**

1. Inside a transaction:
   a. Lock row: `SELECT ... FOR UPDATE`
   b. If not found or terminal status (completed, failed, cancelled): return false
   c. Update status='cancelled', clear claimed_by/claimed_at/last_heartbeat_at
   d. Append `agent.completed` event with payload `{ error: "Cancelled" }` to eventLog
   e. Flush eventLog
   f. Return true

**list(options?): Promise&lt;ConversationInfo[]&gt;**

1. Build query with optional WHERE clauses: status filter, agentDefinitionId filter
2. Apply limit (default 100)
3. Order by created_at DESC
4. Map rows to ConversationInfo array

**Internal helper: findNextSuffix(tx, baseId)**

Query `WHERE id LIKE ${baseId}-r%` ORDER BY id DESC LIMIT 1. Parse `-r(\d+)$` from last match. Return parsed + 1, or 2 if no matches.

Export `createConversationExecutor` from framework/index.ts.

IMPORTANT implementation notes:
- Use `eq()`, `and()`, `like()`, `or()`, `desc()` from drizzle-orm for type-safe queries
- Use `sql` tagged template for raw SQL where Drizzle's builder is insufficient (e.g., FOR UPDATE within transaction)
- The factory does NOT start the worker loop. It only provides the API surface. The worker loop (Plan 03) calls internal methods.
- Store references to db, registries, logger as closure variables inside the factory
- Do NOT persist messages on start -- just the initial message array. Messages are persisted at lifecycle boundaries during execution (Plan 03).
