## Changes Summary

### Task 1: Add startApprovalWorkflow to Temporal client

**Problem:** No function to start the approval workflow from external triggers. The webhook handler needs to start workflows programmatically.

**Solution:**
- Added `startApprovalWorkflow` function that wraps `client.workflow.start`
- Imports `prApprovalWorkflow` from workflows module
- Uses `dev-agent-queue` task queue (matching worker configuration)
- Re-exports `ApprovalWorkflowInput` and `ApprovalWorkflowResult` types

**Key code:**
```typescript
export async function startApprovalWorkflow(
  workflowId: string,
  input: ApprovalWorkflowInput
): Promise<WorkflowHandle<typeof prApprovalWorkflow>> {
  const client = await getTemporalClient();
  return client.workflow.start(prApprovalWorkflow, {
    workflowId,
    taskQueue: APPROVAL_TASK_QUEUE,
    args: [input],
  });
}
```

### Task 2: Create Linear AgentSession webhook handler

**Problem:** Gap 3 from audit - no automated trigger for Dev Agent when tasks are delegated in Linear.

**Solution:**
- Created `linear-agent-session.ts` with two functions:
  - `handleAgentSessionWebhook`: Business logic for processing AgentSession events
  - `linearWebhookHandler`: HTTP request handler with signature verification
- Follows same pattern as `github-pr-review.ts`
- Uses existing webhook utilities from `integrations/linear/webhooks.ts`
- Only handles 'created' action (new delegation), ignores 'prompted' (follow-up)

**Key workflow:**
1. Verify signature using `verifyWebhookSignature`
2. Validate timestamp with `validateWebhookTimestamp` (replay attack prevention)
3. Check if event is `AgentSession` type
4. Build `ApprovalWorkflowInput` from config and payload
5. Call `startApprovalWorkflow` with workflow ID `approval-{taskId}`

### Task 3: Update Dev Agent entry point

**Problem:** Dev Agent only ran Temporal worker. No HTTP server to receive Linear webhooks.

**Solution:**
- Added HTTP server using `createServer` from `node:http`
- Routes:
  - `POST /webhooks/linear` - Linear webhook handler
  - `GET /health` - Health check for container orchestration
- Initializes all activity dependencies:
  - LinearClient, Octokit, WebClient, DockerSandbox
- Passes dependencies to `createTemporalWorker`
- Worker runs non-blocking; HTTP server handles requests
- Graceful shutdown cleans up server, worker, and sandbox

**New required env vars:**
- `LINEAR_WEBHOOK_SECRET`
- `SLACK_BOT_TOKEN`
- `SLACK_CHANNEL_ID`
- `DATABASE_URL`

## Integration Notes

The Linear webhook handler completes Gap 3 from the v1-MILESTONE-AUDIT. The E2E flow is now:

1. User delegates task to Dev Agent in Linear
2. Linear sends AgentSession webhook to `/webhooks/linear`
3. Webhook handler verifies signature and starts `prApprovalWorkflow`
4. Workflow runs Dev Agent, sends Slack notification, waits for approval
5. On approval, merges PR and updates Linear status

**Webhook Configuration Required:**
- Linear Settings -> Webhooks -> Add webhook
- URL: `https://your-domain/webhooks/linear` (or use ngrok for local dev)
- Events: AgentSession
- Copy signing secret to `LINEAR_WEBHOOK_SECRET`
