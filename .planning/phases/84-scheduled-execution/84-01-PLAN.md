    ```typescript
    /** Cron schedules that periodically trigger this agent */
    schedules: z.array(z.object({
      /** Unique schedule name within this agent (used in correlationKey, dashboard, prompts) */
      name: z.string().min(1),
      /** Standard 5-field cron expression (e.g., "0 9 * * MON") */
      cron: z.string().min(1).refine(
        (val) => {
          try {
            // Import cron-parser (transitive dep via pg-boss) for validation
            const { CronExpressionParser } = require("cron-parser");
            CronExpressionParser.parse(val);
            return true;
          } catch {
            return false;
          }
        },
        { message: "Invalid cron expression" }
      ),
      /** IANA timezone (e.g., "America/New_York"). Defaults to UTC. */
      timezone: z.string().optional(),
    })).optional(),
    ```

    **1. Create `schedule-registry.ts`:**

    Export a `createScheduleRegistry(options: ScheduleRegistryOptions): ScheduleRegistry` factory.

    **Queue naming:** `schedule:${agentId}:${scheduleName}` (e.g., `schedule:product-agent:weekly-grooming`). This prefix is critical for reconciliation -- only touch queues starting with `schedule:`.

    **`registerAll(boss)`:**
    1. Load all agent definitions via `agentRegistry.list()`
    2. Build set of expected schedule queue names from definitions with `schedules` field
    3. Call `boss.getSchedules()` to get all existing pg-boss schedules
    4. Filter existing schedules to those with names starting with `schedule:` (avoid touching dedup cleanup or other jobs)
    5. Unschedule any in pg-boss that aren't in the expected set: `boss.unschedule(name)`
    6. For each expected schedule:
       a. `boss.createQueue(queueName)`
       b. `boss.schedule(queueName, cronExpr, { agentId, scheduleName, cron: cronExpr }, { tz: timezone ?? "UTC" })`
       c. `boss.work(queueName, handler)` where handler calls `handleScheduleFire(agentId, scheduleName, cronExpr)`
    7. Log summary: registered count, unscheduled count

    **`handleScheduleFire(agentId, scheduleName, cron)` (private):**
    1. Build the deterministic correlationKey: `${agentId}:${scheduleName}`
    2. Check for overlap: query conversations table where `id LIKE '${agentId}-${correlationKey}%'` and status in ('queued', 'running', 'waiting'). Use the pool directly for this query.
    3. If active conversation found: log skip at info level, optionally insert a skip event (use the `event.routed` pattern from router.ts -- direct DB insert to agent_events with `conversation_id: "scheduler"`, type `schedule.skipped`, and payload with agentId, scheduleName, activeConversationId, reason). Return early.
    4. If no overlap: build schedule context via `buildScheduleContext()`, then create synthetic `IncomingEvent`:
       ```typescript
       const syntheticEvent = {
         type: "schedule.triggered",
         source: "scheduler",
         correlationKey: `${agentId}:${scheduleName}`,
         data: { agentId, scheduleName, cron, trigger: "scheduled" as const },
         message: `Scheduled run: ${scheduleName}`,
       };
       ```
    5. The synthetic event needs to be submitted to the event processing pipeline. Store the `routeEventFn` callback via a `setRouteEventFn(fn)` method on the registry, called during main.ts wiring. The handler calls `routeEventFn(syntheticEvent)`.

    Alternatively, accept the routeEvent dependency in options or as a late-binding setter. The handler needs to POST to itself or call the route function directly. Since the route function requires `RouteEventDeps`, the cleanest approach is: the handler creates the synthetic event and calls a callback that was set during wiring. Add `setEventHandler(handler: (event: IncomingEvent) => Promise<void>): void` to the ScheduleRegistry interface.

    **`getScheduleStates(agentId)`:**
    Query `agents.schedule_state` where `agent_id = agentId`. Return array of `ScheduleState`.

    **`getAllScheduleStates()`:**
    Query all rows from `agents.schedule_state`. Return array of `ScheduleState`.

    **`updateScheduleState(agentId, scheduleName, outcome, conversationId, summary)`:**
    Upsert into `agents.schedule_state`:
    ```sql
    INSERT INTO agents.schedule_state (agent_id, schedule_name, last_run_at, last_run_outcome, last_run_conversation_id, last_run_summary, run_count)
    VALUES ($1, $2, now(), $3, $4, $5, 1)
    ON CONFLICT (agent_id, schedule_name) DO UPDATE SET
      last_run_at = now(),
      last_run_outcome = EXCLUDED.last_run_outcome,
      last_run_conversation_id = EXCLUDED.last_run_conversation_id,
      last_run_summary = EXCLUDED.last_run_summary,
      run_count = agents.schedule_state.run_count + 1;
    ```

    **`buildScheduleContext(agentId, scheduleName, trigger)`:**
    1. Query schedule state from DB
    2. Compute time since last run (if lastRunAt exists)
    3. If lastRunConversationId exists, query the conversation's `messages` array for the last assistant message content. Truncate to ~500 chars.
    4. Build XML block:
    ```xml
    <schedule_context>
    Schedule: {scheduleName}
    Last run: {lastRunAt or "Never"}
    Time since last run: {humanDuration or "First run"}
    Last run outcome: {lastRunOutcome or "N/A"}
    Last run summary: {summary or "No previous run"}
    Run count: {runCount}
    Trigger: {trigger}
    </schedule_context>
    ```
