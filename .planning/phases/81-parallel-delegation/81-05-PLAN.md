<objective>
Implement the one-cleanup-turn cancellation pattern: when a conversation receives a `task_cancelled` signal, it gets exactly one agent loop run to clean up, then is force-terminated.

Purpose: This cancellation pattern is required by both `cancel_group` and standalone task cancellation. It ensures agents can save artifacts and add comments before termination, but cannot keep running indefinitely. Per user decision, this applies to ALL delegation, not just groups.

Output: pending_cancellation column, signal delivery sets the flag, worker loop enforces one-turn termination.
</objective>

The cancellation pattern has two sides: (1) setting the flag when the signal is delivered, (2) enforcing one-turn termination in the worker loop.

**conversation-executor.ts changes (signal delivery):**

1. In the `signal()` method, when the signal type is `task_cancelled` and the conversation is being resumed (action === "resumed"), set `pending_cancellation = true` on the conversation row alongside the status transition:
   ```typescript
   // In the signal() method, when transitioning from "waiting" to "queued"
   if (signal.type === "task_cancelled") {
     // Set pending_cancellation so worker loop enforces one-turn limit
     await db.update(conversations).set({
       pending_cancellation: true,
       // ... other fields already being set
     }).where(eq(conversations.id, conversationId));
   }
   ```
   Find the exact location where the signal delivery transitions the conversation and add the pending_cancellation flag there.

2. Also handle queued signals: if a `task_cancelled` signal is queued (conversation is running), set `pending_cancellation = true` immediately so the worker loop can check it after the current agent loop completes.

**Worker loop changes (enforcement):**

3. In the worker loop, AFTER the agent loop exits (step 14, where `waitForState.triggered` is checked), add a `pending_cancellation` check BEFORE the normal result handling:

   ```typescript
   // 13c. Check for pending cancellation (one-cleanup-turn pattern, Phase 81)
   // Re-read the conversation to get the latest pending_cancellation flag
   // (may have been set by a signal delivered during the agent loop)
   const cancellationCheck = await db
     .select({ pending_cancellation: conversations.pending_cancellation })
     .from(conversations)
     .where(eq(conversations.id, conv.id))
     .limit(1);

   if (cancellationCheck[0]?.pending_cancellation) {
     // Agent had one turn to clean up. Force-terminate regardless of waitForState.
     await db.update(conversations).set({
       status: "cancelled",
       messages: finalMessages as unknown[],
       pending_cancellation: false,
       last_persisted_sequence: eventLog.getSequence(conv.id),
       claimed_by: null,
       claimed_at: null,
       last_heartbeat_at: null,
       updated_at: new Date(),
     }).where(eq(conversations.id, conv.id));

     eventLog.append({
       ...eventBase,
       type: "agent.completed",  // Use completed event type (task status is cancelled)
       payload: { output: "Conversation terminated after cancellation cleanup turn" },
     });
     await eventLog.flush();

     // Cascade: send task_cancelled to any active delegations this conversation has
     const freshConv = await db.select({ active_delegations: conversations.active_delegations })
       .from(conversations).where(eq(conversations.id, conv.id)).limit(1);
     const activeDelegations = (freshConv[0]?.active_delegations ?? []) as Array<{ taskId?: string }>;
     for (const delegation of activeDelegations) {
       if (delegation.taskId) {
         const childConv = await options.executor?.findActiveForTask(delegation.taskId);
         if (childConv) {
           void options.executor?.signal(childConv.id, {
             type: "task_cancelled",
             data: { taskId: delegation.taskId, reason: "Parent conversation cancelled" },
             message: "Your task has been cancelled because the parent was cancelled. You have one turn to clean up.",
             source: `cascade:${conv.id}`,
             deduplicationId: `cancel-cascade-${delegation.taskId}`,
           }).catch(err => {
             childLogger.warn({ err, taskId: delegation.taskId }, "Failed to cascade cancellation (non-fatal)");
           });
         }
       }
     }

     childLogger.info("Conversation terminated after cancellation cleanup turn");
     return;
   }
   ```

4. Place this check BEFORE the existing `if (waitForState.triggered)` block so it takes precedence. If `pending_cancellation` is true, the conversation is terminated regardless of whether the agent called wait_for or ended normally.

5. **Important edge case:** If the conversation was already in a wait state when the cancellation signal was queued (but the signal hasn't been consumed yet), the signal consumption at step 6 of the worker loop will resume the conversation with the cancellation message. The `pending_cancellation` flag will already be set. After the cleanup turn, the check at step 13c will terminate it.
