     ed.name AS entity_name,
     tt.status,

Visual design (per user decisions and research):
- Wider than task nodes: `w-[280px]` (vs ~220px for tasks)
- Top row: policy badge (pill with policy type text) + group status icon
- Policy display: "all_required" -> "All Required", "any_sufficient" -> "Any (1/{total})", "min_required" -> "Min {threshold}/{total}"
- Middle: progress fraction (e.g., "3/5 completed") with a subtle progress bar
- Bottom: group status text
- Border color based on group status:
  - `active` -> amber/yellow (`border-amber-500`)
  - `satisfied` -> green (`border-emerald-500`)
  - `unsatisfiable` -> red (`border-red-500`)
  - `cancelled` -> gray (`border-gray-400`)
  - `settled` -> green if was satisfied, gray otherwise
- Background: follows dashboard's depth/elevation pattern (subtle card background)
- Handles: top (target) and bottom (source) for React Flow edges

3. Update `transformTreeToGraph`:
   a. **Detect groups:** Group tasks by `groupId`. Tasks sharing the same non-null `groupId` form a group.
   b. **Create group nodes:** For each unique groupId, create a `GraphNode` with type `"group"`:
      - `id`: the groupId (e.g., `grp_abc123`)
      - Compute counts from the group's tasks (completed, failed, running, etc.)
      - Policy and status from the first task's `groupPolicy` and `groupStatus` fields
   c. **Re-parent edges:** For grouped tasks, change the edge so:
      - The delegator (parent of grouped tasks) connects to the group node
      - The group node connects to each task in the group
      - Remove the direct delegator-to-task edges for grouped tasks
   d. **Non-grouped tasks:** Unchanged (existing behavior).

4. Important: the group node's parentId is the parent_id of the first task in the group (all tasks in a group share the same parent). The group node sits between the delegator and the individual task nodes.
