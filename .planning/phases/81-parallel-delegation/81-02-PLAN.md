**delegate-group.ts:**

1. **Input schema** (Zod):
   ```typescript
   const TaskInGroupSchema = z.object({
     agentId: z.string().min(1).optional(),
     capability: z.string().min(1).optional(),
     description: z.string().min(1),
     timeout: z.string().optional()
       .describe("Per-task timeout (e.g., '1h'). Optional within groups."),
   }).refine(
     (task) => (task.agentId != null) !== (task.capability != null),
     "Exactly one of agentId or capability must be provided"
   );

   const CompletionPolicySchema = z.discriminatedUnion("type", [
     z.object({ type: z.literal("all_required") }),
     z.object({ type: z.literal("any_sufficient") }),
     z.object({ type: z.literal("min_required"), threshold: z.number().int().min(1) }),
   ]);

   const DelegateGroupInputSchema = z.object({
     tasks: z.array(TaskInGroupSchema).min(2),
     policy: CompletionPolicySchema,
     timeout: z.string().optional(),
   });
   ```

2. **Factory signature:** `createDelegateGroupTool(ctx: ToolContext): ToolDefinition`

3. **Tool name:** `delegate_group`. Description should explain it creates parallel delegations with policy-driven completion.

4. **Execute logic** (similar to delegate_task but multi-task):
   a. Check `ctx.delegationDeps` exists (return error if not).
   b. Validate all tasks: for each task, if `capability` is provided, return error "Capability-based routing not yet available (Phase 85). Use agentId." If `agentId` provided, verify entity exists via `deps.directoryService.get()`.
   c. If ANY task fails validation, return error with all failing tasks listed (atomic -- no partial creation).
   d. Check delegation depth for each task (same logic as delegate_task, using parent task from `ctx.taskId`).
   e. Validate `min_required` threshold: if `policy.type === "min_required"`, check `policy.threshold <= tasks.length`. Error if threshold > task count.
   f. Create group via `deps.groupService.create()` (GroupService comes from Plan 01; DelegationDeps extension is handled in step 0 above).
   g. For each task: create task via `deps.taskService.create()` with `groupId: group.id`, build delegation XML block, start conversation via `deps.executor.start()`.
   h. If any task creation/start fails after the group was created, cancel already-started conversations and delete the group (rollback). Use try/catch around the task creation loop.
   i. Schedule group timeout if `timeout` provided. Use optional chaining on `deps.timeoutScheduler`:
      ```typescript
      if (parsed.timeout && deps.timeoutScheduler) {
        const jobId = await deps.timeoutScheduler.schedule(
          group.delegatorConversationId,
          parsed.timeout,
          "group_timeout",
          `Group ${groupId} timeout`,
          { groupId },
        );
        await deps.groupService!.setTimeoutJobId(groupId, jobId);
      }
      ```
      This is a no-op when `timeoutScheduler` is undefined (before Plan 04 wires it). Plan 04 injects the scheduler; the scheduling call already lives here.
   j. Track all delegations in `active_delegations` on the delegator's conversation (same pattern as delegate_task but batch).
   k. Return human-readable response: groupId, per-task mapping (taskId + title + agent), policy, guidance to call wait_for_group.

**cancel-group.ts:**

1. **Input schema:**
   ```typescript
   const CancelGroupInputSchema = z.object({
     groupId: z.string().min(1).describe("ID of the group to cancel"),
   });
   ```

2. **Factory:** `createCancelGroupTool(ctx: ToolContext): ToolDefinition`

3. **Tool name:** `cancel_group`. Description: cancels all remaining tasks in a group by sending task_cancelled signal.

4. **Execute logic:**
   a. Get group state via `deps.groupService.getGroupState(groupId)`.
   b. If group not found, return error.
   c. If group already in terminal state (cancelled or settled), return informational message.
   d. For each task that is NOT in a terminal state (completed, failed, cancelled):
      - Find active conversation: `deps.executor.findActiveForTask(task.taskId)`
      - If found, send `task_cancelled` signal:
        ```typescript
        await deps.executor.signal(conv.id, {
          type: "task_cancelled",
          data: {
            taskId: task.taskId,
            groupId: groupId,
            reason: "Group cancelled by delegator",
          },
          message: "Your task has been cancelled. You have one turn to clean up (save artifacts, add comments, mark status).",
          source: `agent:${ctx.agentId}`,
          deduplicationId: `cancel-${task.taskId}`,
        });
        ```
      - Update task status to cancelled: `deps.taskService.update(task.taskId, { status: "cancelled" })`
   e. Update group status to "cancelled": `deps.groupService.updateStatus(groupId, "cancelled")`
   f. Cancel group timeout job if one exists (via `deps.timeoutScheduler?.cancel(group.timeout_job_id)`).
   g. Return summary: how many tasks were cancelled, how many were already terminal.

5. **Cancellation cascading:** The `task_cancelled` signal triggers the target conversation to wake. The worker loop's `pending_cancellation` pattern (Plan 05) handles the one-cleanup-turn guarantee. If the cancelled task has its own sub-delegations, the cancellation cascades via the same signal mechanism when that conversation processes the signal.
