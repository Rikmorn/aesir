```typescript
interface CompactionResult {
```

**HistoryManager interface and factory:**
```typescript
interface HistoryManager {
  compact(
```

**Protected boundary calculation:**
- `protectedStart = Math.max(0, messages.length - config.protectedMessages)`
- After computing protectedStart, check if message at protectedStart is a user message containing ONLY tool_result blocks. If so, move protectedStart back by 1 to include the preceding assistant message with matching tool_use blocks. This ensures tool_use/tool_result pairs are never split.

**Deduplication by file path:**
- Scan unprotected messages from END to START
- For each tool_result block where the tool name is `read_file` or `get_file_contents`, extract the file path from the corresponding tool_use block in the preceding assistant message
- Track which file paths have been seen. For duplicate paths (earlier reads), mark them for replacement with minimal descriptors (not head+tail -- they'll be fully replaced since a more recent read exists)
- Look up tool names by matching tool_use_id from tool_result blocks against tool_use blocks in the preceding (i-1) assistant message

**Tool type tier system (pattern matching, not hardcoded list):**
- File reads: tool name matches `read_file` or `get_file_contents` -- apply head+tail truncation (500 head + 1500 tail tokens, converted to chars * 4)
- Search/list: tool name matches `search_codebase`, `list_directory`, `list_files` -- minimal descriptor: `[Tool: {name} -- args: {JSON.stringify(args)}. {removedTokens} tokens removed.]`
- Command output: tool name matches `run_command` -- minimal descriptor: `[Tool: {name} -- command: {command}, exit code: {exitCode}. {removedTokens} tokens removed.]` Extract command and exitCode from tool_use input and tool_result content respectively.
- Integration tools: tool name contains `:` in the ORIGINAL tool name (from Anthropic content block, which uses underscores not colons -- so match tool names starting with `linear_`, `github_`, `slack_` or use a configurable pattern) -- apply head+tail truncation same as file reads

**Head+tail truncation function:**
```typescript
function headTailTruncate(text: string, headTokens: number, tailTokens: number): { truncated: string; removedTokens: number }
```
- Convert token targets to character positions (tokens * 4)
- If total tokens <= headTokens + tailTokens, return unchanged
- Take `text.slice(0, headChars)` and `text.slice(-tailChars)`
- Insert `\n\n[... {removedTokens} tokens truncated ...]\n\n` between head and tail

**Phase 1 pruning pipeline (within compact method):**
1. Estimate tokens in messages array
2. If < pruneThreshold: return messages unchanged with phase "none"
3. Deep-clone unprotected messages (never mutate input)
4. Run deduplication pass (replace earlier reads of same file with descriptors)
5. Run tier-based replacement pass on remaining unprotected tool results
6. Re-estimate tokens after pruning
7. Return with phase "pruned" (Plan 02 will add Phase 2 check here)

**Important implementation details:**
- NEVER mutate the input messages array. Deep-clone before modification.
- NEVER prune assistant text blocks (TextBlock). Only tool_result content is replaced.
- When replacing tool_result content, keep the `tool_use_id` and `type: "tool_result"` fields intact. Only replace the `content` field.
- For tool_result blocks with array content (containing text blocks), extract all text, then apply the replacement to the concatenated text and set content back as a string.
- Export `estimateTokens`, `estimateMessageTokens`, `createHistoryManager`, `HistoryConfig`, `CompactionResult`, and `HistoryManager` types.
