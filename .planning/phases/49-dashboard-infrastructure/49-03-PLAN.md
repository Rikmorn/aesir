Create `packages/dashboard/Dockerfile` with a multi-stage build optimized for Next.js standalone output in a pnpm monorepo.

The Dockerfile differs from existing service Dockerfiles because Next.js has its own standalone output mode (`.next/standalone`) instead of using `pnpm deploy --prod`.

**Stage 1: base** (shared base image)
- `FROM node:22-slim AS base`
- `RUN corepack enable && corepack prepare pnpm@9.15.0 --activate`

**Stage 2: deps** (dependency installation)
- `WORKDIR /app`
- Copy workspace config: `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `package.json`, `tsconfig.base.json`
- Copy ALL workspace package.json files needed for pnpm resolution (same pattern as existing Dockerfile):
  - `packages/types/package.json`
  - `packages/platform/package.json`
  - `packages/observability/package.json`
  - `packages/agents/package.json`
  - `packages/test-utils/package.json`
  - `packages/integrations/linear/package.json`
  - `packages/integrations/github/package.json`
  - `packages/integrations/slack/package.json`
  - `packages/dashboard/package.json`
- `RUN pnpm install --frozen-lockfile`

**Stage 3: builder** (build workspace deps + Next.js)
- `WORKDIR /app`
- Copy node_modules from deps stage
- `COPY . .`
- Build workspace dependencies that dashboard imports:
  - `RUN pnpm --filter @aesir/types build`
  - `RUN pnpm --filter @aesir/platform build`
  - If dashboard depends on @aesir/agents for schema: `RUN pnpm --filter @aesir/agents exec tsc -b tsconfig.build.json`
- Build Next.js: `RUN pnpm --filter @aesir/dashboard build`

**Stage 4: runner** (minimal production image)
- `FROM base AS runner`
- `WORKDIR /app`
- `ENV NODE_ENV=production`
- Create non-root user: `RUN groupadd -g 1001 aesir && useradd -u 1001 -g aesir aesir`
- Copy standalone output. Because `outputFileTracingRoot` is set to monorepo root, the standalone output mirrors the monorepo directory structure:
  ```dockerfile
  COPY --from=builder /app/packages/dashboard/.next/standalone ./
  COPY --from=builder /app/packages/dashboard/.next/static ./packages/dashboard/.next/static
  COPY --from=builder /app/packages/dashboard/public ./packages/dashboard/public
  ```
  Note: The `public` directory COPY will fail silently if `public/` doesn't exist (no static assets yet). Add `public/.gitkeep` in the dashboard package if needed, or use a conditional copy pattern.
- `USER aesir`
- `EXPOSE 3005`
- Set runtime environment:
  ```dockerfile
  ENV PORT=3005
  ENV HOSTNAME="0.0.0.0"
  ```
- Start command: `CMD ["node", "packages/dashboard/server.js"]`

**Important considerations:**
- Do NOT use tini (unlike other services) -- Next.js standalone server handles signals adequately
- Do NOT use `pnpm deploy --prod` -- Next.js standalone mode replaces that pattern
- The `COPY . .` in builder copies the entire monorepo, which is necessary because `outputFileTracingRoot` traces from the root
- If the `public/` directory doesn't exist yet, create an empty `packages/dashboard/public/.gitkeep` to prevent Docker COPY failure

**Update docker-compose.yml:**

Add a `dashboard` service after the `agent-service` service and before the `cloudflared` service. Follow the existing service patterns.

```yaml
  # Dashboard - Next.js operations dashboard for agent monitoring
  # Provides read-only visibility into conversations, agents, tools, and system health
  # Access: http://localhost:3005 (direct) or http://localhost/dashboard/ (via nginx)
  dashboard:
    build:
      context: .
      dockerfile: packages/dashboard/Dockerfile
    container_name: aesir-dashboard
    depends_on:
      postgresql:
        condition: service_healthy
    environment:
      # Database connection (read-only access to existing schemas)
      - DB_HOST=postgresql
      - DB_PORT=5432
      - DB_USER=aesir
      - DB_PASSWORD=aesir
      - DB_NAME=aesir
      # Server configuration
      - PORT=3005
      - HOSTNAME=0.0.0.0
      - NODE_ENV=${NODE_ENV:-production}
    ports:
      - "3005:3005"
    healthcheck:
      test: ["CMD-SHELL", "node -e \"require('http').get('http://localhost:3005/dashboard/api/health', (r) => process.exit(r.statusCode === 200 ? 0 : 1))\""]
      interval: 10s
      timeout: 5s
      retries: 3
      start_period: 30s
    networks:
      - aesir-network
    restart: unless-stopped
    develop:
      watch:
        - action: rebuild
          path: ./packages/dashboard/src
        - action: rebuild
          path: ./packages/dashboard/package.json
```

Note: The healthcheck URL includes `/dashboard/` prefix because `basePath: "/dashboard"` is set in next.config.ts. The health API route is at `/dashboard/api/health`.

**Important:** Do NOT add the dashboard as a dependency of nginx. The nginx service currently depends on all 4 existing services being healthy. Adding the dashboard would mean nginx won't start until the dashboard is healthy, which may slow down development when the dashboard isn't needed. Instead, make the nginx dashboard routing work when the service is available but don't block nginx startup on it.

If nginx depends_on is updated, the dashboard would need to be running for ANY nginx routing to work (including webhooks). This is unacceptable. Keep the dashboard as an optional service that nginx routes to when available.

**Intentional tradeoff:** When the dashboard service is down or not started, requests to `/dashboard/*` through nginx will return 502 Bad Gateway. This is acceptable and intentional -- the dashboard is an operations tool, not a critical path service. A 502 on `/dashboard/*` does not affect webhook routing, agent execution, or any integration. The alternative (adding dashboard to nginx depends_on) would block ALL nginx routing when the dashboard is unhealthy, which is far worse.

**Update docker-config/nginx.conf:**

Add a `dashboard` upstream and location block. Insert after the `agent-service` upstream and before the `server` block:

```nginx
upstream dashboard {
    server dashboard:3005;
}
```

Add a location block inside the server block, after the `/agent/` location and before the root location:

```nginx
    # Dashboard - Next.js operations dashboard
    # Routes: /dashboard/* -> Next.js app with basePath: "/dashboard"
    # Note: basePath means Next.js expects to receive /dashboard/* paths
    location /dashboard/ {
        proxy_pass http://dashboard/dashboard/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
        proxy_buffering off;
    }
```

The `proxy_pass http://dashboard/dashboard/;` preserves the `/dashboard/` prefix because Next.js expects it (basePath config). Without this, Next.js would receive requests at `/` and not match its routes.

Update the root location to include the dashboard in the available routes JSON:
```json
{"routes":{"/linear/*":"Linear integration","/github/*":"GitHub integration","/slack/*":"Slack integration","/agent/*":"Agent service","/dashboard/*":"Operations dashboard","/health":"Nginx health"}}
```

Also update the docker-compose.yml header comments to include dashboard in the access URLs section:
```
#   - http://localhost/dashboard/* → Dashboard (agent monitoring)
```
And direct access:
```
#   - Dashboard: http://localhost:3005
```
