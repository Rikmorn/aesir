  <action>
**Add database dependencies to package.json:**
Add `drizzle-orm@^0.45.1` and `pg@^8.17.2` to dependencies. Add `@types/pg@^8.16.0` to devDependencies. Run `pnpm install` from monorepo root.

**Create `src/lib/db.ts`:**

The dashboard needs read-only access to `agents.conversations`, `agents.agent_events`, and `agents.agent_sessions` tables. There are two approaches for getting the schema:

**Approach A (preferred):** Import schema from `@aesir/agents`. The package exports `./*` mapping to `./dist/*.js`, so `@aesir/agents/shared/db/schema` should resolve. Add `@aesir/agents` as a dependency to the dashboard package.json (with `workspace:*`). Test the import works at typecheck time.

**Approach B (fallback, if import fails):** Define standalone read-only table definitions directly in the dashboard. This is acceptable for read-only use -- copy the Drizzle table definitions (conversations, agentEvents, agentSessions) from `packages/agents/src/shared/db/schema.ts` into a local `src/lib/schema.ts` file. This trades slight duplication for independence from internal package export paths.

**Try Approach A first.** If `pnpm --filter @aesir/dashboard run typecheck` fails with import resolution errors, switch to Approach B.

The db.ts file should:
- Use `drizzle` from `drizzle-orm/node-postgres` with `pg.Pool`
- Configure connection via environment variables: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` (same pattern as all other services)
- Use `max: 5` pool size (read-only dashboard needs fewer connections)
- Set `idleTimeoutMillis: 30000` and `connectionTimeoutMillis: 5000`
- Pass schema to the drizzle constructor

Example structure:
```typescript
import { drizzle } from "drizzle-orm/node-postgres";
import { Pool } from "pg";
// Import or define schema tables here

const pool = new Pool({
  host: process.env.DB_HOST || "localhost",
  port: Number.parseInt(process.env.DB_PORT || "5432", 10),
  user: process.env.DB_USER || "aesir",
  password: process.env.DB_PASSWORD || "aesir",
  database: process.env.DB_NAME || "aesir",
  max: 5,
  idleTimeoutMillis: 30000,
  connectionTimeoutMillis: 5000,
});

export const db = drizzle(pool, { schema: { ... } });
```

Note: The dashboard uses environment variables directly (process.env) rather than the platform's env validation -- it's a Next.js app with its own runtime, not a service that imports @aesir/platform config.

  <action>
Create `src/services/conversations.ts` that abstracts all conversation database queries behind typed functions.

The service must:
1. Import `db` from `@/lib/db`
2. Import the conversations table definition (from wherever it was resolved in Task 1)
3. Import Drizzle operators: `desc`, `eq`, `sql`, `count` from `drizzle-orm`
4. Define a `ConversationSummary` interface with typed fields:
   ```typescript
   export interface ConversationSummary {
     id: string;
     agentDefinitionId: string;
     status: string;
     retryCount: number;
     errorMessage: string | null;
     createdAt: Date;
     updatedAt: Date;
   }
   ```
5. Export `listConversations` function:
   ```typescript
   export async function listConversations(opts?: {
     status?: string;
     limit?: number;
     offset?: number;
   }): Promise<ConversationSummary[]>
   ```
   - Select relevant columns from conversations table
   - Apply optional status filter using `eq()` when `opts.status` is provided
   - Order by `updated_at` DESC
   - Limit defaults to 50, offset defaults to 0
   - Map database column names (snake_case) to interface fields (camelCase)

6. Export `countConversationsByStatus` function:
   ```typescript
   export async function countConversationsByStatus(): Promise<
     Array<{ status: string; count: number }>
   >
   ```
   - Group by status, count each
   - Returns array of { status, count } objects

These two functions prove the service layer pattern works. Future phases will add more query functions to this file and create additional service files (events.ts, sessions.ts, etc.).

**Important:** This file uses `"use server"` or is only imported by server components. Next.js App Router server components can use `async` functions directly. Do NOT add `"use client"` anywhere. The service layer runs server-side only.
