**Function 1: getConversationStatusCounts()**

Returns `StatusCounts` interface with fields: `running`, `waiting`, `queued`, `completedLast24h`, `failedLast24h` (all numbers).

CRITICAL: Mixed time scoping (from RESEARCH.md Pitfall 2):
- `running`, `waiting`, `queued`: Count ALL conversations with these statuses (no time filter -- these are current state)
- `completedLast24h`, `failedLast24h`: Count conversations with status='completed'/'failed' AND `updated_at >= now() - 24h`

Implementation: Use two queries:
1. `countConversationsByStatus()` pattern (already exists in conversations.ts) -- but we need a simpler version that just counts running/waiting/queued. Query: `SELECT status, COUNT(*) FROM agents.conversations WHERE status IN ('running', 'waiting', 'queued') GROUP BY status`
2. For 24h counts: `SELECT status, COUNT(*) FROM agents.conversations WHERE status IN ('completed', 'failed') AND updated_at >= $since GROUP BY status`

Map results into `StatusCounts` object, defaulting each field to 0 if no rows match.

**Function 2: getActiveConversations(limit = 10)**

Returns `ActiveConversation[]` with fields: `id`, `agentDefinitionId`, `status`, `createdAt` (Date), `lastEventType` (string | null).

Query conversations with `status IN ('running', 'waiting')`, LEFT JOIN `agent_sessions` for `last_event_type`.
Order by `created_at ASC` (oldest first = longest running first, per CONTEXT.md decision).
Limit to `limit` rows.

Use the existing `agentSessions` import from `@/lib/schema` (add to imports if needed).

Map snake_case DB columns to camelCase interface fields.

**Function 3: getRecentErrors(limit = 10)**

Returns `RecentError[]` with fields: `id`, `conversationId` (string | null for failed conversations -- use conversation id), `agentDefinitionId`, `errorMessage` (string, truncated), `timestamp` (Date), `type` ('conversation' | 'tool').

Two parallel queries (from RESEARCH.md):

1. Failed conversations in last 24h:
   ```sql
   SELECT id, agent_definition_id, error_message, updated_at
   FROM agents.conversations
   WHERE status = 'failed' AND updated_at >= $since
   ORDER BY updated_at DESC LIMIT $limit
   ```

2. Tool failures in last 24h:
   ```sql
   SELECT id, conversation_id, agent_definition_id, payload, timestamp
   FROM agents.agent_events
   WHERE type = 'tool.failed' AND timestamp >= $since
   ORDER BY timestamp DESC LIMIT $limit
   ```

Normalize both into `RecentError[]`, merge, sort by timestamp DESC, slice to `limit`.

For failed conversations: `conversationId = row.id` (the conversation IS the error), `errorMessage = row.error_message ?? "Unknown error"`.
For tool failures: `conversationId = row.conversation_id`, `errorMessage = (payload.output as string) ?? (payload.tool_name as string + " failed")`.

Truncate errorMessage to 120 characters (per RESEARCH.md recommendation).

**Function 4: getTokenUsageByAgent()**

Returns `TokenUsageByAgent[]` with fields: `agentDefinitionId` (string), `inputTokens` (number), `outputTokens` (number).

Query (from RESEARCH.md):
```sql
SELECT agent_definition_id,
       COALESCE(SUM(token_count_input), 0) as total_input,
       COALESCE(SUM(token_count_output), 0) as total_output
FROM agents.agent_events
WHERE type = 'llm.response' AND timestamp >= $since
GROUP BY agent_definition_id
```

Where `$since` = `new Date(Date.now() - 24 * 60 * 60 * 1000)`.

Map to camelCase, cast with `Number()`.
