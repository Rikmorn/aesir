<task type="auto">
  <name>Task 1: Fix import paths across all packages</name>
  <files>packages/*/src/**/*.ts</files>
  <action>
  Go through each package and fix import statements. The pattern is:

  **In @aesir/common:**
  - Imports within common use relative paths: `./config/index.js`
  - No external @aesir/* imports (common is the leaf)

  **In @aesir/platform:**
  - Import from common: `import { config } from "@aesir/common";`
  - Internal imports: relative paths `./state/index.js`

  **In @aesir/integrations:**
  - Import from common: `import { logger } from "@aesir/common";`
  - Import from platform: `import { state } from "@aesir/platform";`
  - Internal imports: relative paths

  **In @aesir/agents:**
  - Import from common: `import { config } from "@aesir/common";`
  - Import from integrations: `import { linearClient } from "@aesir/integrations";`
  - Do NOT import directly from @aesir/platform (agents access platform through integrations or common)
  - Internal imports: relative paths

  **Common patterns to fix:**
  1. `from "../config/index.js"` -> `from "@aesir/common"` (when crossing package boundary)
  2. `from "../../logging/logger.js"` -> `from "@aesir/common"` (when crossing package boundary)
  3. `from "../integrations/linear/client.js"` -> `from "@aesir/integrations"` (when in agents)

  **Keep as relative paths:**
  - Imports within the same package stay relative
  - `from "./nodes/index.js"` stays as-is in agents

  **Strategy:**
  1. Start with common (no external deps, just internal fixes)
  2. Then platform (imports from common)
  3. Then integrations (imports from common + platform)
  4. Finally agents (imports from common + integrations)

  For each file, check:
  - Is the import target in the same package? -> Keep relative
  - Is the import target in a different package? -> Use @aesir/* package import
  </action>
  <verify>
  After fixing imports:
  - `grep -r "from \"\.\.\/\.\.\/" packages/` should return minimal results (only legitimate deep relative imports within same package)
  - `grep -r "@aesir/common" packages/platform/` shows platform correctly imports from common
  - `grep -r "@aesir/integrations" packages/agents/` shows agents correctly imports from integrations
  </verify>
  <done>All cross-package imports use @aesir/* package names, intra-package imports use relative paths</done>
</task>

<task type="auto">
  <name>Task 2: Run pnpm install and verify build</name>
  <files>pnpm-lock.yaml, package.json, packages/*/dist/</files>
  <action>
  1. Delete old npm artifacts:
  ```bash
  rm -rf node_modules package-lock.json
  ```

  2. Run pnpm install:
  ```bash
  pnpm install
  ```

  Watch for:
  - Peer dependency warnings (especially LangChain) - note but don't block
  - Workspace package linking confirmation
  - Any hard errors

  If peer dependency errors occur:
  - Check if they're warnings vs errors
  - For LangChain, ensure @langchain/core is installed at root level
  - Use pnpm's built-in handling before adding overrides

  3. Build all packages:
  ```bash
  pnpm build
  # or
  tsc -b
  ```

  This builds in dependency order: common -> platform -> integrations -> agents.

  Fix any TypeScript errors that appear. Common issues:
  - Missing exports in index.ts files
  - Circular dependencies (will be caught by disallow-workspace-cycles in .npmrc)
  - Type mismatches after import changes

  4. Verify each package built:
  ```bash
  ls packages/common/dist/
  ls packages/platform/dist/
  ls packages/integrations/dist/
  ls packages/agents/dist/
  ```

  Each should have .js and .d.ts files.

  5. Run typecheck to verify no type errors:
  ```bash
  pnpm typecheck
  ```

  6. Update root package.json scripts if needed:
  ```json
  {
    "scripts": {
      "build": "tsc -b",
      "typecheck": "tsc -b --noEmit",
      "test": "vitest run",
      "lint": "biome check .",
      "lint:fix": "biome check --write .",
      "format": "biome format --write .",
      "dev-agent": "pnpm --filter @aesir/agents dev-agent",
      "product-agent": "pnpm --filter @aesir/agents product-agent",
      "prepare": "husky"
    }
  }
  ```
  </action>
  <verify>
