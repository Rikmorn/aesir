# Phase 22.1: Common Library Refactor - Context

**Gathered:** 2026-01-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Refactor @aesir/common from a library that validates environment variables at import time to a pure library pattern. Common will have no config file, no env.ts, and no global config — all dependencies are passed as function arguments. Services (agents, integrations) own their environment configuration and pass values to common utilities.

</domain>

<decisions>
## Implementation Decisions

### Migration Approach
- Big bang migration — fix all consumers in one phase, no shim layer
- Each service gets a single `src/config.ts` file (flat, not folder)
- Config validated eagerly at boot — fail fast if env vars missing
- Within a service, import config object directly: `import { config } from './config.js'`
- Remove lazy loading hacks introduced during debugging — straightforward eager validation

### API Surface Changes
- Logger factory uses defaults with optional overrides: `createLogger(opts?)`
- DB utilities: Keep only if abstraction is useful, otherwise remove — services use libraries directly
- Integration-specific errors (LinearError, GitHubError, SlackError) move to each integration package
- Correlation ID utilities stay in common — pure function, no env vars
- Re-export third-party types (PinoLogger etc.) from common — consumers get clean abstraction
- Zod schemas exported alongside types for consumer composition
- State module stays in common (cross-layer contract for typed checkpoints)
- HTTP middleware (pino-http) stays in common — not broken, don't move it
- Temporal logger adapter stays in common
- agent-config.ts moves to agents package

### Dependency Management
- Runtime dependencies in common's package.json (dependencies, not devDependencies)
- Never manually edit lock files — always use `pnpm install`
- Agents must verify dependency placement (dev vs non-dev) — past issues with nanoid, dotenv-flow not being available in containers

### Backward Compatibility
- No deprecation warnings — big bang migration
- Removed exports cause compilation errors (not runtime errors)
- Verification: build + unit tests + Docker startup (all containers must start)
- Audit and update integration re-exports if they depend on removed common exports
- Test mocking strategy: Claude's discretion based on test complexity

### Module Boundaries (Final Structure)
- Delete common/src/config/ folder entirely (including env.ts)
- Rename common/src/db/ to common/src/utils/ or common/src/ids/
- Keep: errors/, logging/, mcp/, state/, temporal/, types/, utils/
- MCP types stay in common (shared contract)
- Temporal types stay in common

### Docker/Env Alignment
- Ensure docker-compose.yml environment variables match service config schemas
- Main .env file has all vars; containers reference what they need
- Remove Proxy-based lazy validation — eager fail-fast at boot

</decisions>

<specifics>
## Specific Ideas

- "Common should not interact with env vars at all — simply request needed data as arguments"
- "Main services (agents and integrations) can load env vars at boot eagerly and in a concrete config file (instead of spread out through the code)"
- "As they use modules from common that require new config, add appropriately to service config file, and to docker container as main .env file will have them all anyway"
- "Consumer doesn't care what's underneath, just that it logs to the standard set on the project"
- "Rather it be kept simple — overhead is non-existent in practice" (re: runtime dependencies)
- "Do not change lock files manually, always run pnpm as that service will ensure lock file is up to date"
- "Lazy loads can be removed and loading can be made more straightforward, fail at boot if env vars/config is missing"
- "Ensure docker definitions and env vars in config actually match"

</specifics>

<deferred>
## Deferred Ideas

- **State module migration to agents** — For better scaling when multiple teams/agents exist. Currently state is cross-layer contract; future: agents own state, platform uses generics/opaque JSON for checkpoints.

</deferred>
