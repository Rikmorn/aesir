  <action>
Replace the stub observability schema with actual table definition:

1. In `packages/observability/src/db/schema.ts`:
   - Import `createId` from `@aesir/common`
   - Import `pgSchema, text, timestamp, integer, index` from `drizzle-orm/pg-core`
   - Define `agentExecutions` table with columns:
     - `id`: text primary key with `$defaultFn(() => createId.execution())`
     - `workspace_id`: text, notNull
     - `agent_type`: text, notNull (e.g., 'dev-agent', 'product-agent')
     - `issue_id`: text, notNull (Linear issue ID as string, not FK)
     - `status`: text with enum `['started', 'completed', 'failed']`, notNull
     - `started_at`: timestamp with timezone, notNull
     - `ended_at`: timestamp with timezone (nullable)
     - `duration_ms`: integer (nullable, calculated on completion)
     - `last_known_state`: text (nullable, captured on failure)
     - `created_at`: timestamp with timezone, defaultNow, notNull
   - Add indexes:
     - `agent_executions_status_started_idx` on (status, started_at) - for querying recent failures
     - `agent_executions_workspace_idx` on (workspace_id) - for multi-tenant filtering
   - Export types: `AgentExecution`, `NewAgentExecution`

2. In `packages/observability/src/db/schema.drizzle.ts`:
   - Create standalone schema file for drizzle-kit (same pattern as integrations)
   - Inline the pgSchema and table definition (no workspace:* imports)
   - This file is only used by drizzle-kit for migrations

Follow the exact pattern from `packages/integrations/src/db/schema.ts`.
