Create `knowledge-service.ts` following the `createTaskService()` factory pattern from `task-service.ts`.

**Interface:**
```typescript
interface KnowledgeServiceOptions {
  db: NodePgDatabase<typeof agentsSchemaModule>;
  embeddingService: EmbeddingService;
  logger: PinoLogger;
}

interface KnowledgeService {
  store(params: StoreKnowledgeParams): Promise<StoreKnowledgeResult>;
  query(params: QueryKnowledgeParams): Promise<KnowledgeQueryResult[]>;
  supersede(entryId: string, params: SupersedeParams): Promise<StoreKnowledgeResult>;
  invalidate(entryId: string, reason?: string): Promise<void>;
  cleanupExpired(): Promise<number>;
  health(): Promise<{ healthy: boolean; latencyMs: number }>;
  close(): Promise<void>;
}
```

**Store params (Zod-validated internally):**
- `type`: one of 6 fixed types
- `topic`: string (will be normalized: lowercase, trimmed)
- `content`: string, max 2000 characters (reject with error if exceeded)
- `author`: string (agentId)
- `scope`: optional override (default derived from type)
- `tags`: optional string[]

**Store logic:**
1. Validate input with Zod
2. Normalize topic: `topic.trim().toLowerCase()`
3. Determine scope: use provided scope or default from SCOPE_DEFAULTS map:
   - discovery -> shared, constraint -> shared, architecture_decision -> shared, preference -> shared, test_result -> shared, thought -> private
4. Calculate expires_at: `new Date(Date.now() + EXPIRY_DURATIONS[type])` where durations are:
   - discovery: 24h, constraint: 30d, architecture_decision: 7d, thought: 24h, preference: 30d, test_result: 7d
5. **Deduplication check**: Query for existing entry with same normalized topic + same type that is active (not superseded, not invalidated, not expired). If found, auto-supersede: mark old entry with `superseded_by = newId`, create new entry.
6. Generate embedding: call `embeddingService.embed("{topic}: {content}")`. If null (failure), proceed with null embedding -- entry is still stored and queryable by structured fields.
7. Insert new entry with `createId.knowledgeEntry()` as ID.
8. Return `{ id, topic: normalizedTopic, type }` (same shape regardless of dedup).

**Query params:**
- `query`: semantic search text
- `agentId`: string (for scope filtering)
- `type`: optional type filter
- `topic`: optional exact match (normalized)
- `limit`: default 10, max 25

**Query logic:**
1. Build base conditions (always applied):
   - `expires_at > NOW()` (query-time expiry filter)
   - `invalidated = false`
   - `superseded_by IS NULL`
   - Scope visibility: `scope = 'shared' OR (scope = 'private' AND author = agentId)` -- this is the invisible row-level security
2. If `type` provided, add `type = ?` filter
3. If `topic` provided, add `LOWER(TRIM(topic)) = LOWER(TRIM(?))` filter
4. Embed query text: call `embeddingService.embed(query)`.
   - If embedding succeeds: use cosine similarity ordering with threshold (0.3). Use Drizzle's `cosineDistance()` function. Compute similarity as `1 - cosineDistance(embedding, queryEmbedding)`. Filter where similarity > 0.3. Order by similarity DESC.
   - If embedding fails AND structured filters exist (type/topic): fall back to structured-only query, ordered by created_at DESC.
   - If embedding fails AND no structured filters: return empty array (MEM-08).
5. Apply limit (capped at 25).
6. Return results mapped to: `{ id, type, topic, content, author, createdAt }` (ISO string for createdAt). Omit: embedding, expires_at, scope, tags.

**Supersede method:**
- Takes entryId + new content + optional type/topic overrides
- Verify original entry exists and is active (not already superseded/invalidated)
- Create new entry (inheriting type/topic from original unless overridden)
- Update original with `superseded_by = newId`
- Return same shape as store: `{ id, topic, type }`

**Invalidate method:**
- Takes entryId + optional reason
- Verify entry exists
- Update `invalidated = true, invalidation_reason = reason`

**cleanupExpired method:**
- DELETE FROM agents.knowledge_entries WHERE expires_at < NOW() - INTERVAL '24 hours'
- Return count of deleted rows

**health/close:** Follow TaskService pattern (health does a lightweight SELECT 1, close is no-op).
