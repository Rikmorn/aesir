  <action>
Create `packages/agents/scripts/validate-workflow.ts` following the existing script pattern from `seed-directory.ts`.

**Script structure:**

```
#!/usr/bin/env tsx
```

1. **Environment setup:** Import and call `loadEnvFromRoot()` from `@aesir/platform` (must be first, before accessing env vars). Import `nanoid` for ID generation.

2. **Constants:**
   - `AGENT_SERVICE_URL`: from `process.env.AGENT_SERVICE_URL` or default `"http://localhost:3004"`
   - `DASHBOARD_URL`: from `process.env.DASHBOARD_URL` or default `"http://localhost:3005/dashboard"`

3. **Health check function:** `waitForHealth(url: string, maxWaitMs = 30000)` — poll `GET /health` every 1 second until `res.ok` or timeout. Throw descriptive error on timeout.

4. **Main function:**
   a. Print banner: "Aesir v2.7 Triangular Workflow Validation"
   b. Call `waitForHealth(AGENT_SERVICE_URL)` — print "Waiting for agent-service..."
   c. Construct synthetic NormalizedEvent (must match NormalizedEventSchema exactly):
      ```typescript
      const correlationId = `validate_${nanoid()}`;
      const event = {
        id: `evt_${nanoid()}`,
        type: "slack.app_mention.created",
        source: "slack" as const,
        timestamp: new Date().toISOString(),
        correlationId,
        payload: {
          text: "Add a /health endpoint that returns { status: 'ok', version: '<package version>' }",
          channel: "C_SYNTHETIC",
          user: "U_VALIDATION",
          ts: `${Date.now() / 1000}`,
          teamId: "T_SYNTHETIC",
        },
      };
      ```
   d. POST to `${AGENT_SERVICE_URL}/events` with JSON body. Log the response.
   e. Extract conversationId from response if present. Print dashboard URL.
   f. **Optional polling:** If `--poll` flag is passed (check `process.argv`), poll the task tree API endpoint `GET /api/tasks/tree?rootTaskId=<id>` every 10 seconds and print a one-line status summary (task count, status distribution). Stop after 5 minutes or when root task reaches terminal state. This is a convenience — the primary observation path is the dashboard.
   g. Print the manual verification checklist:
      ```
      --- Manual Verification Checklist ---
      Open the dashboard to verify:
      1. [ ] Task tree shows full triangle (product->dev->QA, plus fix subtree if triggered)
      2. [ ] Handshakes visible — accept + estimate on each delegation
      3. [ ] Signals flow chronologically — delegation created, accepted, completed
      4. [ ] Health indicators green (no orphans, no unresolved timeouts)
      5. [ ] Knowledge entries exist: SELECT * FROM agents.knowledge_entries WHERE type = 'test_result'
      6. [ ] Conversation links show coherent message history
      ```
   h. Print prerequisite reminder:
      ```
      Prerequisites:
      - docker compose up postgresql github-integration agent-service
      - pnpm db:migrate
      - pnpm --filter @aesir/agents seed:directory
      - Embedding service running (for directory:find)
      ```

5. **Error handling:** Wrap main in `.catch()` that logs error and exits with code 1. Use `console.log`/`console.error` (not pino — this is a CLI script, not a service).

**Important details:**
- Use `fetch` (global in Node 18+) — no need for node:http or axios
- `nanoid` is already a dependency of @aesir/agents
- The script does NOT need to import from @aesir/types — it constructs the event object as a plain object that matches the schema
- The `slack.app_mention.created` event type triggers product-agent (per its definition.yaml triggers)
- Payload structure should match what the Slack adapter expects but does not need to be exhaustive — the adapter and router handle partial payloads gracefully
