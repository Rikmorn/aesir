## Decisions Made
- SpawnAgentDeps carries all spawn dependencies inside ToolContext rather than modifying ToolFactory signature -- keeps existing 28 tool registrations unchanged
- Used conditional spread (`...(deps.abortSignal && { abortSignal: deps.abortSignal })`) instead of passing undefined to satisfy TypeScript's exactOptionalPropertyTypes
- Sub-agent ToolContext inherits containerManager and taskId from parent (shared sandbox) but omits spawnDeps unless the sub-agent definition includes coordination:spawn_agent in its tools AND depth allows -- future-proof without enabling uncontrolled recursion
- Task descriptions truncated to 200 chars and output previews to 300 chars in event payloads -- reasonable bounds for event storage

None - plan executed exactly as written.

## Issues Encountered
- TypeScript `exactOptionalPropertyTypes` rejected `abortSignal: deps.abortSignal` when the value might be `undefined` -- resolved with conditional spread pattern
- Biome flagged unused `SpawnAgentDeps` type import (only `ToolContext` needed since `SpawnAgentDeps` is accessed via `ctx.spawnDeps`) -- removed the unused import
