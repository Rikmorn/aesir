  <action>
    Create five components for the agent detail page sections. All are server components (no "use client") EXCEPT agent-prompt-viewer which needs "use client" for the Collapsible toggle state.

    **1. `agent-config-panel.tsx` (server component):**

    Displays the agent's full configuration in a structured layout.

    Props: Accept the `AgentDetail` type (from `@/lib/agent-service`).

    Layout: Use a Card component with sections. Display as a definition list or grid:

    **Model section:**
    - Model: e.g., "claude-sonnet-4-20250514"
    - Temperature: e.g., "0.7" (show "default" if undefined)

    **Execution limits:**
    - Max Iterations: e.g., "50"
    - Token Budget: e.g., "200,000" (format with toLocaleString for readability)

    **History settings (sub-section):**
    - Prune Threshold: e.g., "80,000 tokens"
    - Protected Messages: e.g., "10"
    - Summary Threshold: e.g., "60,000 tokens"
    - Summary Model: e.g., "claude-haiku-3-20240307"

    Use `Separator` between sections. Use muted labels with values in a `dl`/`dt`/`dd` pattern or a two-column grid (`grid grid-cols-[auto,1fr]`). Keep it clean and scannable.

    **2. `agent-tools-list.tsx` (server component):**

    Displays tools grouped by namespace with links to the tool dashboard.

    Props: `{ tools: string[] }` where each tool is a `namespace:tool_name` string (e.g., `"linear:get_issue"`).

    Group tools by namespace prefix (split on `:`). Display each namespace as a section header with tools listed below.

    Namespace ordering: codebase, coordination, linear, github, slack (or alphabetical).

    Each tool renders as a clickable link to `/tools?tool=namespace:tool_name`. These links will 404 until Phase 53 ships the tool dashboard, but will work once it exists. This is intentional and documented in CONTEXT.md.

    Show the total tool count in a header (e.g., "12 tools").

    Use Badge for namespace labels (color-coded by namespace if desired). Use a compact list layout.

    **3. `agent-sub-agents.tsx` (server component):**

    Displays sub-agent references with links to their detail pages.

    Props: `{ subAgents?: Record<string, string> }` where keys are roles (e.g., "researcher") and values are agent IDs (e.g., "researcher").

    If `subAgents` is undefined or empty, render nothing (return null).

    For each sub-agent, display:
    - Role label (e.g., "researcher", "coder", "tester")
    - Agent ID as a link to `/agents/[agent-id]`
    - These links work immediately within this phase since both list and detail pages exist

    Layout: Simple list or small cards, one per sub-agent.

    **4. `agent-prompt-viewer.tsx` ("use client" component):**

    Renders the system prompt as Markdown inside a collapsible section.

    Props: `{ systemPrompt: string }`

    This component MUST be "use client" because it uses the Collapsible component which needs state for open/close toggling.

    Import `Markdown` from `react-markdown` (v10+). Note: Despite the component being "use client", react-markdown will be included in the client bundle. This is acceptable because the system prompt content is passed as a prop from the server component page (the content is already fetched server-side, only the rendering happens client-side for the toggle interaction).

    Layout:
    - Use shadcn Collapsible component
    - CollapsibleTrigger shows "System Prompt" header with expand/collapse icon (ChevronDown/ChevronUp from lucide-react) and the prompt size (e.g., "2,847 chars")
    - CollapsibleContent renders the Markdown content
    - Default state: collapsed (prompts are long, 2-10KB)
    - When expanded, wrap in a `max-h-[600px] overflow-auto` container with padding
    - Apply prose styling for Markdown: `prose prose-sm dark:prose-invert max-w-none`

    The system prompts contain mixed content: plain text, XML-like tags (`<identity>`, `<constraints>`), Markdown headers, lists, code blocks, bold text. react-markdown will strip XML tags (expected behavior per RESEARCH.md) and render the Markdown portions. This is acceptable -- the goal is readability, not perfect fidelity.

    **5. `agent-recent-conversations.tsx` (server component):**

    Displays the last 10 conversations for this agent.

    Props: `{ conversations: RecentConversation[]; agentDefinitionId: string }` where `RecentConversation` is imported from `@/services/agents`.

    Layout: Use the shadcn Table component (consistent with conversations list page).

    Columns:
    - Status: StatusBadge component (reuse from `@/components/conversations/status-badge`)
    - Duration: Formatted using `formatDuration(createdAt, updatedAt)` from `@/lib/format`
    - Tokens: Input + output formatted with `formatTokenCount` from `@/lib/format`
    - Last Activity: `formatRelativeTime(lastActivity)` from `@/lib/format`

    Each row links to `/conversations/[id]` (the conversation detail page from Phase 51).

    Footer: "View all" link to `/conversations?agent=${agentDefinitionId}` -- navigates to the conversations list pre-filtered by this agent. This uses the existing filter parameter from Phase 50.

    Empty state: If no conversations, show a muted message "No recent conversations".
