### Potential Risk Areas (for monitoring, not blocking)

## Tech Debt

### Phase 29: tool_result Trace Gap

**Severity:** Low
**Item:** TRAC-02 partial — `tool_result` trace type not recorded because `runAgentLoop()` has no `onToolResult` callback. 4 of 5 trace types are recorded (tool_call, llm_response, agent_spawn, agent_complete).
**Impact:** Tool results are part of LLM conversation history but not explicitly traced as separate database records.
**Mitigation:** LLM response traces contain reasoning about tool results.
**Future:** Extend Phase 28 with `onToolResult` callback.

### Phase 31: Prompt Effectiveness Unvalidated

**Severity:** Medium
**Items:**
- DEVO-11: Error recovery with genuinely different approaches — prompt instructs this but no real-world LLM validation
- DEVO-13: Escalation after 3 distinct failures — prompt instructs this but effectiveness unproven
- Adaptive complexity assessment — tests mock ideal LLM behavior, not actual reasoning

**Impact:** System works correctly IF Claude follows prompt instructions. Behavioral tests prove the code CAN handle all scenarios.
**Mitigation:** Phase 36 behavioral tests prove the orchestrator's code paths work. Prompt iteration will be needed based on production LLM behavior.
**Future:** Run with real Anthropic API calls against representative tasks and iterate prompts based on observed behavior.

### Phase 36: Infrastructure-Dependent Validation

**Severity:** Low
**Items:**
- E2EV-01 (full flow), E2EV-03 (feature implementation), E2EV-07 (context persistence) verified structurally via code path tracing, not with running Docker Compose + services
- 1 pre-existing test failure in orchestrator.test.ts (tool count assertion)

**Impact:** Code paths are correctly wired (verified through source inspection). Full running validation requires Docker Compose with real or mocked external services.
**Future:** Run full Docker Compose E2E test during first operational deployment.
